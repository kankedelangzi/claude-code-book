## C.0 Claude Code Security：自动安全审查（2026年5月）

> 🆕 **2026年5月27日发布** — Anthropic 推出 Claude Code 自动漏扫与修复插件，安全审查进入"零配置"时代

### 演进时间线

| 时间 | 里程碑 |
|------|--------|
| 2026年2月 | Claude Code Security 首次向企业版/团队版推出（研究预览） |
| 2026年5月27日 | 自动漏扫与修复插件全面发布，CLI ≥ 2.1.144 可用 |

### 核心能力

**两种使用方式：**

1. **终端斜杠命令**：在 Claude Code 中输入 `/security-review`，即时扫描当前代码变更
2. **GitHub Actions 集成**：每个 PR 自动触发安全审查，在代码行上添加内联评论

**三阶段实时防护：**

| 阶段 | 触发时机 | 工作方式 | API 消耗 |
|------|----------|----------|----------|
| 编辑时 | 写代码过程中 | 本地规则实时匹配高危模式 | ❌ 零费用 |
| 会话结束时 | 对话结束 | 模型比对 git 差异，拦截逻辑漏洞 | ✅ 消耗 |
| 提交时 | git commit/push | 深度智能体评审 | ✅ 消耗 |

**覆盖漏洞类型：** 注入攻击（SQL/命令/LDAP/XPath/NoSQL/XXE）、认证授权、数据泄露、加密问题、输入验证、业务逻辑缺陷、配置安全、供应链安全、代码执行、XSS

**基准测试：** 启用安全审查后，PR 的安全修复意见减少 30%~40%

### 快速配置

```yaml
# .github/workflows/security.yml
name: Security Review

permissions:
  pull-requests: write
  contents: read

on:
  pull_request:

jobs:
  security:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          ref: ${{ github.event.pull_request.head.sha || github.sha }}
          fetch-depth: 2

      - uses: anthropics/claude-code-security-review@main
        with:
          comment-pr: true
          claude-api-key: ${{ secrets.CLAUDE_API_KEY }}
```

### 运行要求

| 要求 | 说明 |
|------|------|
| Claude Code CLI | ≥ 2.1.144 |
| Python | ≥ 3.8 |
| 首次激活 | 自动部署虚拟环境并安装 Agent SDK |
| API Key | 需同时启用 Claude API 和 Claude Code 使用权限 |

## C.1 Agent View：多任务管理新纪元（2026年5月）

> 🆕 **2026年5月12日发布** — Claude Code 正式进入"多线程并发"时代

### 核心痛点
以前想让多个 AI 代理同时工作，得开一堆终端标签页或 tmux 窗口。光记住"哪个窗口在干什么"就够费劲的，更别提某个任务跑测试时装依赖，你只能干等。

### Agent View 是什么？
一种内置的任务面板，让你在同一个终端窗口里：
- ✅ **调度多个并行的 AI 编程代理**
- ✅ **后台挂起任务，不占用前台**
- ✅ **统一管理所有任务状态**

### 进入方式
```bash
# 方式一：快捷键
按左方向键 ←  # 弹出 Agent View 总览界面

# 方式二：命令
claude agents
```

### 后台任务管理
```bash
# 把当前会话推到后台
/bg

# 直接派一个后台任务，不进入交互
claude --bg "帮我把整个API层的异常处理重构一遍"

# 查看所有后台任务
claude agents
```

### Agent View 界面展示
```
┌─────────────────────────────────────────────────────┐
│ Agent View - 全局任务列表                             │
├─────────────────────────────────────────────────────┤
│ ○ 重构API层异常处理     [运行中]   闲置 2 分钟        │
│ ● 补充单元测试         [等待回复] 等待你的指令...     │
│ ✓ 更新依赖版本         [已完成]   耗时 8 分钟        │
│ ○ 代码审查PR #42       [运行中]   闲置 30 秒        │
└─────────────────────────────────────────────────────┘
```

### 无感知交互
在总览界面，你可以：
- 选中某个会话，预览最新进展（不需要切入完整窗口）
- 如果某个代理卡在等指令，**直接在总览页原地回复**
- 不用切入完整会话，就能解除阻塞

### 三层并行机制对比

| 机制 | 拓扑结构 | 适用场景 | Token 成本 |
|------|---------|---------|----------|
| **Subagents** | 星型：主对话居中，子代理汇报 | 专注型任务，只需结果 | 较低 |
| **Agent Teams** | 网状：队友之间直接通信 | 复杂任务，需要讨论协作 | 较高（3-4倍） |
| **Agent View** | 统一面板管理所有会话 | 多任务并发监控 | 中等 |

###

### 为什么需要 Auto 模式？

Anthropic 统计：用户已批准 **93% 的权限提示**。大量审批操作是冗余的，但 `--dangerously-skip-permissions` 又太激进。

Auto 模式在两者之间找到了平衡点。

### 双层安全机制

| 层级 | 检测内容 | 处理方式 |
|------|---------|---------|
| 输入层 | Prompt 注入探测 | 拦截恶意输入 |
| 输出层 | Transcript 分类器 | 评估操作风险 |

- **安全操作**：自动执行，无需人工确认
- **高风险操作**：阻止执行，Claude 尝试寻找更安全的替代方案

### 使用方法

```bash
# 启用 Auto 模式
claude --auto

# 结合 Computer Use
claude --auto --computer-use

# 查看安全策略配置
claude config auto-mode --show
```

### 适用场景

- 日常开发：写代码、跑测试、修 Bug
- 代码审查：自动检查 PR 变更
- 项目重构：批量修改文件

### 不适用场景

- 涉及生产环境部署
- 删除大量文件或数据库操作
- 敏感数据操作

> 💡 **实用建议**：先用 Auto 模式跑小任务，观察 Claude 的行为边界，再逐步扩大使用范围。

## C.3 Computer Use：突破终端边界

### 核心能力

Claude 可以像人类一样操作桌面界面：打开文件、运行开发工具、在浏览器中点击和导航。

### 技术原理

Claude 通过截屏识别屏幕内容，然后发出鼠标/键盘指令来操作界面。当工作流离开终端进入浏览器、桌面应用或系统 UI 时，Claude 不再需要人类接管。

### 启用方式

```bash
# 在会话中启用
/computer-use

# 或启动时启用
claude --computer-use
```

### 实战案例：Web 应用端到端测试

```
> 我刚写了一个登录页面，帮我测试一下完整流程：
> 1. 打开浏览器访问 http://localhost:3000
> 2. 输入测试账号 test@example.com
> 3. 输入密码 Test123456
> 4. 点击登录按钮
> 5. 验证是否跳转到首页
> 6. 截图保存测试结果
```

Claude 会自动操作浏览器完成整个测试流程，无需你手动点击。

### 安全边界

- 访问应用前会请求用户许可
- 截屏识别存在延迟和误差
- **不建议**在敏感金融、健康或个人记录场景使用

## C.4 语音模式：嘴巴写代码

### 启用方式

在会话中输入 `/voice`，然后按住空格说话，实时转录为指令。

### 适用场景

- 边走边改代码（配合 Remote Control）
- 快速口述需求，比打字快 3-5 倍
- 手不方便操作键盘时

### 使用技巧

```
# 语音 + 打字混合输入
/voice                           # 开启语音模式
（按住空格）"帮我把登录接口加上限流"  # 语音输入
（打字补充）"限流策略用令牌桶算法"    # 打字补充
```

## C.5 Remote Control：手机接管终端

### 使用场景

在电脑上启动 Claude Code 会话，通过手机/平板远程发送 Prompt，随时随地编码、调试、审查。

### 操作步骤

```bash
# 本机启动远程控制会话
claude
> /remote-control

# 生成二维码，手机 Claude App 扫码接管
# 手机端可以查看会话、发送指令
```

### 限制

- 每台机器同一时间只能运行一个远程控制会话
- 需要网络连接

### 实战：通勤时修 Bug

```
# 早上到公司：启动远程控制
claude
> /remote-control

# 通勤路上：手机打开 Claude App
# > 查看早上的 CI 报错，修复那个类型错误
# > 修复后跑一下测试

# 到公司：电脑上直接看到修复结果
```

## C.6 /schedule：云端定时任务

### 核心能力

让 Claude 在 Anthropic 云端定时执行任务，即使你的电脑关了也在运行。

### 典型场景

| 场景 | 调度频率 | 说明 |
|------|---------|------|
| 每日 PR Review | 每天早上 9:00 | 自动审查前一天的 Pull Request |
| CI 失败检查 | 每 2 小时 | 夜间自动检查并修复 CI 问题 |
| 文档同步 | 每次合并后 | 合并后自动更新相关文档 |
| 依赖审计 | 每周一次 | 扫描过时依赖和安全漏洞 |

### 创建方式

```bash
# CLI 创建定时任务
claude /schedule "Review all open PRs and flag potential issues" \
  --repo github.com/myorg/myapp \
  --cron "0 9 * * 1-5" \
  --env NODE_ENV=production
```

### 工作流程

1. 给 Claude 一个 Prompt
2. 关联一个或多个代码仓库
3. 选择调度频率
4. 配置环境变量和连接器
5. 每次运行从全新仓库克隆开始，创建独立会话
6. 运行结束后审查变更，直接创建 Pull Request

## C.7 Cloud Auto-Fix：PR 自动修复

### 核心能力

Web 和移动端会话可以自动跟踪 Pull Request，在云端修复 CI 失败并处理评审意见。

### 工作流程

```
提交 PR → CI 失败 → Cloud Auto-Fix 自动修复 → 处理 Review 意见
→ 开发者回来时面对一个可合并的 PR
```

### 意义

将 Claude Code 的工作范围从"生成代码"延伸到"维护代码"——真正的端到端智能体工作流。

## C.8 多智能体并行工作

### 使用方式

- `Shift+Up/Down` 切换子 Agent
- 或通过 tmux 直接接管任意子 Agent

### 适用场景

- 代码审查（可分拆为独立、读密集型子任务）
- 大型代码库维护
- 多模块并行开发

### 实战：并行审查多个 PR

```
> 同时审查 PR #42、#43、#45，每个 PR 单独开一个 Agent
> 审查要点：代码质量、安全隐患、性能问题
> 完成后汇总报告

# Claude 会启动 3 个并行 Agent，各自独立审查
# 用 Shift+Up/Down 切换查看各 Agent 进度
```

## C.9 输出上限提升

Opus 4.6 的输出上限：

| 参数 | 值 |
|------|---|
| 默认输出上限 | 64k tokens |
| 最大输出上限 | 128k tokens |

这对长时间运行的 Agent 任务至关重要——Claude 可以一次性输出更多代码，减少上下文切换。
