# 6.5 团队协作与代码规范

> 让Claude Code帮助团队保持代码一致性，提高协作效率。

## 🎯 场景描述

团队协作中经常遇到：
- 代码风格不统一
- 命名规范不一致
- 项目结构混乱
- 文档不完整

**Claude Code可以帮团队建立和维护代码规范，自动检查和修复风格问题。**

## ✨ 经典团队协作场景

### 场景1：建立代码规范

**规范制定指令：**

```
为我们的 [JavaScript/TypeScript/Python/Java] 项目制定代码规范：
- 命名规范（变量、函数、类、文件）
- 代码格式（缩进、空格、换行）
- 注释规范
- 项目结构规范
- Git提交规范

生成 .eslintrc、.prettierrc 等配置文件和文档。
```

**Claude Code会做什么：**
- 生成完整的代码规范文档
- 创建配置文件（ESLint、Prettier、EditorConfig等）
- 提供代码示例
- 制定代码审查清单

### 场景2：批量修复风格问题

**修复指令：**

```
按照我们的代码规范，修复整个项目的风格问题：
- 缩进统一为2个空格
- 分号统一使用
- 引号统一使用单引号
- 函数名使用驼峰命名
- 常量使用大写+下划线

只改风格，不改逻辑。
```

**Claude Code会做什么：**
- 批量修复代码风格
- 保持代码逻辑不变
- 生成修改报告
- 提供回滚方案

### 场景3：生成团队文档

**文档生成指令：**

```
为我们的项目生成团队协作文档：
- 代码规范指南
- 项目结构说明
- 开发流程说明
- 代码审查指南
- 测试规范

用Markdown格式，包含示例代码。
```

**Claude Code会做什么：**
- 生成完整的团队文档
- 提供代码示例
- 制定最佳实践
- 创建检查清单

## 🔥 实战Prompt模板

### 模板1：制定代码规范

```
为 [技术栈] 项目制定代码规范：

项目特点：
- 团队规模：[人数]
- 项目类型：[Web应用/API/CLI工具等]
- 主要技术：[列出主要技术栈]

规范内容：
1. 命名规范（变量、函数、类、文件）
2. 代码格式（缩进、空格、换行、分号等）
3. 注释规范（函数注释、行内注释）
4. 项目结构规范
5. Git提交规范
6. 测试规范

输出：
- 规范文档（Markdown）
- 配置文件（.eslintrc, .prettierrc等）
- 代码示例
```

### 模板2：批量风格修复

```
修复以下文件的代码风格问题：

文件列表：
- [文件路径1]
- [文件路径2]
- ...

修复规则：
- [规则1，如"缩进统一为2空格"]
- [规则2，如"使用单引号"]
- [规则3，如"行尾加分号"]

要求：
- 只改风格，不改逻辑
- 保持代码功能不变
- 生成修改报告
```

### 模板3：生成团队文档

```
为项目生成团队协作文档：

项目信息：
- 项目名称：[名称]
- 技术栈：[列出技术]
- 团队规模：[人数]

需要生成的文档：
1. 代码规范指南
2. 项目结构说明
3. 开发流程（分支策略、代码审查等）
4. 测试规范
5. 部署流程

格式：Markdown，包含目录和示例代码
```

## 🚀 团队协作工作流

```
1. 规范制定
   ├── 制定代码规范
   ├── 创建配置文件
   └── 生成团队文档

2. 工具集成
   ├── 集成ESLint/Prettier
   ├── 配置Git钩子（husky）
   └── 设置CI检查

3. 培训与执行
   ├── 团队培训
   ├── 代码审查检查规范
   └── 定期规范更新

4. 持续改进
   ├── 收集反馈
   ├── 更新规范
   └── 工具配置优化
```

## ⚠️ 团队协作最佳实践

| 实践 | 说明 |
|------|------|
| **规范先行** | 项目开始时就制定规范 |
| **工具自动化** | 用工具自动检查和修复 |
| **代码审查** | 人工审查规范遵守情况 |
| **定期更新** | 根据项目发展更新规范 |
| **团队共识** | 规范要经过团队讨论和同意 |

## 📝 小结

Claude Code在团队协作中的优势：

- **快速制定规范** — 几分钟生成完整规范
- **批量修复问题** — 自动修复风格不一致
- **生成文档** — 自动生成团队文档
- **保持一致性** — 确保团队代码风格统一

**好的代码规范是团队效率的基础，Claude Code让制定和执行规范变得简单。**
