# 6.6 实用技巧速查

> 把全书最实用的技巧集中在这里，方便随时查阅。遇到问题时先翻这一节，80% 的场景都能找到答案。

---

## 指令编写技巧

### 1. 用"角色 + 任务 + 约束"三件套

```bash
# ❌ 模糊指令
"帮我写个登录功能"

# ✅ 三件套指令
"你是一个有 5 年经验的 Node.js 后端工程师。
帮我写一个手机号+验证码登录的 API 接口。
要求：Express 框架，JWT 认证，输入参数校验，错误处理完整。"
```

**为什么有效**：角色让 Claude Code 进入专业模式，任务明确输出范围，约束保证代码质量。

---

### 2. 用文件路径代替"这个文件"

```bash
# ❌ 模糊指代
"把这个文件改成 async/await"

# ✅ 明确路径
"把 src/services/user-service.js 里的回调函数全部改成 async/await"
```

**为什么有效**：Claude Code 能直接定位，不用猜你想改哪个文件。

---

### 3. 分步执行复杂任务

```bash
# ❌ 一次性扔给 Claude Code
"帮我重构整个项目，加测试，写文档，部署到服务器"

# ✅ 分四步
"第一步：分析 src/ 目录的代码结构，找出需要重构的模块"
# （审核后）
"第二步：重构 user-service.js，改成 async/await"
# （审核后）
"第三步：为重构后的代码添加单元测试"
# （审核后）
"第四步：更新 README，补充新的 API 说明"
```

**为什么有效**：每步都能审核，避免一次性改太多导致翻车。

---

### 4. 用"参考示例"提高准确率

```bash
# ❌ 纯文字描述
"写一个和现有代码风格一致的组件"

# ✅ 给参考示例
"参考 src/components/UserCard.js 的代码风格，
在 src/components/ 下创建一个新的 OrderCard 组件，
功能：显示订单号、金额、状态，支持点击跳转详情页"
```

**为什么有效**：Claude Code 会模仿参考代码的缩进、命名、注释风格。

---

### 5. 明确"不要做什么"

```bash
# ❌ 只说要什么
"写一个 API 接口"

# ✅ 说清楚边界
"写一个获取用户列表的 API 接口。
要求：
- 使用 Express 框架
- 支持分页（page, pageSize）
- 返回 JSON 格式
不要：
- 不要加权限验证（后面再做）
- 不要连数据库（先用 mock 数据）
- 不要写测试（优先跑通功能）"
```

**为什么有效**：明确边界能避免 Claude Code "过度发挥"。

## 代码审查技巧

### 6. 让 Claude Code 先"说"再"做"

```bash
# 需要先理解代码时
"别急着改，先说说 src/utils/auth.js 现在的逻辑是什么，
有哪些潜在问题，然后再给我重构方案"
```

**场景**：遗留代码、别人写的代码、长时间没碰的代码。

---

### 7. 用"对比模式"审查代码

```bash
# 让 Claude Code 给出多个方案
"用两种方式实现缓存层：
方案 A：使用 Redis
方案 B：使用 Node.js 内存缓存
对比两者的优缺点，给出推荐"
```

**场景**：技术方案选型、性能优化对比。

---

### 8. 指定审查重点

```bash
# ❌ 泛泛审查
"审查一下这段代码"

# ✅ 指定重点
"审查 src/services/order-service.js，重点看：
1. 错误处理是否完整
2. 有没有 SQL 注入风险
3. 异步操作有没有 await 遗漏"
```

## 调试技巧

### 9. 让 Claude Code 帮你"读"错误栈

```bash
# 直接粘贴错误栈
"这个错误怎么回事？
TypeError: Cannot read property 'map' of undefined
    at UserList (/app/src/components/UserList.jsx:15:22)
    at renderWithHooks (/app/node_modules/react-dom/cjs/react-dom.development.js:16305:18)
    
相关代码：
（粘贴 UserList.jsx 内容）"
```

**技巧**：错误栈 + 相关代码一起贴，Claude Code 能精准定位问题。

---

### 10. 用"最小化复现"调试复杂问题

```bash
# 复杂问题先简化
"这个 Bug 只在生产环境出现，本地复现不了。
帮我写一个最小复现代码，隔离变量，逐步排查：
1. 先排除数据源问题
2. 再排除缓存问题
3. 最后看是不是并发问题"
```

---

### 11. 让 Claude Code 帮你写调试日志

```bash
"在 src/services/payment.js 的关键位置加 console.log，
打印：入参、返回值、错误对象、执行时间。
用完后告诉我哪些可以删掉。"
```

## Git 协作技巧

### 12. 用 Claude Code 生成规范的 commit message

```bash
# 先让 Claude Code 分析改动
"分析一下我刚做的改动（git diff），
生成一条符合 Conventional Commits 的 commit message"
```

**输出示例**：
```
feat(user): 添加手机号登录功能

- 新增 SMS 验证码发送接口
- 新增手机号+验证码登录接口
- 更新用户模型，添加手机号字段

Closes #123
```

---

### 13. 让 Claude Code 帮你写 PR 描述

```bash
"基于当前的 commit 记录，帮我写一份 PR 描述，
包括：改动摘要、测试计划、影响范围、截图（如果有 UI 改动）"
```

---

### 14. 用 Claude Code 解决合并冲突

```bash
# 遇到冲突时
"解决当前 Git 合并冲突。
对于 each conflict：
1. 先解释两边的改动意图
2. 给出合并方案
3. 等我确认后再修改"
```

**注意**：合并冲突涉及业务逻辑时，一定要人工确认后再让 Claude Code 修改。

## 性能优化技巧

### 15. 让 Claude Code 帮你"找"性能瓶颈

```bash
"分析 src/services/report-service.js，
找出可能的性能瓶颈：
1. 有没有 N+1 查询
2. 有没有不必要的全表扫描
3. 有没有可以加缓存的地方"
```

---

### 16. 用"前后对比"验证优化效果

```bash
"优化 src/utils/data-processor.js 的性能。
优化前后，用 console.time 测试关键函数的执行时间，
确保优化有效（附测试结果）"
```

## 上下文管理技巧

### 17. 大项目用 CLAUDE.md 当"项目说明书"

```bash
# 在项目根目录创建 CLAUDE.md
"帮我写一个 CLAUDE.md，内容包括：
1. 项目技术栈（React + Express + PostgreSQL）
2. 目录结构说明
3. 编码规范（使用 ESLint + Prettier）
4. 常用指令示例"
```

**效果**：每次打开 Claude Code，它都先读 CLAUDE.md，不用重复解释项目背景。

---

### 18. 用"任务清单"管理复杂需求

```bash
# 开始大任务前先列清单
"帮我实现一个完整的用户管理模块，先列个任务清单"
→ Claude Code 输出：
  - [ ] 1. 设计数据库表结构
  - [ ] 2. 写 Model 层代码
  - [ ] 3. 写 API 接口
  - [ ] 4. 写单元测试
  - [ ] 5. 写 API 文档

# 然后逐个完成，每完成一个打勾
"完成第 1 步：设计数据库表结构"
```

---

### 19. 用"文件引用"精简上下文

```bash
# ❌ 把大文件内容直接粘贴进去
"这是我的配置文件（粘贴 500 行）..."

# ✅ 让 Claude Code 自己读
"参考 package.json 和 webpack.config.js 的配置，
帮我升级到 Webpack 5"
```

**为什么有效**：Claude Code 能直接读取文件，不用你手动复制粘贴占篇幅。

## 省钱技巧（API 调用优化）

### 20. 用"继续"代替重新提问

```bash
# ❌ 超时后重新开始（重复消耗 token）
"帮我重构这个文件（重新粘贴代码）"

# ✅ 用"继续"接着上次的输出
"继续输出，从刚才中断的地方开始"
```

---

### 21. 大文件分块处理

```bash
# ❌ 一次扔给 Claude Code 一个 2000 行的文件
"帮我重构这个文件（paste 2000 行）"

# ✅ 分块处理
"先分析 src/legacy/user-system.js 的结构（2000 行，先别改）
我准备分 3 次重构：
1. 用户注册相关函数（第 1-500 行）
2. 用户登录相关函数（第 501-1000 行）
3. 用户信息管理（第 1001-2000 行）"
```

---

### 22. 用"增量修改"代替"全部重写"

```bash
# ❌ 让 Claude Code 重写整个文件
"重写 user-service.js，用 TypeScript"

# ✅ 增量修改
"逐步把 user-service.js 改成 TypeScript：
第一步：先加类型注解，不改逻辑
第二步：改回调函数成 async/await
第三步：优化错误处理"
```

**为什么有效**：每次改动小，容易审核，也省 token。

## 实战组合技

### 组合技 1：5 分钟搭一个新功能

```bash
# 一条指令搞定
"在现有 Express 项目里加一个『留言板』功能：
1. 数据库表设计（messages: id, name, content, created_at）
2. API 接口（GET /api/messages, POST /api/messages）
3. 前端页面（HTML + Vanilla JS，不用框架）
4. 基础样式（用 CSS Grid 布局）

代码放 src/features/guestbook/ 目录下"
```

---

### 组合技 2：10 分钟生成项目文档

```bash
# 基于代码生成文档

1. README.md（项目介绍、安装、运行）

3. ARCHITECTURE.md（目录结构、技术栈、设计决策）

文档风格：简洁实用，避免废话"
```

## 速查表

### 指令模板速查

| 场景 | 指令模板 |
|------|----------|
| 写新功能 | "你是一个 [角色]。帮我实现 [功能]。要求：[约束1]、[约束2]。不要：[边界1]、[边界2]。" |
| 改现有代码 | "把 [文件路径] 的 [具体函数/模块] 改成 [目标]。参考：[参考文件]。" |
| 调试 Bug | "这个错误 [错误栈]。相关代码：[粘贴代码]。帮我定位问题并修复。" |
| 性能优化 | "分析 [文件路径] 的性能瓶颈，重点看 [切入点]。优化后附测试结果。" |
| 生成文档 | "基于 [代码目录] 生成 [文档类型]，风格：[参考示例]。" |

---

### 常见错误速查

| 错误现象 | 可能原因 | 解决方案 |
|----------|----------|----------|
| Claude Code 输出不完整 | 超时或 token 超限 | 用"继续"指令，或分块处理 |
| 改错文件 | 指令路径不明确 | 用绝对路径，避免"这个文件" |
| 代码风格不一致 | 没给参考示例 | 指定参考文件，让 Claude Code 模仿 |
| 过度发挥 | 指令边界不清晰 | 用"不要"明确列出不该做的事 |
| 上下文丢失 | 大项目信息太多 | 创建 CLAUDE.md，或用任务清单分步骤 |

---

### 文件组织速查

```
你的项目/
├── CLAUDE.md          # 项目说明书（给 Claude Code 读的）
├── .claude/            # Claude Code 配置目录
│   └── commands/      # 自定义指令（快捷指令）
├── src/
│   ├── features/      # 按功能模块组织（推荐）
│   ├── shared/        # 共享代码
│   └── __tests__/     # 测试文件
└── docs/              # 项目文档
```

## 小结

这一节是把全书的技巧做了"压缩包"：

1. **指令编写**：角色+任务+约束、明确路径、分步执行、给示例、说边界
2. **代码审查**：先说再做、对比模式、指定重点
3. **调试**：贴错误栈、最小化复现、加调试日志
4. **Git 协作**：规范 commit、写 PR 描述、解决冲突
5. **性能优化**：找瓶颈、前后对比验证
6. **上下文管理**：CLAUDE.md、任务清单、文件引用
7. **省钱技巧**：用"继续"、分块处理、增量修改
8. **组合技**：5 分钟搭功能、10 分钟生成文档、15 分钟代码审查

**下一步**：把这些技巧用熟，你就能把 Claude Code 用得比别人快 3 倍。
