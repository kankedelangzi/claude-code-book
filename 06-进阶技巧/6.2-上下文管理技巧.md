# 6.2 上下文管理技巧

> 让 Claude Code 记住重要信息，写出更准确的代码。

## 🎯 场景描述

Claude Code 有上下文窗口限制（约 200K tokens），对话太长会"忘记"之前的内容。更关键的是——每次新对话，它从零开始，完全不知道你的项目情况。你需要一套系统的方法来管理上下文：

- 让它知道项目的技术栈和规范
- 在长对话中避免信息丢失
- 在多会话间保持一致性
- 高效利用有限的上下文空间

## 💡 核心思路

```
持久化上下文（CLAUDE.md）+ 对话内压缩（/compact）+ 精准引用（@文件）
```

---

## 📝 方法一：CLAUDE.md — 项目的"身份证"

在项目根目录创建 `CLAUDE.md`，Claude Code 启动时会自动读取。

### 最小可用版本

```markdown
# CLAUDE.md

## 技术栈
- Node.js + Express + TypeScript
- PostgreSQL + Prisma
- React + Tailwind CSS

## 常用命令
- dev: npm run dev
- test: npm test
- migrate: npx prisma migrate dev
```

三行就够，别小看它。有了这三行，Claude Code 就不会给你写 Python 代码了。

### 完整版模板

```markdown
# CLAUDE.md

## 技术栈
- 后端：Node.js + Express + TypeScript
- 数据库：PostgreSQL + Prisma
- 前端：React + Tailwind CSS
- 测试：Jest + Testing Library

## 代码规范
- 使用 async/await，不用 .then()
- 错误处理用 try-catch
- API 响应格式：{ success: boolean, data?: any, error?: string }
- 变量用 camelCase，类型/接口用 PascalCase
- 注释用中文

## 项目结构
- src/routes/ - API 路由
- src/services/ - 业务逻辑
- src/middleware/ - 中间件
- src/types/ - 类型定义
- src/utils/ - 工具函数

## 常用命令
- 开发：npm run dev
- 测试：npm test
- 数据库迁移：npx prisma migrate dev
- 代码检查：npm run lint

## 重要约定
- 所有 API 路由必须有对应的测试
- 数据库操作统一走 service 层
- 环境变量在 .env.local，不要硬编码
```

### 实战技巧：让 Claude Code 帮你生成 CLAUDE.md

新项目？别自己写，让 Claude Code 来：

```
我刚创建了一个 Next.js 项目，请帮我：
1. 分析项目结构
2. 生成一个 CLAUDE.md 文件，包含技术栈、代码规范、常用命令
```

Claude Code 会扫描 `package.json`、配置文件、目录结构，自动生成精准的 CLAUDE.md。

### ⚠️ CLAUDE.md 的常见错误

```markdown
# ❌ 太长——写着写着就几百行
# ❌ 放了敏感信息——API Key、数据库密码
# ❌ 过时——代码改了但 CLAUDE.md 没更新
# ❌ 太模糊——写"使用现代框架"而不是"React 18 + TypeScript"
```

**经验法则：CLAUDE.md 控制在 50 行以内，只写"看了就能少问三个问题"的内容。**

## 📝 方法二：/compact — 长对话的救星

当你和 Claude Code 聊了很久，对话越来越长，它开始"犯糊涂"——忘了前面的约定，重复问问题。这时候用 `/compact`：

```
/compact
```

Claude Code 会自动总结当前对话的关键信息，压缩上下文，释放空间。就像你让一个同事"把刚才的讨论做个小结"。

### 什么时候用 /compact

| 场景 | 是否需要 compact |
|------|-----------------|
| 对话超过 20 轮 | ✅ 建议用 |
| 感觉 Claude Code 开始"忘事" | ✅ 立即用 |
| 切换到新话题 | ✅ 建议用 |
| 刚开始对话 | ❌ 没必要 |
| 单次小改动 | ❌ 没必要 |

### /compact 的高级用法

你可以在 `/compact` 后面加提示，告诉它保留什么：

```
/compact 保留关于数据库 schema 的讨论和 API 设计决策
```

这样压缩时会优先保留你指定的内容，丢掉无关闲聊。

### 实战案例

```
你：帮我重构用户模块
Claude Code：[修改了 5 个文件，对话已经很长]
你：现在帮我处理订单模块
Claude Code：[开始忘记用户模块的约定]

→ 这时应该：
你：/compact 保留代码规范和项目架构约定
Claude Code：[压缩完成，关键信息保留]
你：现在帮我处理订单模块
Claude Code：[清晰记得规范，继续工作]
```

## 📝 方法三：精准引用文件

不要让 Claude Code 读完整个项目再开始工作，直接告诉它看哪个文件。

### 用 @ 引用文件

```
请看 @src/services/userService.ts，帮我给 createUser 函数添加参数校验
```

Claude Code 只会读取你指定的文件，不会浪费上下文空间扫描整个项目。

### 引用多个文件

```
请看 @src/types/user.ts 和 @src/services/userService.ts，
确保 createUser 的参数类型和接口定义一致
```

### 引用目录

```
请看 @src/routes/ 目录下所有文件，帮我添加统一的错误处理中间件
```

### ❌ 常见错误：无差别加载

```
# ❌ 浪费上下文
请读取项目所有文件，然后帮我改一下登录接口

# ✅ 精准引用
请看 @src/routes/auth.ts，帮我给登录接口添加速率限制
```

## 📝 方法四：对话中提供上下文

即使有 CLAUDE.md，有时候还需要在对话中补充细节。

### 错误示范

```
帮我写一个登录接口
```

Claude Code 会问：用什么框架？什么数据库？返回什么格式？一来一回浪费好几轮。

### 正确示范

```
项目背景：
- Express + TypeScript
- 用户数据在 PostgreSQL，用 Prisma ORM
- 密码用 bcrypt 加密
- 返回 JWT token

帮我写一个登录接口：
POST /auth/login
Body: { email, password }
返回: { success: true, token: "xxx" }
```

**一次性给足上下文，比来回问答高效 5 倍。**

### 上下文模板

对于复杂需求，用这个模板：

```
【项目背景】一句话描述项目
【技术栈】框架 + 语言 + 数据库
【需求】要做什么
【约束】不能做什么 / 必须遵循什么
【参考文件】@相关文件路径
```

## 📝 方法五：多会话分工

一个大项目不要在一个对话里干完。把不同任务拆到不同会话：

### 分会话策略

```
会话 1：数据库 schema 设计 → 输出 schema.prisma
会话 2：API 路由实现 → 基于 schema 写 routes
会话 3：前端页面 → 基于 API 接口写组件
会话 4：测试用例 → 给所有接口写测试
```

### 跨会话衔接

每个会话结束时，让 Claude Code 总结关键决策：

```
请总结本次会话的关键决策和产出，包括：
1. 做了什么改动
2. 重要的设计选择
3. 下一步需要做什么
```

把总结写入项目的 `NOTES.md`，下一个会话就能接上。

### 实战案例：用 CLAUDE.md 做跨会话传递

```
# 第一个会话
你：帮我设计数据库 schema
Claude Code：[设计完成]
你：请把数据库设计要点更新到 CLAUDE.md

# 第二个会话（新对话，Claude Code 自动读 CLAUDE.md）
你：帮我基于现有 schema 写 API 路由
Claude Code：[已经知道 schema 设计，直接开干]
```

## 📝 方法六：大文件的处理策略

文件太大，一次性读取会占满上下文？有几个办法：

### 策略一：只读关键部分

```
请读取 @src/handlers/userHandler.ts 的 handleCreateUser 函数，
帮我添加参数校验
```

Claude Code 会精确定位函数，而不是读整个文件。

### 策略二：先概览再深入

```
请先列出 @src/services/orderService.ts 的所有函数名和签名，
然后我会告诉你要改哪个
```

### 策略三：让 Claude Code 自己决定读多少

```
帮我修改 @src/utils/validator.ts 中的 email 校验逻辑。
如果文件不大就读全部，如果太大就只读相关部分。
```

## 📝 方法七：自定义指令 — 你的"人格设定"

在 Claude Code 设置中配置自定义指令，每次对话自动生效。

### 设置路径

```
Settings → Custom Instructions（或 ~/.claude/settings.json）
```

### 实用配置示例

```json
{
  "customInstructions": "你是一个专业的 TypeScript 后端开发者。\n\n写代码时：\n1. 优先使用 ES Modules（import/export）\n2. 错误处理要完善\n3. 变量命名要语义化\n4. 添加必要的中文注释\n\n不要：\n1. 不要用 var\n2. 不要省略错误处理\n3. 不要用 any 类型\n4. 不要用 console.log，用 logger"
}
```

### .cursorrules 文件（Cursor IDE 用户）

```
# .cursorrules
- 所有代码用 TypeScript
- 使用函数式组件 + Hooks
- CSS 用 Tailwind，不用 styled-components
- 每个组件要有对应的测试文件
- 注释用中文
```

## 🔥 终极技巧：上下文管理检查清单

每次开始重要任务前，过一遍这个清单：

```
☐ CLAUDE.md 是否存在且最新？
☐ 是否只引用了必要的文件？
☐ 需求描述是否包含足够的背景？
☐ 长对话是否需要 /compact？
☐ 是否应该拆成多个会话？
☐ 自定义指令是否适合当前任务？
```

## 🎓 学到了什么

1. **CLAUDE.md 是零成本的最大收益——每次新对话自动生效**
2. **/compact 是长对话的续命神技——感觉"忘事"就压缩**
3. **@引用比"读取所有文件"高效 10 倍——精准定位，节省空间**
4. **一次性给足上下文，比来回问答快 5 倍**
5. **大项目拆会话，CLAUDE.md 做桥梁**
6. **大文件先概览再深入，别一次塞满**

## ⚠️ 注意

- CLAUDE.md 不要写敏感信息（API Key、密码等）
- CLAUDE.md 定期更新，保持和项目同步
- /compact 后检查一下，确认关键信息没丢
- 自定义指令和 CLAUDE.md 不要重复，选一个主力
- 上下文不是越多越好——信息过载和上下文不足一样糟糕
