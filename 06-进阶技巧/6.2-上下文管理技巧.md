# 6.2 上下文管理技巧

## 场景描述

跟 Claude Code 聊太久，它会"忘记"之前的内容。用上下文管理技巧可以让 Claude Code **记住关键信息**、**管理长对话**、**避免遗忘**。

本章案例：用上下文管理技巧，让 Claude Code 记住**待办 API 的所有功能**。

---

## 核心目标

- **记住关键信息**：让 Claude Code 记住关键决策、设计选择
- **管理长对话**：把大任务拆成小任务，避免对话过长
- **避免遗忘**：用 `SATE_DB` 机制，让 Claude Code 记住之前的内容
- **上下文压缩**：用 `SATE_SUMMARY` 压缩上下文

---

## 完整工作流

### 第一步：让 Claude Code 记住关键信息（3分钟）

对 Claude Code 说：

```
请记住以下关键信息（项目上下文）：

1. 项目类型：待办管理 API
2. 技术栈：Node.js + Express + MongoDB
3. 数据库：MongoDB（Mongoose ODM）
4. 认证方式：JWT
5.  API 接口：POST /todos、GET /todos、PUT /todos/:id、DELETE /todos/:id

请记住这些信息，后续对话中请参考。
```

**Claude Code 会确认**：

```
✅ 已记住项目上下文：
1. 项目类型：待办管理 API
2. 技术栈：Node.js + Express + MongoDB
3. 数据库：MongoDB（Mongoose ODM）
4. 认证方式：JWT
5. API 接口：POST /todos、GET /todos、PUT /todos/:id、DELETE /todos/:id

后续对话中我会参考这些信息。
```

**关键点**：Claude Code 会在当前对话中记住这些信息。

---

### 第二步：管理长对话（拆分任务）（5分钟）

如果你的需求很复杂，不要一次性说完，拆分成多个小任务：

**❌ 不好**：一次性说所有需求

```
请帮我：
1. 搭建待办 API 项目
2. 实现用户认证（JWT）
3. 实现待办事项的 CRUD
4. 添加单元测试
5. 用 Docker 部署
6. 用 GitHub Actions 做 CI/CD

请一次性完成。
```

**✅ 好**：拆分成多个小任务

```
# 任务 1：搭建项目架构
请帮我搭建待办 API 项目架构，包含：
- Express 项目结构
- Mongoose 连接配置
- 路由配置

# 任务 2：实现用户认证
请帮我实现用户认证（JWT），包含：
- 用户注册（POST /users）
- 用户登录（POST /login）
- 认证中间件

# 任务 3：实现待办事项的 CRUD
请帮我实现待办事项的 CRUD，包含：
- 创建待办（POST /todos）
- 获取列表（GET /todos）
- 更新待办（PUT /todos/:id）
- 删除待办（DELETE /todos/:id）
```

**好处**：
- 每次对话更聚焦
- Claude Code 不会"忘记"之前的对话
- 容易验证每个步骤的结果

---

### 第三步：用 `SATE_DB` 记住关键信息（3分钟）

如果 Claude Code 忘记了之前的关键信息，用 `SATE_DB` 机制提醒它：

```
【记住】项目上下文：
1. 项目类型：待办管理 API
2. 技术栈：Node.js + Express + MongoDB
3. 数据库：MongoDB（Mongoose ODM）
4. 认证方式：JWT

请参考这些信息继续工作。
```

**Claude Code 会回应**：

```
✅ 已更新项目上下文。

继续之前的工作：实现待办事项的 CRUD...
```

---

### 第四步：用 `SATE_SUMMARY` 压缩上下文（5分钟）

如果对话很长，Claude Code 的上下文窗口快满了，用 `SATE_SUMMARY` 压缩之前的对话：

```
【上下文总结】

我们已经完成了：
1. ✅ 搭建项目架构（Express + MongoDB）
2. ✅ 实现用户认证（JWT）
3. 🔄 正在实现待办事项的 CRUD

接下来要做的：
1. 完成待办事项的更新和删除
2. 添加单元测试
3. 用 Docker 部署

请参考这个总结继续工作。
```

**Claude Code 会回应**：

```
✅ 已理解当前进度。

继续实现待办事项的更新和删除...
```

**好处**：
- 压缩上下文，避免窗口溢出
- 让 Claude Code 快速回顾之前的进度

---

### 第五步：用文件管理上下文（推荐）（5分钟）

**最好的方式**：把关键信息写到文件里，让 Claude Code 读取文件。

#### 1. 创建 `PROJECT_CONTEXT.md`

```markdown
# 项目上下文

## 项目类型
待办管理 API

## 技术栈
- Node.js 18+
- Express 4.x
- MongoDB（Mongoose ODM）
- JWT 认证

## 数据库设计
### User Model
- name: String
- email: String（unique）
- password: String（hashed）

### Todo Model
- title: String（required）
- description: String
- completed: Boolean
- userId: ObjectId（ref: User）
- createdAt: Date

## API 接口
- POST /users（注册）
- POST /login（登录）
- POST /todos（创建待办）
- GET /todos（获取列表）
- PUT /todos/:id（更新待办）
- DELETE /todos/:id（删除待办）

## 已完成
- ✅ 项目架构搭建
- ✅ 用户认证实现

## 待完成
- 🔄 待办事项 CRUD
- ⬜ 单元测试
- ⬜ Docker 部署
```

#### 2. 让 Claude Code 读取上下文

```
请先读取 PROJECT_CONTEXT.md，了解项目上下文，然后继续实现待办事项的 CRUD。
```

**Claude Code 会读取文件**，然后基于文件内容继续工作。

---

## 核心技巧

### 1. 用文件管理上下文，别依赖记忆

❌ **不好**：依赖 Claude Code 的记忆力（长对话会忘）
✅ **好**：把关键信息写到文件里（如 `PROJECT_CONTEXT.md`）

**好处**：
- 跨会话保持上下文（新对话也能读取）
- 团队成员都能看到项目上下文
- 方便更新和维护

---

### 2. 长对话要拆分任务，别一次性说完

❌ **不好**：一次性说 10 个需求
✅ **好**：拆分成 10 个小任务，逐个完成

**原因**：
- Claude Code 的上下文窗口有限（~200K tokens）
- 长对话后，Claude Code 会"忘记"之前的内容

---

### 3. 用 `SATE_SUMMARY` 压缩上下文

如果对话很长，用 `SATE_SUMMARY` 压缩：

```
【上下文总结】

我们已经完成了：
1. ✅ ...
2. ✅ ...

接下来要做的：
1. ...
2. ...

请参考这个总结继续工作。
```

**好处**：
- 压缩上下文，避免窗口溢出
- 让 Claude Code 快速回顾进度

---

### 4. 关键信息用"强调"语气，别轻描淡写

❌ **不好**："顺便说一下，我们用的是 MongoDB..."
✅ **好**："【重要】数据库：MongoDB（Mongoose ODM）"

**原因**：Claude Code 对"强调"的内容印象更深。
