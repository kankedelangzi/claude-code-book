# 6.1 多文件协同编辑

> 让 Claude Code 同时改多个文件，保持一致性。

## 🎯 场景描述

你要重构一个功能，涉及多个文件：
- 修改 API 接口定义
- 更新调用方的代码
- 同步更新测试文件
- 更新文档

一个一个改太慢，还容易漏。Claude Code 可以帮你一起改。

## 💡 核心思路

```
告诉 Claude Code 变更范围 + 让它同时修改所有相关文件
```

关键原则：**一次描述清楚所有关联改动，让 Claude Code 全局执行，而不是逐个文件指导它。**

## 📝 实战案例一：重命名函数

```

- services/userService.js
- controllers/userController.js

```

```javascript
// services/userService.js - 改前

// services/userService.js - 改后
async function findUserById(id) {
  return await db.users.findUnique({ where: { id } });

```

```javascript
// controllers/userController.js - 改前
```


## 📝 实战案例二：添加新字段

### 需求描述

```
给 User 添加一个 role 字段，涉及：

1. 数据库 schema (schema.prisma)
2. 类型定义 (types/user.ts)
3. 服务层 (services/userService.ts)
4. API 响应 (controllers/userController.ts)
5. 前端组件 (components/UserCard.vue)
6. 测试数据 (tests/fixtures/user.json)

role 的值：'admin' | 'user' | 'guest'
默认值：'user'
```

### Claude Code 一键搞定

**schema.prisma**
```prisma
model User {
  id        Int      @id @default(autoincrement())
  email     String   @unique
  name      String
  role      String   @default("user")  // 新增
  createdAt DateTime @default(now())
}
```

**types/user.ts**
```typescript
export interface User {
  id: number;
  email: string;
  name: string;
  role: 'admin' | 'user' | 'guest';  // 新增
  createdAt: Date;
}
```

**services/userService.ts**
```typescript
async function createUser(data: CreateUserData) {
  return await db.user.create({
    data: {
      ...data,
      role: data.role || 'user',  // 默认值
    }

```

**controllers/userController.ts**
```typescript
// API 响应中包含 role 字段
function formatUserResponse(user: User) {
  return {
    id: user.id,

```

**components/UserCard.vue**

## 📝 实战案例三：迁移到新 API

### 需求描述

```
项目要从 REST API 迁移到 GraphQL，涉及：

1. 替换所有 fetch('/api/xxx') 为 GraphQL 查询
2. 更新类型定义
3. 修改错误处理逻辑
4. 更新 mock 数据

帮我处理 src/api/ 目录下所有文件。
```

### Claude Code 批量转换

**改前 (REST)**
```typescript
// api/users.ts
export async function getUsers() {
  const res = await fetch('/api/users');
  return res.json();
}

export async function getUser(id: number) {
  const res = await fetch(`/api/users/${id}`);
  return res.json();
}
```

**改后 (GraphQL)**
```typescript
// api/users.ts
import { gql, client } from './client';

export async function getUsers() {
  const { data } = await client.query({
    query: gql`
      query GetUsers {
        users {
          id
          name
          email
        }
      }
    `
  });
  return data.users;
}

export async function getUser(id: number) {
  const { data } = await client.query({
    query: gql`
      query GetUser($id: Int!) {
        user(id: $id) {
          id
          name
          email
        }
      }
    `,
    variables: { id }
  });
  return data.user;
}
```

## 📝 实战案例五：依赖库升级

把 moment.js 换成 dayjs——经典的依赖替换场景。

### 需求描述

```
把项目里的 moment.js 全部替换成 dayjs，包括：

1. 替换 import 语句
2. 处理 API 差异（moment 和 dayjs 用法不同）
3. 更新 package.json 依赖
4. 删除 moment 相关的类型声明

先搜索所有使用 moment 的文件。
```

### Claude Code 扫描 + 替换

```
搜索 import moment 找到 12 个文件：

api/dateHelpers.ts     - 使用 moment().format()
components/Report.vue  - 使用 moment().subtract()
utils/scheduler.ts     - 使用 moment.duration()
pages/Calendar.vue     - 使用 moment.locale()
...

API 差异对照：
  moment().format('YYYY-MM-DD')     → dayjs().format('YYYY-MM-DD')    ✅ 语法相同
  moment().subtract(7, 'days')      → dayjs().subtract(7, 'day')      ⚠️ 'days'→'day'
  moment.duration(2, 'hours')       → dayjs.extend(durationPlugin)    ⚠️ 需要插件
  moment.locale('zh-cn')            → dayjs.locale('zh-cn')           ✅ 语法相同

开始替换...
```

**utils/scheduler.ts — 有 API 差异，需要特殊处理**

```typescript
// 改前
import moment from 'moment';

const delay = moment.duration(2, 'hours').asMilliseconds();
const deadline = moment().add(3, 'days');

// 改后
import dayjs from 'dayjs';
import duration from 'dayjs/plugin/duration';
import dayjs_add from 'dayjs/plugin/addDays';

dayjs.extend(duration);
dayjs.extend(dayjs_add);

const delay = dayjs.duration(2, 'hour').asMilliseconds();  // 'hours'→'hour'
const deadline = dayjs().add(3, 'day');                     // 'days'→'day'
```

**components/Report.vue**

```vue
<!-- 改前 -->
<script>
import moment from 'moment';
export default {
  computed: {
    lastWeek() {
      return moment().subtract(7, 'days').format('YYYY-MM-DD');
    }
  }
}
</script>

<!-- 改后 -->
<script>
import dayjs from 'dayjs';
export default {
  computed: {
    lastWeek() {
      return dayjs().subtract(7, 'day').format('YYYY-MM-DD');
    }
  }
}
</script>
```

### Claude Code 最后处理 package.json

```bash
npm uninstall moment
npm install dayjs
```

## 📝 实战案例六：统一错误处理模式

这种改动看似简单，实际影响面广——从 API 层到 UI 层全要改。

### 需求描述

```
项目目前每个 API 调用都单独 try/catch，错误处理不统一。
我要改成统一的错误拦截模式：

1. 创建统一的错误处理中间件 src/utils/errorHandler.ts
2. 修改 axios 拦截器统一处理错误
3. 删除各处重复的 try/catch
4. 添加全局错误提示组件

涉及 src/api/ 和 src/components/ 目录。
```

### 改造过程

**新建统一处理器**

```typescript
// src/utils/errorHandler.ts
import { ElMessage } from 'element-plus';

export interface AppError {
  code: string;
  message: string;
  detail?: unknown;
}

export function handleError(error: AppError | Error) {
  if ('code' in error) {
    // 业务错误
    const messages: Record<string, string> = {
      AUTH_EXPIRED: '登录已过期，请重新登录',
      PERMISSION_DENIED: '没有操作权限',
      NOT_FOUND: '请求的资源不存在',
      VALIDATION_ERROR: error.message,
    };
    ElMessage.error(messages[error.code] || '操作失败');
    
    if (error.code === 'AUTH_EXPIRED') {
      window.location.href = '/login';
    }
  } else {
    // 未知错误
    ElMessage.error('系统异常，请稍后重试');
    console.error(error);
  }
}
```

**改造前 — 每个请求单独处理**

```typescript
// api/users.ts — 改前
export async function getUsers() {
  try {
    const res = await axios.get('/api/users');
    return res.data;
  } catch (e) {
    if (e.response?.status === 401) {
      message.error('登录过期');
      router.push('/login');
    } else {
      message.error('获取用户列表失败');
    }
    throw e;
  }
}

export async function createUser(data: User) {
  try {
    const res = await axios.post('/api/users', data);
    return res.data;
  } catch (e) {
    if (e.response?.status === 401) {
      message.error('登录过期');
      router.push('/login');
    } else if (e.response?.status === 422) {
      message.error(e.response.data.message);
    } else {
      message.error('创建用户失败');
    }
    throw e;
  }
}
```

**改造后 — 统一拦截，业务代码只关心正常逻辑**

```typescript
// api/users.ts — 改后
import { api } from './client';  // 带 interceptor 的 axios 实例

export async function getUsers() {
  const res = await api.get('/api/users');
  return res.data;
}

export async function createUser(data: User) {
  const res = await api.post('/api/users', data);
  return res.data;
}
```

所有错误处理统一在拦截器完成，业务代码变得干净清爽。Claude Code 一次改完全部 8 个 API 文件。

## ⚡ 进阶技巧

### 技巧一：让 Claude Code 自己找关联文件

```
我要把项目里的 moment.js 换成 dayjs。
请先找出所有使用 moment.js 的文件，然后一起修改。
```

Claude Code 会：
1. 搜索 `import moment` 或 `require('moment')`
2. 找出所有使用的地方
3. 批量替换为 dayjs
4. 处理 API 差异（moment 和 dayjs 的 API 不完全一样）

### 技巧二：改动前先列清单确认

```
我要给所有 API 接口加上 JWT 鉴权。
先列出需要修改的文件，我确认后再改。
```

这样做的好处：
- 你知道改动范围，心里有数
- 可以排除不想改的文件
- 避免 Claude Code 改过头

### 技巧三：分批提交多文件改动

```
改完后按功能分批提交：
- 类型定义的改动一次提交
- 业务逻辑的改动一次提交
- 测试的改动一次提交
```

保持 Git 历史清晰，万一出问题也好回滚。

### 技巧四：用 CLAUDE.md 记录项目结构

在项目根目录放一个 CLAUDE.md 文件，记录项目结构：

```markdown
# 项目结构
- src/api/ — API 请求层，所有接口都在这里
- src/types/ — TypeScript 类型定义
- src/components/ — Vue 组件
- src/stores/ — Pinia 状态管理
- src/utils/ — 工具函数
```

Claude Code 读取后会更好地理解文件关联，多文件修改更精准。

## 🎓 学到了什么

1. **多文件修改要一次性描述清楚，让 Claude Code 全部处理**
2. **改名、加字段、迁移 API 都可以自动化**
3. **让 Claude Code 先搜索再改，不会遗漏**
4. **改完后跑一遍测试验证**
5. **复杂的全局改动（国际化、错误处理统一）也能批量完成**
6. **改动前列清单、改完后分批提交，保持可控**

## ⚠️ 注意事项

- 改动前先提交代码（方便回滚）
- 大范围改动让 Claude Code 列出文件清单确认
- 改完后跑测试确保没破坏功能
- 依赖升级要注意 API 差异，不能简单全局替换
- 涉及公共模块的改动，多写几个测试用例保护
