## 🔧 常见报错速查

| 报错类型 | 最常见原因 | 快速修复 |
|---------|-----------|---------|
| `undefined is not a function` | 函数未定义或拼写错误 | 检查 import 是否正确 |
| `Cannot read property 'X' of null` | 对象是 null | `obj?.X` 或默认值 |
| `Maximum update depth exceeded` | useEffect 依赖数组有问题 | 添加空数组 `[]` 或正确依赖 |
| `CORS error` | 跨域请求未配置 | 后端加 CORS 头或代理 |
| `404 on localhost` | 路径拼写或端口错误 | 检查服务是否启动 |

## 🚀 进阶案例：复杂报错链路追踪

### 案例：React + TypeScript 项目报错

**报错信息：**

```
TypeError: Cannot read properties of undefined (reading 'filter')
    at UserList (src/components/UserList.tsx:42:18)
    at renderWithHooks (react-dom.development.js:14985:18)
    at mountIndeterminateComponent (react-dom.development.js:17802:12)
```

**给 Claude Code 的完整信息：**

```
报错了，帮我分析：

报错信息：
```
TypeError: Cannot read properties of undefined (reading 'filter')
    at UserList (src/components/UserList.tsx:42:18)
```

技术栈：React 18 + TypeScript + Redux Toolkit

组件代码（第40-50行）：
```tsx
const UserList = () => {
  const users = useAppSelector(state => state.users.list)
  const filtered = users.filter(u => u.active) // 第42行
  return <ul>{filtered.map(u => <li key={u.id}>{u.name}</li>)}</ul>
}
```

Redux slice：
```tsx
const usersSlice = createSlice({
  name: 'users',
  initialState: { list: [], loading: false },
  reducers: { ... }
})
```

问题：页面刷新后偶现这个报错，刷新几次又好了。
```

**Claude Code 分析结果：**

```
问题定位：
1. users 在某时刻是 undefined，不是空数组 []
2. 偶现说明和异步数据加载有关

可能原因：
1. Redux initialState 设置了 list: []，但某处代码把它设成了 undefined
2. 组件渲染时，Redux 状态还没初始化完成
3. 某个 reducer 错误地返回了 undefined

建议检查：
1. 搜索所有对 state.users.list 的赋值
2. 检查 RTK Query 或异步 action 的处理
3. 加防御代码：const users = useAppSelector(state => state.users.list) ?? []
```

### 案例：Node.js 后端报错

**报错信息：**

```
Error: Cannot set headers after they are sent to the client
    at ServerResponse.setHeader (_http_outgoing.js:485:11)
    at res.header (express/lib/response.js:769:10)
```

**给 Claude Code 的分析请求：**

```
这个报错是什么意思？代码如下：

```javascript
router.post('/order', async (req, res) => {
  const order = await createOrder(req.body)
  res.json({ success: true, order })
  
  // 发送通知（不阻塞响应）
  sendNotification(order.id).catch(console.error)
  
  // 记录日志
  logOrder(order.id)
  res.json({ logged: true }) // 这里报错
})
```
```

**Claude Code 分析：**

```
问题：res.json() 被调用了两次

分析：
1. 第一个 res.json() 已经发送响应并结束
2. 第二个 res.json() 尝试再次发送，报错

修复方案：
```javascript
router.post('/order', async (req, res) => {
  const order = await createOrder(req.body)
  
  // 异步操作放后面，不要再调 res.json
  sendNotification(order.id).catch(console.error)
  logOrder(order.id)
  
  // 只发送一次响应
  res.json({ success: true, order })
})
```
```

## 🔍 报错信息解读速查表

### JavaScript/TypeScript 常见报错

| 报错信息 | 原因分析 | 快速修复 |
|---------|---------|---------|
| `undefined is not a function` | 变量是 undefined 但当函数调用 | 检查变量定义和 import |
| `Cannot read property 'X' of undefined` | 对象为 undefined | `obj?.X` 或 `obj \|\| {}` |
| `Cannot read property 'X' of null` | 对象为 null | 加 null 检查 |
| `X is not defined` | 变量未声明 | 检查作用域和拼写 |
| `Maximum call stack size exceeded` | 无限递归 | 检查递归终止条件 |
| `Unexpected token` | 语法错误 | 检查括号、引号匹配 |

### React 常见报错

| 报错信息 | 原因分析 | 快速修复 |
|---------|---------|---------|
| `Maximum update depth exceeded` | 无限重渲染 | 检查 useEffect 依赖数组 |
| `Objects are not valid as a React child` | 直接渲染对象 | 渲染对象的具体属性 |
| `Cannot update a component while rendering` | 渲染时调用 setState | 把 setState 移到 useEffect |
| `Each child in a list should have a unique "key"` | 列表缺少 key | 加 `key={item.id}` |

### Node.js 常见报错

| 报错信息 | 原因分析 | 快速修复 |
|---------|---------|---------|
| `ECONNREFUSED` | 连接被拒绝 | 检查服务是否启动 |
| `ETIMEDOUT` | 连接超时 | 检查网络或增加超时时间 |
| `Cannot set headers after they are sent` | 重复发送响应 | 一个请求只发一次响应 |
| `Port 3000 is already in use` | 端口被占用 | 换端口或杀掉占用进程 |

### Python 常见报错

| 报错信息 | 原因分析 | 快速修复 |
|---------|---------|--------|
| `ModuleNotFoundError: No module named 'X'` | 模块未安装或虚拟环境不对 | `pip install X` 或激活正确的 venv |
| `KeyError: 'X'` | 字典中不存在该键 | 用 `dict.get('X', default)` 或先判断 |
| `IndexError: list index out of range` | 列表索引越界 | 检查列表长度，用 `len()` 判断 |
| `TypeError: 'NoneType' object is not iterable` | 函数返回了 None 但被当可迭代对象 | 检查函数是否所有路径都有 return |
| `AttributeError: 'NoneType' object has no attribute 'X'` | 对象是 None | 检查上游赋值，加 None 判断 |
| `RecursionError: maximum recursion depth exceeded` | 递归没有终止条件 | 检查递归出口，或用迭代替代 |
| `UnicodeDecodeError: 'gbk' codec can't decode` | 文件编码不对 | 用 `open(f, encoding='utf-8')` 指定编码 |
| `ImportError: cannot import name 'X' from 'Y'` | 导入名称不存在或版本不兼容 | 检查包版本，`pip show Y` 确认 |

### 数据库常见报错

| 报错信息 | 原因分析 | 快速修复 |
|---------|---------|--------|
| `ECONNREFUSED` (PostgreSQL) | 数据库服务未启动 | `pg_isready` 检查，`pg_ctl start` 启动 |
| `Access denied for user` | 用户名或密码错误 | 检查 `.env` 中的数据库凭据 |
| `relation "X" does not exist` | 表不存在或 schema 不对 | 检查迁移是否执行，`npx prisma migrate dev` |
| `column "X" does not exist` | 列不存在 | 检查迁移，确认列名拼写 |
| `deadlock detected` | 事务死锁 | 检查事务顺序，添加重试逻辑 |
| `too many connections` | 连接池耗尽 | 检查连接泄漏，增大连接池上限 |
| `syntax error at or near` | SQL 语法错误 | 检查引号、逗号、关键字拼写 |
| `value too long for type character varying(N)` | 字符串超长 | 检查输入长度，或修改列定义 |

### Docker / 部署常见报错

| 报错信息 | 原因分析 | 快速修复 |
|---------|---------|--------|
| `OOM killed` | 内存不足 | 增大内存限制或优化代码 |
| `port is already allocated` | 端口冲突 | `docker ps` 查看，`docker stop` 或换端口 |
| `no space left on device` | 磁盘满 | `docker system prune` 清理镜像/容器 |
| `permission denied` | 文件权限不对 | 检查 Dockerfile 中的 USER 和文件权限 |
| `network X not found` | Docker 网络不存在 | `docker network create X` 或检查 compose 配置 |

## 🔥 实战案例：Python 项目报错排查

### 案例：Flask 接口 500 错误

**报错信息：**

```
TypeError: The view function did not return a valid response.
The return type was str, but it needs to be a tuple or Response object.
```

**给 Claude Code 的分析请求：**

```
Flask 接口报 500，日志如下：

TypeError: The view function did not return a valid response.
The return type was str, but it needs to be a tuple or Response object.

代码：
```python
@app.route('/api/users', methods=['POST'])
def create_user():
    data = request.get_json()
    if not data.get('email'):
        return '邮箱不能为空'  # 这里报错
    user = save_user(data)
    return jsonify(user.to_dict()), 201
```
```

**Claude Code 分析：**

```
问题：Flask 视图函数返回了纯字符串，但 Flask 1.0+
要求返回 Response 对象或 (response, status) 元组。

修复方案：
```python
@app.route('/api/users', methods=['POST'])
def create_user():
    data = request.get_json()
    if not data.get('email'):
        return jsonify({'error': '邮箱不能为空'}), 400  # 返回 JSON + 状态码
    user = save_user(data)
    return jsonify(user.to_dict()), 201
```
```

### 案例：Python 异步代码报错

**报错信息：**

```
RuntimeWarning: coroutine 'get_user' was never awaited
```

**给 Claude Code 的分析请求：**

```
Python 异步代码报了这个警告，但数据没拿到：

```python
async def get_user(user_id):
    return await db.users.find_one({'_id': user_id})

# 调用处
user = get_user(user_id)  # 忘了 await
print(user['name'])  # 报 TypeError: 'coroutine' object is not subscriptable
```

技术栈：FastAPI + MongoDB + motor
```

**Claude Code 分析：**

```
问题：调用异步函数时忘了 await，返回的是协程对象而非结果。

修复：
```python
user = await get_user(user_id)  # 加 await
print(user['name'])
```

如果是非异步上下文调用异步函数，需要用 asyncio.run() 或
把调用方也改成 async。
```

## 🎯 高效报错定位的 5 个习惯

### 习惯 1：看报错信息的最后一段

堆栈跟踪从上到下，**最先看最后一段**——那里才是你自己的代码：

```
  at processTicksAndRejections (node:internal/process/task_queues:95:5)  ← 框架代码，跳过
  at async runMicrotasks (node:internal/process/task_queues:42:1)        ← 框架代码，跳过
  at async UserController.getUser (src/controllers/user.ts:25:12)       ← 👈 你的代码，看这里
```

### 习惯 2：区分「报错行」和「原因行」

报错行不等于问题行。比如：

```javascript
const data = JSON.parse(response)  // 报错行：SyntaxError
```

真正的原因可能是 `response` 本身就不是合法 JSON——问题在上游。

**给 Claude Code 时同时提供报错行和上游代码。**

### 习惯 3：偶现报错 = 并发/时序问题

如果报错「有时候有、有时候没有」，多半是：
- 异步数据还没到就开始用
- 两个请求同时修改同一份数据
- 缓存和数据库不同步

**给 Claude Code 时强调「偶现」，它会从时序角度分析。**

### 习惯 4：用二分法缩小范围

不确定哪段代码导致报错时：

```
我有一个报错，不确定是 A 模块还是 B 模块导致的。
我注释掉了 A 模块的调用，报错消失了。
这是 A 模块的代码，帮我看看问题在哪。
```

### 习惯 5：保存「报错-原因-修复」笔记

每次解决一个报错，记下来：

```markdown
| 报错信息 | 原因 | 修复方式 | 耗时 |
|---------|------|---------|------|
| Cannot read property 'map' of undefined | 接口返回 null | 加 `?? []` | 30min |
| ECONNREFUSED | Redis 没启动 | Docker restart | 10min |
```

下次遇到同类报错，直接查表，从 30 分钟变 30 秒。
