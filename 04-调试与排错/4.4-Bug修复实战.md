# 4.4 Bug 修复实战

## 场景描述

生产环境报 Bug 了，用户投诉功能不正常。用 Claude Code 可以快速**定位 Bug 根源**、**生成修复方案**、**自动修复代码**。

本章案例：定位并修复一个 Express 项目的 Bug（包含逻辑错误、异步错误、边界条件错误）。

---

## 核心目标

- **Bug 定位**：让 Claude Code 快速定位 Bug 根源
- **生成方案**：自动生成修复方案（多种方案备选）
- **自动修复**：让 Claude Code 修改代码（保持功能不变）
- **验证结果**：用测试确保修复不引入新 Bug

## 完整工作流

### 第一步：准备"有 Bug 的代码"（2分钟）

假设我们有一个有 Bug 的待办 API（`todoService.js`）：

```javascript
const Todo = require('../models/Todo');

const todoService = {
  // Bug 1：逻辑错误（应该过滤已完成，但代码写错了）
  getPendingTodos: async (userId) => {
    const todos = await Todo.find({ userId });
    return todos.filter(t => t.completed === 'true');  // ← 应该是 true，不是 'true'
  },
  
  // Bug 2：异步错误（未 await）
  createTodo: async ({ title, description }) => {
    if (!title) {
      const err = new Error('Title is required');
      err.status = 400;
      throw err;
    }
    
    const todo = new Todo({ title, description });
    todo.save();  // ← 缺少 await
    return todo;
  },
  
  // Bug 3：边界条件错误（未处理空数组）
  getStats: async (userId) => {
    const todos = await Todo.find({ userId });
    
    const stats = {
      total: todos.length,
      completed: todos.filter(t => t.completed).length,
      pending: todos.filter(t => !t.completed).length,
      completionRate: (todos.filter(t => t.completed).length / todos.length) * 100  // ← 如果 todos 为空，除零错误
    };
    
    return stats;
  },
  
  // Bug 4：并发问题（未加锁）
  incrementViewCount: async (todoId) => {
    const todo = await Todo.findById(todoId);
    todo.viewCount += 1;  // ← 并发时可能丢失更新
    await todo.save();
    return todo;
  }
};

module.exports = todoService;
```

**Bug 清单**：
1. 逻辑错误：`t.completed === 'true'` 应该是 `t.completed === true`（第 7 行）
2. 异步错误：`todo.save()` 前未加 `await`（第 17 行）
3. 边界条件错误：除零错误（如果 `todos` 为空）（第 28 行）
4. 并发问题：未加锁，并发更新可能丢失（第 35 行）

```

**Claude Code 会生成类似报告**：

```markdown
# Bug 定位报告

## 1. 逻辑错误（高危 🔴）

**位置**：第 7 行
**问题**：`t.completed === 'true'` 应该是 `t.completed === true`
**影响**：所有待办事项都被视为未完成，`getPendingTodos` 永远返回空数组

**修复方案**：
```javascript
// 错误代码
return todos.filter(t => t.completed === 'true');

// 正确代码
return todos.filter(t => t.completed === true);
```

---

## 2. 异步错误（高危 🔴）

**位置**：第 17 行
**问题**：`todo.save()` 前未加 `await`
**影响**：函数立即返回 `todo`（此时还未保存到数据库）

**修复方案**：
```javascript
// 错误代码
todo.save();
return todo;

// 正确代码
await todo.save();
return todo;
```

---

## 3. 边界条件错误（中危 🟡）

**位置**：第 28 行
**问题**：如果 `todos` 为空数组，`todos.length` 为 0，导致除零错误
**影响**：`getStats` 函数抛出异常

**修复方案**：
```javascript
// 错误代码
completionRate: (todos.filter(t => t.completed).length / todos.length) * 100

// 正确代码
completionRate: todos.length > 0 
  ? (todos.filter(t => t.completed).length / todos.length) * 100 
  : 0
```

---

## 4. 并发问题（低危 🟢）

**位置**：第 35 行
**问题**：`todo.viewCount += 1` 在并发时会丢失更新
**影响**：多个用户同时查看待办事项，`viewCount` 不准确

**修复方案**：
```javascript
// 方案1：用 findByIdAndUpdate（原子操作）
const todo = await Todo.findByIdAndUpdate(
  todoId,
  { $inc: { viewCount: 1 } },  // 原子递增
  { new: true }
);

// 方案2：用 Redis 锁（分布式锁）
const lock = await redis.lock(`todo:${todoId}`);
try {
  const todo = await Todo.findById(todoId);
  todo.viewCount += 1;
  await todo.save();
} finally {
  lock.unlock();
}
```

## 修复优先级

1. **立即修复**：逻辑错误（功能完全不正常）
2. **立即修复**：异步错误（数据未保存）
3. **高优先级**：边界条件错误（空数组导致崩溃）
4. **中优先级**：并发问题（数据不准确）

---

## 验证方案

1. **逻辑错误**：调用 `getPendingTodos`，检查返回结果
2. **异步错误**：调用 `createTodo`，检查数据库是否有数据
3. **边界条件错误**：调用 `getStats`（空数组场景），检查是否抛异常
4. **并发问题**：用压测工具模拟并发，检查 `viewCount` 是否准确

## 核心技巧

### 1. 让 Claude Code 生成"完整的 Bug 定位报告"

❌ **不好**：只说"帮我修复 Bug"
✅ **好**：明确说出你要分析的方面

```
请帮我定位 Bug，重点检查：
1. 逻辑错误（条件判断错误）
2. 异步错误（未 await）
3. 边界条件错误（空数组、null、undefined）
4. 并发问题（未加锁、丢失更新）
```

---

### 2. 优先修复"高危"Bug

根据 Bug 报告的优先级逐个修复：

1. **立即修复**：逻辑错误（功能完全不正常）
2. **立即修复**：异步错误（数据未保存）
3. **高优先级**：边界条件错误（空数组导致崩溃）
4. **中优先级**：并发问题（数据不准确）

---

### 3. 用"分步修复"降低风险

❌ **不好**：让 Claude Code "一次性修复所有 Bug"
✅ **好**：分步修复，每步验证

```
第一步：修复逻辑错误
第二步：修复异步错误
第三步：修复边界条件错误
第四步：修复并发问题
```

**原因**：分步修复容易回滚，一旦出错可以快速定位。

---

### 4. 让 Claude Code 生成单元测试验证修复效果

❌ **不好**：修复完就完事，不验证
✅ **好**：修复后生成单元测试，确保修复有效

```
请帮我修复这个 Bug，并生成单元测试验证修复效果。

重点测试：
1. 正常场景（功能恢复正常）
2. 边界场景（空数组、null、undefined）
3. 并发场景（模拟并发请求）
```
