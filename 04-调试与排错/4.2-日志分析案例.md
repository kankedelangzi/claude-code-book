**Claude Code 会生成类似报告**：

```markdown
# 日志分析报告

分析时间范围：2026-05-17 10:00:00 - 10:00:50

---

## 1. 错误统计

### 数据库连接有问题（高危 🔴）
- **错误次数**：3 次
- **错误率**：30%（3/10 条日志）
- **时间分布**：10:00:10、10:00:30、10:00:35（每 20-25 秒一次）
- **可能原因**：
  1. 数据库服务挂了
  2. 数据库连接池满了
  3. 网络不稳定

**建议**：
- 检查数据库服务状态（CPU、内存、磁盘）
- 增加数据库连接池大小
- 添加数据库健康检查

---

### 未处理的 Promise 拒绝（中危 🟡）
- **错误次数**：2 次
- **错误信息**：`Cannot read property 'map' of undefined`
- **可能原因**：代码中没有 `await`（异步错误）

**建议**：
- 用 `try-catch` 包裹异步代码
- 用 `express-async-errors` 自动捕获

---

## 2. 性能分析

### 慢查询（中危 🟡）
- **查询**：`SELECT * FROM users`
- **耗时**：1200ms（正常应该 <100ms）
- **可能原因**：
  1. 没有索引
  2. 返回数据量太大（没有分页）

**建议**：
- 在 `users` 表的主键上添加索引
- 添加分页（LIMIT 20）

---

### 内存使用过高（低危 🟢）
- **内存使用率**：85%
- **可能原因**：
  1. 内存泄漏（全局变量未释放）
  2. 数据量太大（一次性加载所有数据）

**建议**：
- 用 `heapdump` 分析内存泄漏
- 分页加载数据

---

## 3. 异常模式

### 周期性错误
- **模式**：数据库连接失败每 20-25 秒发生一次
- **推断**：可能是健康检查机制在重试，但一直失败

---

## 4. 改进建议（按优先级）

1. **立即处理**：修复数据库连接问题（检查数据库服务）
2. **高优先级**：修复未处理的 Promise 拒绝（加 `try-catch`）
3. **中优先级**：优化慢查询（加索引、分页）
4. **低优先级**：分析内存泄漏（用 `heapdump`）

---

## 5. 监控告警建议

- **数据库连接失败**：超过 2 次/分钟 → 立即告警（邮件 + Slack）
- **慢查询**：超过 500ms → 记录日志，超过 1000ms → 告警
- **内存使用过高**：超过 80% → 告警
```

**Claude Code 会生成类似代码**：

#### `config/logger.js`

```javascript
const winston = require('winston');
const path = require('path');

// 日志格式
const logFormat = winston.format.combine(
  winston.format.timestamp({ format: 'YYYY-MM-DD HH:mm:ss' }),
  winston.format.errors({ stack: true }),
  winston.format.json()
);

// 创建 logger
const logger = winston.createLogger({
  level: process.env.LOG_LEVEL || 'info',
  format: logFormat,
  transports: [
    // 错误日志（单独文件）
    new winston.transports.File({
      filename: path.join(__dirname, '../logs/error.log'),
      level: 'error',
      maxsize: 10485760,  // 10MB
      maxFiles: 5
    }),
    // 综合日志
    new winston.transports.File({
      filename: path.join(__dirname, '../logs/combined.log'),
      maxsize: 10485760,
      maxFiles: 5
    })
  ]
});

// 开发环境：同时输出到控制台
if (process.env.NODE_ENV !== 'production') {
  logger.add(new winston.transports.Console({
    format: winston.format.simple()
  }));
}

module.exports = logger;
```

---

#### `app.js`（集成 Morgan 和 Winston）

```javascript
const express = require('express');
const morgan = require('morgan');
const logger = require('./config/logger');
const app = express();

// HTTP 访问日志（用 Morgan）
app.use(morgan('combined', {
  stream: {
    write: (message) => logger.info(message.trim())
  }
}));

// 路由
app.get('/api/users', async (req, res) => {
  try {
    const users = await User.find();
    logger.info('获取用户列表成功', { count: users.length });
    res.json(users);
  } catch (error) {
    logger.error('获取用户列表失败', { error: error.message, stack: error.stack });
    res.status(500).json({ error: 'Internal server error' });
  }
});

// 错误处理中间件
app.use((err, req, res, next) => {
  logger.error('未处理的错误', { error: err.message, stack: err.stack });
  res.status(500).json({ error: 'Internal server error' });
});

app.listen(3000);
```

**Claude Code 会生成类似代码**：

#### `scripts/monitor.js`

```javascript
const fs = require('fs');
const path = require('path');
const nodemailer = require('nodemailer');

const LOG_FILE = path.join(__dirname, '../logs/combined.log');
const ERROR_THRESHOLD = 5;  // 5 个错误/分钟 → 告警

// 发送邮件告警
const sendAlert = async (subject, message) => {
  const transporter = nodemailer.createTransporter({
    service: 'gmail',
    auth: {
      user: process.env.EMAIL_USER,
      pass: process.env.EMAIL_PASSWORD
    }
  });
  
  await transporter.sendMail({
    from: process.env.EMAIL_USER,
    to: 'admin@example.com',
    subject,
    text: message
  });
  
  console.log('✅ 告警邮件已发送');
};

// 分析日志
const analyzeLogs = () => {
  const content = fs.readFileSync(LOG_FILE, 'utf-8');
  const lines = content.split('\n');
  
  // 统计最近 1 分钟的错误
  const oneMinuteAgo = Date.now() - 60 * 1000;
  const recentErrors = lines.filter(line => {
    if (!line.includes('[error]')) return false;
    
    // 提取时间戳（假设格式：2026-05-17 10:00:00）
    const match = line.match(/^(\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2})/);
    if (!match) return false;
    
    const logTime = new Date(match[1]).getTime();
    return logTime >= oneMinuteAgo;
  });
  
  console.log(`最近 1 分钟内有 ${recentErrors.length} 个错误`);
  
  // 超过阈值 → 告警
  if (recentErrors.length >= ERROR_THRESHOLD) {
    sendAlert(
      '🚨 生产环境错误告警',
      `最近 1 分钟内检测到 ${recentErrors.length} 个错误：\n\n${recentErrors.join('\n')}`
    );
  }
};

// 每分钟执行一次
setInterval(analyzeLogs, 60 * 1000);

// 立即执行一次
analyzeLogs();

console.log('📊 日志监控已启动...');
```

## 核心技巧

### 1. 让 Claude Code 生成"完整的日志分析报告"

❌ **不好**：只说"帮我分析日志"
✅ **好**：明确说出你要分析的方面

```
请帮我分析日志，重点分析：
1. 错误日志（统计错误类型、频率、时间分布）
2. 性能问题（慢查询、内存使用过高）
3. 异常模式（是否有周期性错误？）
4. 生成日志分析报告（包含错误统计、性能分析、改进建议）
```

---

### 2. 日志要"结构化"，别只写字符串

❌ **不好**：`logger.error('数据库错误')`
✅ **好**：`logger.error('数据库错误', { error: err.message, query: sql })`

**好处**：
- 方便日志分析工具解析（Elasticsearch + Kibana）
- 包含上下文信息，容易定位问题

---

### 3. 用 Winston 的"日志轮转"防止磁盘占满

❌ **不好**：所有日志写到一个文件（最终磁盘满）
✅ **好**：用 Winston 的 `maxsize` 和 `maxFiles`

```javascript
new winston.transports.File({
  filename: 'logs/combined.log',
  maxsize: 10485760,  // 10MB
  maxFiles: 5  // 最多保留 5 个文件
})
```

---

### 4. 监控告警要"分级"，别一出错就告警

| 级别 | 条件 | 动作 |
|---|---|---|
| **INFO** | 正常日志 | 只记录，不告警 |
| **WARN** | 性能下降（慢查询） | 记录日志，定期汇总 |
| **ERROR** | 错误次数 > 阈值 | 立即告警（邮件 + Slack） |

**让 Claude Code 生成分级告警规则**：

```
请帮我生成分级告警规则：
1. INFO：不告警
2. WARN：记录日志，每小时汇总
3. ERROR：超过 5 次/分钟 → 立即告警
```
