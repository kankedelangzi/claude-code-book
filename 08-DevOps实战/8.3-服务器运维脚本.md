# 8.3 服务器运维脚本

> SSH 到服务器上改配置？让 Claude Code 先写好脚本，你只管执行。

## 🎯 场景描述

运维工作充满了重复操作：

- 部署新服务、更新配置
- 监控磁盘、内存、CPU
- 备份数据库、清理日志
- SSL 证书续期
- 用户权限管理

**这些大部分可以写成脚本，Claude Code 特别擅长这个。**

## ✨ 案例一：一键部署脚本

### 需求

```
帮我写一个部署脚本 deploy.sh，要求：
1. 拉取最新代码
2. 安装依赖
3. 运行数据库迁移
4. 重新构建
5. 滚动重启 PM2 服务
6. 部署失败自动回滚到上一版本
7. 每步记录日志
8. 发送部署通知
```

### Claude Code 生成

```bash
#!/bin/bash
# deploy.sh — 自动化部署脚本
set -euo pipefail

# ---- 配置 ----
APP_DIR="/var/www/myapp"
BACKUP_DIR="/var/backups/myapp"
PM2_APP_NAME="myapp"
LOG_FILE="/var/log/deploy-$(date +%Y%m%d-%H%M%S).log"
WEBHOOK_URL="${DEPLOY_WEBHOOK_URL:-}"
HEALTH_CHECK_URL="http://localhost:3000/health"
MAX_RETRIES=3

# ---- 工具函数 ----
log() {
    echo "[$(date '+%Y-%m-%d %H:%M:%S')] $1" | tee -a "$LOG_FILE"
}

notify() {
    local status=$1
    local message=$2
    log "通知: [$status] $message"
    if [ -n "$WEBHOOK_URL" ]; then
        curl -s -X POST "$WEBHOOK_URL" \
            -H "Content-Type: application/json" \
            -d "{\"status\":\"$status\",\"message\":\"$message\",\"time\":\"$(date -Iseconds)\"}" \
            > /dev/null 2>&1 || true
    fi
}

health_check() {
    local retries=0
    while [ $retries -lt $MAX_RETRIES ]; do
        if curl -sf "$HEALTH_CHECK_URL" > /dev/null 2>&1; then
            return 0
        fi
        retries=$((retries + 1))
        log "健康检查失败，重试 $retries/$MAX_RETRIES..."
        sleep 5
    done
    return 1
}

rollback() {
    log "❌ 部署失败，执行回滚..."
    if [ -d "$BACKUP_DIR/current" ]; then
        cp -r "$BACKUP_DIR/current/." "$APP_DIR/"
        pm2 restart "$PM2_APP_NAME"
        log "✅ 回滚完成"
        notify "ROLLBACK" "部署失败，已回滚到上一版本"
    else
        log "⚠️ 没有备份，无法回滚"
        notify "FAILURE" "部署失败，且无备份可回滚"
    fi
    exit 1
}

# ---- 清理旧日志 ----
find /var/log -name "deploy-*.log" -mtime +30 -delete

# ---- 部署流程 ----
log "🚀 开始部署..."
notify "START" "部署开始"

cd "$APP_DIR" || { log "目录不存在: $APP_DIR"; exit 1; }

# 1. 备份当前版本
log "📦 备份当前版本..."
mkdir -p "$BACKUP_DIR/current"
cp -r "$APP_DIR"/* "$BACKUP_DIR/current/" 2>/dev/null || true

# 2. 拉取代码
log "📥 拉取最新代码..."
git fetch origin main
git reset --hard origin/main || rollback

# 3. 安装依赖
log "📦 安装依赖..."
npm ci --production=false || rollback

# 4. 数据库迁移
log "🗄️ 运行数据库迁移..."
npx prisma migrate deploy || rollback

# 5. 构建
log "🔨 构建项目..."
npm run build || rollback

# 6. 重启服务
log "🔄 重启服务..."
pm2 restart "$PM2_APP_NAME" --update-env

# 7. 健康检查
log "🏥 健康检查..."
if health_check; then
    log "✅ 部署成功！"
    notify "SUCCESS" "部署成功"
else
    rollback
fi

log "🎉 部署流程完成"
```

### 效率提升

之前手动部署一次：SSH 上去 → git pull → npm install → 手动迁移 → 手动重启 → 测试。搞完 20 分钟。

现在：`./deploy.sh`，2 分钟搞定，失败自动回滚。

## ✨ 案例二：服务器监控脚本

### 需求

```
写一个服务器监控脚本 monitor.sh：
1. 检查 CPU、内存、磁盘使用率
2. 检查关键服务是否运行（PM2 进程、Nginx、PostgreSQL）
3. 超过阈值时发送报警
4. 每 5 分钟执行一次
5. 生成每日报告
```

### Claude Code 生成

```bash
#!/bin/bash
# monitor.sh — 服务器监控脚本
set -euo pipefail

# ---- 阈值配置 ----
CPU_THRESHOLD=80        # CPU 使用率告警阈值 %
MEM_THRESHOLD=85        # 内存使用率告警阈值 %
DISK_THRESHOLD=90       # 磁盘使用率告警阈值 %
WEBHOOK_URL="${MONITOR_WEBHOOK_URL:-}"
DAILY_REPORT="/var/log/server-daily-$(date +%Y%m%d).log"

log() {
    local msg="[$(date '+%H:%M:%S')] $1"
    echo "$msg" >> "$DAILY_REPORT"
    echo "$msg"
}

alert() {
    local level=$1
    local msg=$2
    log "🚨 [${level}] $msg"
    if [ -n "$WEBHOOK_URL" ]; then
        curl -s -X POST "$WEBHOOK_URL" \
            -H "Content-Type: application/json" \
            -d "{\"level\":\"$level\",\"message\":\"$msg\",\"host\":\"$(hostname)\",\"time\":\"$(date -Iseconds)\"}" \
            > /dev/null 2>&1 || true
    fi
}

# ---- 检查 CPU ----
check_cpu() {
    local cpu_usage
    cpu_usage=$(top -l 1 -n 0 2>/dev/null | awk '/CPU usage/ {print int($3)}' || \
                vm_stat | awk '/Pages free/ {free=$3} /Pages active/ {active=$3} /Pages inactive/ {inactive=$3} /Pages speculative/ {spec=$3} END {used=(active+inactive+spec)/(active+inactive+spec+free)*100; printf "%.0f", used}' 2>/dev/null || \
                echo "0")
    
    if [ "$cpu_usage" -gt "$CPU_THRESHOLD" ]; then
        alert "WARNING" "CPU 使用率 ${cpu_usage}%，超过阈值 ${CPU_THRESHOLD}%"
    else
        log "✅ CPU: ${cpu_usage}%"
    fi
}

# ---- 检查内存 ----
check_memory() {
    local mem_usage
    if command -v free &>/dev/null; then
        mem_usage=$(free | awk '/Mem:/ {printf "%.0f", $3/$2*100}')
    else
        mem_usage=$(vm_stat | awk '/Pages free/ {free=$3} /Pages active/ {active=$3} /Pages inactive/ {inactive=$3} /Pages speculative/ {spec=$3} /Pages wired/ {wired=$3} END {used=(active+wired+spec)/(active+wired+spec+free)*100; printf "%.0f", used}')
    fi
    
    if [ "$mem_usage" -gt "$MEM_THRESHOLD" ]; then
        alert "WARNING" "内存使用率 ${mem_usage}%，超过阈值 ${MEM_THRESHOLD}%"
    else
        log "✅ 内存: ${mem_usage}%"
    fi
}

# ---- 检查磁盘 ----
check_disk() {
    local disk_usage
    disk_usage=$(df / | awk 'NR==2 {sub(/%/, "", $5); print $5}')
    
    if [ "$disk_usage" -gt "$DISK_THRESHOLD" ]; then
        alert "CRITICAL" "磁盘使用率 ${disk_usage}%，超过阈值 ${DISK_THRESHOLD}%"
    else
        log "✅ 磁盘: ${disk_usage}%"
    fi
}

# ---- 检查服务 ----
check_service() {
    local name=$1
    if pgrep -f "$name" > /dev/null 2>&1; then
        log "✅ $name 运行中"
    else
        alert "CRITICAL" "$name 未运行！"
    fi
}

# ---- 执行检查 ----
log "====== 监控检查 $(date) ======"
check_cpu
check_memory
check_disk
check_service "nginx"
check_service "pm2"
check_service "postgres"
log "================================"

# ---- 清理旧报告（保留7天）----
find /var/log -name "server-daily-*.log" -mtime +7 -delete
```

## ✨ 案例三：Nginx 配置管理

### 需求

```
帮我写一个 Nginx 脚本 manage-nginx.sh：
1. 测试配置语法（nginx -t）
2. 安全重载（nginx -s reload）
3. 新增/删除站点配置
4. 自动申请 SSL 证书
5. 开启 HTTP/2 和 gzip
```

### Claude Code 生成的站点模板

```nginx
# /etc/nginx/sites-available/myapp.conf
server {
    listen 80;
    listen [::]:80;
    server_name myapp.com www.myapp.com;
    
    # 自动跳转 HTTPS
    return 301 https://$server_name$request_uri;
}

server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;
    server_name myapp.com www.myapp.com;

    ssl_certificate /etc/letsencrypt/live/myapp.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/myapp.com/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256;

    gzip on;
    gzip_types text/plain text/css application/json application/javascript text/xml;
    gzip_min_length 1000;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:4000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        
        # API 超时设置
        proxy_connect_timeout 10s;
        proxy_read_timeout 30s;
    }
}
```

## ⚠️ 注意事项

1. **先在测试环境跑** — 运维脚本在生产环境直接跑，出错了代价很大
2. **备份再操作** — 任何修改配置的脚本都要先备份
3. **回滚方案** — 脚本必须有回滚能力，尤其是部署脚本
4. **不要把密钥写进脚本** — 用环境变量或密钥管理工具
5. **日志是救命的** — 每一步都记录，出问题时靠日志排查

## 🎓 学到了什么

1. **运维脚本 = 部署 + 监控 + 回滚** — Claude Code 能帮你写出完整的工具链
2. **回滚比部署更重要** — 没有回滚能力的部署脚本就是定时炸弹
3. **监控要设合理的阈值** — 太高没意义，太低天天报警
4. **标准化是关键** — 所有服务器用同一套脚本，维护成本大幅降低
