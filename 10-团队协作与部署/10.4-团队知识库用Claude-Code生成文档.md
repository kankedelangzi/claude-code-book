# 10.4 团队知识库：用 Claude Code 生成文档

> 团队知识库是新人 onboarding、知识传承、协作效率的关键。Claude Code 可以帮你自动生成和维护知识库文档。

---

## 场景：从零搭建团队知识库

**背景**：一个 10 人团队，没有文档，新人入职后要花 2 周才能上手。

**目标**：用 Claude Code 在 1 天内生成完整的团队知识库。

---

## 第一步：生成知识库框架

```bash
你：帮我设计一个团队知识库的框架，包含以下内容：

3. 开发流程文档（development workflow）
4. 代码规范（coding standards）
5. 常见问题 FAQ（troubleshooting）

输出 Markdown 格式，保存到 docs/knowledge-base/
```

## 第二步：逐个生成文档内容

### 2.1 生成新人入职指南

```bash
你：生成 docs/knowledge-base/onboarding/01-环境配置.md：
1. 读取 package.json，确定需要安装的依赖（Node.js 版本、npm 版本）
2. 读取 .env.example，列出需要配置的环境变量
3. 读取 README.md，提取项目运行步骤
4. 生成详细的环境配置指南（包含截图位置的提示）

要求：
- 步骤清晰，新人能照着做
- 包含常见问题（如：Node.js 版本不对怎么办）
- 包含验证步骤（确认配置成功）
```

#### Claude Code 生成的示例

```markdown
# 环境配置指南

本指南帮你配置本地开发环境，预计耗时：30-45 分钟。

## 1. 安装 Node.js 和 npm

### 要求
- Node.js: 18.x 或更高
- npm: 9.x 或更高

### 安装步骤

**macOS**:
```bash
# 使用 nvm 安装（推荐）
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.0/install.sh | bash
nvm install 18
nvm use 18
```

**Windows**:
1. 下载 Node.js 安装包：https://nodejs.org/
2. 运行安装程序，一路「下一步」
3. 打开命令提示符，验证安装：
   ```bash
   node -v  # 应该输出 v18.x.x
   npm -v   # 应该输出 9.x.x
   ```

**验证**:
```bash
node -v  # 输出 v18.x.x
npm -v   # 输出 9.x.x
```

### 常见问题

**Q: 提示 "node: command not found"**
A: 说明 Node.js 没装好，重新安装，或重启终端。

**Q: 提示 "npm: permission denied"**
A: 不要用 sudo 装 npm 包！参考：https://docs.npmjs.com/resolving-eacces-permissions-errors

---

## 2. 配置环境变量

### 步骤

1. 复制 `.env.example` 为 `.env`：
   ```bash
   cp .env.example .env
   ```

2. 打开 `.env`，填写必要的变量：
   ```bash
   # 数据库配置
   DATABASE_URL=postgresql://user:password@localhost:5432/myapp
   
   # JWT 密钥（随便写一个字符串）
   JWT_SECRET=your-secret-key-here
   
   # API 地址
   API_BASE_URL=http://localhost:3000
   ```

### 常见问题

**Q: 不知道数据库密码怎么办？**
A: 问你的 mentor，或查看团队密码管理器（1Password）。

---

## 3. 安装项目依赖

```bash
npm install
```

### 验证

```bash
npm run dev  # 应该能启动开发服务器
```

打开 http://localhost:3000，看到登录页面就说明配置成功了！

   - 分支命名规范
   - 提交信息规范
   - PR 流程
   - Code Review 要求
```

## 第三步：让 Claude Code 维护知识库

### 3.1 代码变更时自动更新文档

创建 `.github/workflows/update-docs.yml`：

```yaml
name: 自动更新知识库文档

on:
  push:
    paths:
      - 'package.json'
      - 'src/**'
      - 'README.md'

jobs:
  update-docs:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout code
        uses: actions/checkout@v3

      - name: 设置 Node.js
        uses: actions/setup-node@v3
        with:
          node-version: '18'

      - name: 安装 Claude Code
        run: npm install -g @anthropic-ai/claude-code

      - name: 更新技术栈文档
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        run: |
          # 检查 package.json 是否有变化
          if git diff HEAD~1 HEAD --name-only | grep -q "package.json"; then
            claude "package.json 有更新，同步更新 docs/knowledge-base/tech-stack/ 下的相关文档"
            git add docs/knowledge-base/tech-stack/
            git commit -m "docs: 自动更新技术栈文档（Claude Code）"
            git push origin main
          fi
```

### 3.2 定期审查知识库

```bash
你：每月 1 号，检查知识库文档是否过时：
1. 读取 docs/knowledge-base/ 下所有文档
2. 对比当前代码（package.json、目录结构、配置文件）
3. 列出过时的内容（如：依赖版本不对、目录结构变化）
4. 生成更新建议，保存到 /tmp/docs-update-suggestions.md
```

## 实战案例：新人 onboarding 时间从 2 周缩短到 3 天

### 之前（没有知识库）

新人入职流程：

```
Day 1-2: 配环境（遇到问题问人，但老人很忙）
Day 3-5: 读代码（没人带，自己摸索）
Day 6-10: 做第一个任务（经常卡住，效率低）
```

**痛点**：
- 环境配置靠口口相传
- 代码规范不明确
- 遇到问题不知道找谁

### 之后（有知识库）

新人入职流程：

```
Day 1: 照着 docs/knowledge-base/onboarding/ 配置环境（2 小时）
Day 1: 读技术栈文档和代码规范（4 小时）
Day 2-3: 做一个小任务（有文档参考，遇到问题查 troubleshooting）
```

**效果**：
- onboarding 时间：14 天 → 3 天（节省 79%）
- 新人满意度：6/10 → 9/10
- 老人被问问题次数：大幅减少

- [ ] 技术栈文档是最新的（依赖版本、目录结构）
- [ ] 开发流程文档是最新的（Git 分支模型、CI/CD 流程）
- [ ] 代码规范是最新的（ESLint 规则、命名规范）
- [ ] 常见问题文档是最新的（新问题及时补充）

**建议**：每月安排 1 人负责审查知识库，确保不过时。

## 小结

用 Claude Code 维护团队知识库的价值：

1. **快速搭建**：1 天内生成完整框架和内容
2. **自动更新**：代码变更时自动更新文档
3. **降低沟通成本**：新人自助查阅，老人不被频繁打扰
4. **知识传承**：老人离职时，知识库还在

**记住**：
- 知识库不是"一次性工程"，需要持续维护
- 让 Claude Code 帮你定期审查，发现过时内容
- 鼓励团队成员补充 troubleshooting 文档（遇到问题时记得写下来）
