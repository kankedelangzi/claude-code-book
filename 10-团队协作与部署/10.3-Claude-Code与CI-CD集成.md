# 10.3 Claude Code 与 CI/CD 集成

> 把 Claude Code 集成到 CI/CD 流水线里，实现自动代码审查、自动修复、自动生成文档。

---

## 场景：自动代码审查 + 自动修复

**目标**：每次 PR 提交后，自动：
1. 用 Claude Code 审查代码
2. 如果发现低级错误（代码规范、明显 bug），自动修复
3. 将修复后的代码推送到 PR（作为新 commit）
4. 生成代码审查报告，回复到 PR 评论

---

## 方案 1：GitHub Actions + Claude Code（推荐）

### 完整工作流

创建 `.github/workflows/claude-code-autofix.yml`：

```yaml
name: Claude Code 自动审查 + 自动修复

on:
  pull_request:
    types: [opened, synchronize]

jobs:
  code-review-and-fix:
    runs-on: ubuntu-latest
    permissions:
      contents: write  # 需要写权限来推送修复
      pull-requests: write  # 需要写权限来回复 PR 评论
    
    steps:
      - name: Checkout code
        uses: actions/checkout@v3
        with:
          ref: ${{ github.head_ref }}  # 检出 PR 的分支
          fetch-depth: 0  # 获取完整 git 历史

      - name: 设置 Node.js
        uses: actions/setup-node@v3
        with:
          node-version: '18'

      - name: 安装 Claude Code
        run: npm install -g @anthropic-ai/claude-code

      - name: 运行代码审查
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        run: |
          # 获取 PR 的 diff
          git diff origin/main...HEAD > /tmp/pr-diff.patch
          
          # 让 Claude Code 审查，输出 JSON 格式
          claude --output json "审查以下 PR 改动（保存在 /tmp/pr-diff.patch），找出：
          1. 代码规范问题（缩进、引号、分号）
          2. 明显的低级错误（未使用的变量、缺少 await）
          
          只列出可以自动修复的问题，输出 JSON 格式：
          {
            \"fixable_issues\": [
              {\"file\": \"src/foo.js\", \"line\": 12, \"problem\": \"...\", \"fix\": \"...\"}
            ]
          }
          " > /tmp/review-result.json
          
          echo "审查完成，结果保存在 /tmp/review-result.json"
```

### 自动修复脚本

创建 `.github/scripts/autofix.sh`：

```bash
#!/bin/bash
# 自动修复脚本

# 读取审查结果
REVIEW_RESULT=$(cat /tmp/review-result.json)

# 提取可自动修复的问题
FIXABLE_ISSUES=$(echo "$REVIEW_RESULT" | jq -r '.fixable_issues[] | "\(.file):\(.line) \(.fix)"')

if [ -z "$FIXABLE_ISSUES" ]; then
  echo "没有可自动修复的问题"
  exit 0
fi

echo "发现 $(echo "$FIXABLE_ISSUES" | wc -l) 个可自动修复的问题"

# 让 Claude Code 自动修复
claude "根据以下列表，自动修复代码：
$FIXABLE_ISSUES

要求：
1. 只修复列出的问题
2. 不要改变代码逻辑
3. 修复后运行 lint 检查
"

# 如果修复成功，提交并推送
if [ $? -eq 0 ]; then
  git config user.name "Claude Code Bot"
  git config user.email "claude-bot@example.com"
  git add .
  git commit -m "fix: 自动修复代码规范问题（Claude Code）"
  git push origin ${{ github.head_ref }}
  echo "✅ 自动修复完成，已推送到 PR"
else
  echo "❌ 自动修复失败，需要人工介入"
  exit 1
fi
```

### 生成审查报告

在 GitHub Actions 工作流里添加：

```yaml
      - name: 生成审查报告并回复到 PR
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        run: |
          # 让 Claude Code 生成审查报告（Markdown 格式）
          claude "根据 /tmp/pr-diff.patch 生成代码审查报告（Markdown 格式）：
          
          ## 代码规范问题
          ## 逻辑错误
          ## 安全隐患
          ## 性能问题
          
          按严重程度排序：🔴>⚠️>❌
          " > /tmp/review-report.md
          
          # 回复到 PR 评论
          gh pr comment ${{ github.event.number }} --body-file /tmp/review-report.md
          
          echo "✅ 审查报告已回复到 PR #${{ github.event.number }}"
```

## 方案 2：GitLab CI + Claude Code

### 配置 .gitlab-ci.yml

```yaml
stages:
  - code-review

claude-code-review:
  stage: code-review
  image: node:18
  script:
    - npm install -g @anthropic-ai/claude-code
    - |
      # 获取 MR 的 diff
      git diff origin/main...HEAD > /tmp/mr-diff.patch
      
      # 运行 Claude Code 审查
      claude --output json "审查 /tmp/mr-diff.patch，输出 JSON 格式的结果" > /tmp/review-result.json
      
      # 生成 Markdown 报告
      claude "根据 /tmp/review-result.json 生成 Markdown 审查报告" > /tmp/review-report.md
      
      # 将报告回复到 MR 评论（需要 GitLab API）
      curl -X POST \
        -H "PRIVATE-TOKEN: $GITLAB_TOKEN" \
        -d "body=$(cat /tmp/review-report.md)" \
        "$CI_API_V4_URL/projects/$CI_PROJECT_ID/merge_requests/$CI_MERGE_REQUEST_IID/notes"
  only:
    - merge_requests
```

## 方案 3：Jenkins Pipeline + Claude Code

### Jenkinsfile

```groovy
pipeline {
    agent any
    
    environment {
        ANTHROPIC_API_KEY = credentials('anthropic-api-key')
    }
    
    stages {
        stage('Checkout') {
            steps {
                checkout scm
            }
        }
        
        stage('Code Review with Claude Code') {
            steps {
                script {
                    // 获取 PR 的 diff
                    sh 'git diff origin/main...HEAD > /tmp/pr-diff.patch'
                    
                    // 运行 Claude Code 审查
                    sh '''
                        claude "审查 /tmp/pr-diff.patch，生成 Markdown 报告" > /tmp/review-report.md
                    '''
                    
                    // 将报告存档
                    archiveArtifacts artifacts: '/tmp/review-report.md', fingerprint: true
                    
                    // 回复到 PR（需要 GitHub API 插件）
                    pullRequest.comment('请查看附件的代码审查报告')
                }
            }
        }
    }
}
```

## 实战案例：自动修复代码规范问题

### PR 提交前

```javascript
// src/components/UserList.jsx
function UserList({users}) {
  return (
    <ul>
      {users.map(user => {
        return <li>{user.name}</li>  // ❌ 缺少 key prop
      })}
    </ul>
  )
}

export default UserList
```

### PR 提交后，GitHub Actions 自动运行

**Claude Code 审查结果**：

```json
{
  "fixable_issues": [
    {
      "file": "src/components/UserList.jsx",
      "line": 5,
      "problem": "列表渲染缺少 key prop",
      "fix": "改成 <li key={user.id}>{user.name}</li>"
    }
  ]
}
```

**自动修复后的代码**：

```javascript
// src/components/UserList.jsx
function UserList({users}) {
  return (
    <ul>
      {users.map(user => {
        return <li key={user.id}>{user.name}</li>  // ✅ 已修复
      })}
    </ul>
  )
}

export default UserList
```

**自动推送新 commit 到 PR**：

```
Commit: fix: 自动修复代码规范问题（Claude Code）
Author: Claude Code Bot <claude-bot@example.com>
Date: 2026-05-17

- 修复 src/components/UserList.jsx 缺少 key prop 的问题
```

**PR 评论里的审查报告**：

```markdown
## Claude Code 代码审查报告

### ❌ 代码规范问题（已自动修复）

1. **src/components/UserList.jsx:5**
   - 问题：列表渲染缺少 key prop
   - 修复：已自动添加 `key={user.id}`

### ✅ 其他检查通过

- 没有发现安全漏洞
- 没有发现明显的逻辑错误
- 没有发现性能问题

---
> 我是 Claude Code 自动审查机器人 🤖。已自动修复低级错误，请专注于业务逻辑审查。
```

## 注意事项

### 1. 安全第一

**不要**把敏感信息发给 Claude Code：

```yaml
# ❌ 错误做法
env:
  ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
  DATABASE_URL: ${{ secrets.DATABASE_URL }}  # ❌ 不要传给 Claude Code！
```

**正确做法**：只传必要的环境变量

```yaml
env:
  ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
  # 不要传其他敏感信息
```

### 2. 限定自动修复的范围

**只自动修复低级问题**（代码规范、明显 bug），**不要自动修复**业务逻辑问题。

```javascript
// ✅ 可以自动修复
"修复代码规范问题（缩进、引号、分号）"

// ❌ 不要自动修复
"根据审查报告自动修复所有问题"  // 可能改坏业务逻辑
```

### 3. 人工审核自动修复的 commit

即使 Claude Code 自动修复了问题，也要在合并前人工审核：

```bash
# PR 里会有两个 commit
* fix: 自动修复代码规范问题（Claude Code）  # ← 需要审核
* feat: 添加用户列表组件                              # ← 原始功能
```

## 小结

把 Claude Code 集成到 CI/CD 流水线里，可以实现：

1. **自动代码审查**：每次 PR 提交后自动运行
2. **自动修复低级问题**：代码规范、明显 bug
3. **生成审查报告**：帮助人类审查者专注于业务逻辑

**记住**：
- 只自动修复低级问题，不要动业务逻辑
- 安全第一，不要泄露敏感信息
- 自动修复后，人工审核再合并
