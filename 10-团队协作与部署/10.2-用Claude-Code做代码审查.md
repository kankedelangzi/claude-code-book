# 10.2 用 Claude Code 做代码审查

> 代码审查（Code Review）是保证代码质量的关键环节。Claude Code 可以帮你做第一轮审查，过滤掉低级错误，让人类审查者专注于业务逻辑和架构设计。

---

## 场景：PR 提交后的自动代码审查

**背景**：每次 PR 提交后，让 Claude Code 先做第一轮审查，自动发现：
- 代码规范问题
- 明显的逻辑错误
- 安全隐患
- 性能问题

人类审查者只需要关注业务逻辑和架构设计。

---

## 工作流设计

### 流程

```
开发者提交 PR
    ↓
Claude Code 自动审查（GitHub Actions / 手动触发）
    ↓
生成代码审查报告，回复到 PR 评论里
    ↓
开发者根据报告修复问题
    ↓
人类审查者审查（重点关注业务逻辑和架构）
    ↓
合并 PR
```

---

## 方法 1：手动审查（适合小团队）

### 步骤

**第 1 步：PR 提交后，让 Claude Code 审查**

```bash
# 假设你刚提交了 PR #42
你：审查 PR #42 的代码（git diff main...feature/user-refactor）
Claude Code：
我来分析这个 PR 的改动（共 15 个文件，+523 行，-412 行）

## 代码规范问题

❌ src/services/user-service.js:45
未使用 async/await，建议使用 async/await 替代回调函数

❌ src/components/UserList.jsx:12
缺少 key prop，可能导致渲染问题

## 逻辑问题

⚠️ src/services/user-service.js:78
如果 `user` 为 `null`，`user.name` 会报错，建议加空值检查

## 安全隐患

🔴 src/controllers/auth-controller.js:23
密码比较使用 `==` 而不是 `===`，可能导致类型转换漏洞

## 性能问题

⚠️ src/services/order-service.js:102
在循环内调用数据库查询，可能导致 N+1 问题

---
建议先修复标记为 🔴 和 ⚠️ 的问题，❌ 的问题可以在合并后修复。
```

**第 2 步：根据报告修复问题**

```bash
你：修复 Claude Code 报告的问题：
1. 把 src/services/user-service.js 的回调函数改成 async/await
2. 给 UserList.jsx 的列表项加 key prop
3. 在 auth-controller.js 里把 `==` 改成 `===`
4. 给 user-service.js:78 加空值检查

Claude Code：[生成修复代码]
你：[审核代码，运行测试，提交修复]
```

**第 3 步：请求人类审查者审查**

人类审查者只需要关注：
- 业务逻辑是否正确
- 架构设计是否合理
- 有没有更好的实现方案

## 方法 2：GitHub Actions 自动审查（适合中大型团队）

### 配置 GitHub Actions

创建 `.github/workflows/claude-code-review.yml`：

```yaml
name: Claude Code 代码审查

on:
  pull_request:
    types: [opened, synchronize]

jobs:
  code-review:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout code
        uses: actions/checkout@v3
        with:
          fetch-depth: 0  # 获取完整 git 历史

      - name: 设置 Node.js
        uses: actions/setup-node@v3
        with:
          node-version: '18'

      - name: 安装 Claude Code
        run: npm install -g @anthropic-ai/claude-code

      - name: 运行代码审查
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        run: |
          # 获取 PR 的 diff
          git diff origin/main...HEAD > /tmp/pr-diff.patch
          
          # 让 Claude Code 审查
          claude "审查以下 PR 改动（保存在 /tmp/pr-diff.patch）：
          1. 代码规范问题
          2. 逻辑错误
          3. 安全隐患
          4. 性能问题
          
          输出格式：Markdown，按问题严重程度排序（🔴>⚠️>❌）
          " > /tmp/review-report.md
          
          # 将审查报告回复到 PR 评论
          gh pr comment ${{ github.event.number }} --body-file /tmp/review-report.md
```

### 效果

每次 PR 提交后，GitHub Actions 会自动：
1.  checkout 代码
2.  运行 Claude Code 审查
3.  将审查报告回复到 PR 评论里

**示例 PR 评论**：

```markdown
## Claude Code 代码审查报告

### 🔴 安全问题（必须修复）

1. **src/controllers/auth-controller.js:23**
   ```javascript
   if (password == storedPassword) {  // ❌ 应该用 ===
   ```
   **修复建议**：改成 `if (password === storedPassword)`

### ⚠️ 逻辑问题（建议修复）

1. **src/services/user-service.js:78**
   ```javascript
   const name = user.name;  // ❌ 如果 user 为 null 会报错
   ```
   **修复建议**：改成 `const name = user?.name || 'Unknown';`

### ❌ 代码规范（可延后修复）

1. **src/components/UserList.jsx:12**
   ```jsx
   {users.map(user => <li>{user.name}</li>)}  // ❌ 缺少 key
   ```
   **修复建议**：改成 `<li key={user.id}>{user.name}</li>`

---
> 我是 Claude Code 自动审查机器人 🤖。请根据报告修复问题，人类审查者会重点审查业务逻辑和架构设计。
```

## 审查重点：Claude Code 擅长什么？不擅长什么？

### Claude Code 擅长

| 审查类型 | 示例 | 准确率 |
|----------|------|--------|
| 代码规范 | 缩进、引号、分号、命名规范 | ⭐⭐⭐⭐⭐ |
| 常见逻辑错误 | 空值未检查、数组越界、类型错误 | ⭐⭐⭐⭐ |
| 安全隐患 | SQL 注入、XSS、密码比较用 `==` | ⭐⭐⭐⭐ |
| 性能问题 | N+1 查询、循环内调用数据库、未使用缓存 | ⭐⭐⭐ |
| 测试覆盖 | 缺少测试用例、测试用例覆盖不完整 | ⭐⭐⭐⭐ |

### Claude Code 不擅长（需要人类审查者）

| 审查类型 | 原因 |
|----------|------|
| 业务逻辑 | AI 不理解你的业务需求 |
| 架构设计 | AI 不知道你的技术栈演进方向 |
| 代码可读性 | AI 认为"能跑就行"，人类关注可维护性 |
| 边界情况 | AI 可能漏掉一些 corner case |

## 实战案例：审查一个真实的 PR

### PR 信息

- **标题**：feat: 添加用户导出功能
- **改动**：8 个文件，+312 行，-45 行
- **功能**：导出用户列表为 Excel

### 让 Claude Code 审查

```bash
你：审查这个 PR（git diff main...feature/user-export）
重点关注：
1. 有没有 SQL 注入风险
2. 有没有性能问题（数据量大时）
3. 错误处理是否完整
```

### Claude Code 的审查报告

```markdown
## 代码审查报告

### 🔴 安全问题（必须修复）

1. **src/services/export-service.js:34**
   ```javascript
   const query = `SELECT * FROM users WHERE name = '${name}'`;  // ❌ SQL 注入风险
   ```
   **修复建议**：使用参数化查询
   ```javascript
   const query = 'SELECT * FROM users WHERE name = $1';
   const result = await db.query(query, [name]);
   ```

### ⚠️ 性能问题（建议修复）

1. **src/services/export-service.js:56**
   ```javascript
   const users = await User.findAll();  // ❌ 如果数据量大会内存溢出
   ```
   **修复建议**：使用流式导出
   ```javascript
   const stream = User.findAll().cursor();
   // 流式写入 Excel
   ```

### ❌ 错误处理不完整

1. **src/controllers/export-controller.js:23**
   ```javascript
   const result = await exportService.exportUsers();
   res.download(result.filePath);  // ❌ 如果导出失败会报错
   ```
   **修复建议**：加 try-catch
   ```javascript
   try {
     const result = await exportService.exportUsers();
     res.download(result.filePath);
   } catch (error) {
     res.status(500).json({ error: '导出失败' });
   }
   ```

### ✅ 代码规范检查通过

- 缩进：✅ 2 空格
- 引号：✅ 单引号
- 分号：✅ 有分号
- 命名：✅ 驼峰命名

---
**总结**：发现了 1 个安全问题和 2 个性能/健壮性问题，建议修复后再合并。
```

### 开发者修复后

```bash
你：根据审查报告修复问题：
1. 把 SQL 查询改成参数化查询
2. 改成流式导出
3. 加 try-catch

Claude Code：[生成修复代码]
你：[审核代码，运行测试，提交修复]
```

### 人类审查者审查

人类审查者只需要看：
1. 业务逻辑是否正确（导出字段是否完整？）
2. 架构设计是否合理（要不要拆成微服务？）
3. 有没有更好的实现方案（要不要改用消息队列异步导出？）

---

## 小结

用 Claude Code 做代码审查的价值：

1. **提高审查效率**：过滤低级错误，人类审查者只需要关注核心问题
2. **统一审查标准**：Claude Code 不会"心情不好"或"赶时间"而漏掉问题
3. **知识传承**：新同事可以从 Claude Code 的审查报告中学习最佳实践

**记住**：
- Claude Code 擅长代码规范、常见错误、安全隐患
- Claude Code 不擅长业务逻辑、架构设计
- 最佳流程：Claude Code 做第一轮审查 → 人类审查者做第二轮审查
