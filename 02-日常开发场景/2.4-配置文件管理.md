# 2.4 配置文件管理

## 场景描述

每个项目都有配置文件：数据库连接、API 密钥、环境变量……

但管理这些配置很头疼：
- 本地、测试、生产环境配置不同
- 敏感信息不能提交到 Git
- 配置项散落各处，难以维护

**Claude Code 可以帮你生成结构清晰的配置管理系统。**

---

## 案例：多环境配置管理

我们要为一个 Node.js 项目搭建配置管理系统，支持：
- 多环境（development、test、production）
- 敏感信息用环境变量
- 配置验证（防止遗漏必填项）
- 配置文件模板（方便团队协作）

---

## 第一步：生成配置管理骨架

**提示词：**

```
在当前目录创建一个配置管理系统：
- 技术栈：Node.js + dotenv
- 支持环境：development、test、production
- 配置项：数据库、Redis、第三方 API、日志级别

**Claude Code 会生成：**

```

## 核心代码解析

### config/default.js（默认配置）

```javascript
module.exports = {
  // 服务器配置
  server: {
    port: process.env.PORT || 3000,
    host: process.env.HOST || 'localhost'
  },
  
  // 数据库配置
  database: {
    host: process.env.DB_HOST || 'localhost',
    port: process.env.DB_PORT || 5432,
    name: process.env.DB_NAME || 'myapp_dev',
    user: process.env.DB_USER || 'postgres',
    password: process.env.DB_PASSWORD,
    pool: {
      max: 10,
      min: 2
    }
  },
  
  // Redis 配置
  redis: {
    host: process.env.REDIS_HOST || 'localhost',
    port: process.env.REDIS_PORT || 6379,
    password: process.env.REDIS_PASSWORD
  },
  
  // 第三方 API
  api: {
    openai: {
      key: process.env.OPENAI_API_KEY,
      baseUrl: process.env.OPENAI_BASE_URL || 'https://api.openai.com/v1'
    },
    stripe: {
      secretKey: process.env.STRIPE_SECRET_KEY,
      webhookSecret: process.env.STRIPE_WEBHOOK_SECRET
    }
  },
  
  // 日志配置
  logging: {
    level: process.env.LOG_LEVEL || 'info',
    format: process.env.LOG_FORMAT || 'combined'
  },
  
  // 安全配置
  security: {
    jwtSecret: process.env.JWT_SECRET,
    corsOrigin: process.env.CORS_ORIGIN || '*'
  }
};
```

### config/index.js（配置入口）

```javascript
const _ = require('lodash');
const defaultConfig = require('./default');
const validator = require('./validator');

// 根据 NODE_ENV 加载对应环境的配置
const env = process.env.NODE_ENV || 'development';
let envConfig = {};

try {
  envConfig = require(`./${env}`);
} catch (err) {
  console.warn(`No config found for environment: ${env}, using default`);
}

// 深度合并配置（环境变量覆盖配置文件）
const config = _.merge({}, defaultConfig, envConfig);

// 验证配置
const errors = validator(config);
if (errors.length > 0) {
  console.error('❌ Configuration validation failed:');
  errors.forEach(err => console.error(`  - ${err}`));
  process.exit(1);
}

module.exports = config;
```

---

### config/validator.js（配置验证）

```javascript
const validate = (config) => {
  const errors = [];
  
  // 验证数据库配置
  if (!config.database.host) {
    errors.push('Database host is required');
  }
  if (!config.database.name) {
    errors.push('Database name is required');
  }
  if (!config.database.user) {
    errors.push('Database user is required');
  }
  if (!config.database.password && process.env.NODE_ENV === 'production') {
    errors.push('Database password is required in production');
  }
  
  // 验证 Redis 配置
  if (!config.redis.host) {
    errors.push('Redis host is required');
  }
  
  // 验证第三方 API
  if (!config.api.openai.key && process.env.NODE_ENV === 'production') {
    errors.push('OpenAI API key is required in production');
  }
  if (!config.api.stripe.secretKey && process.env.NODE_ENV === 'production') {
    errors.push('Stripe secret key is required in production');
  }
  
  // 验证安全配置
  if (!config.security.jwtSecret) {
    errors.push('JWT secret is required');
  }
  
  return errors;
};

module.exports = validate;
```

## 使用方法

### 1. 安装依赖

```bash
npm install dotenv lodash
```

### 2. 复制环境变量模板

```bash
cp .env.example .env.development
# 编辑 .env.development，填入你的本地配置
```

### 3. 在代码中使用配置

```javascript
const config = require('./config');

// 启动服务器
app.listen(config.server.port, () => {
  console.log(`Server running on port ${config.server.port}`);
});

// 连接数据库
const db = await pg.connect({
  host: config.database.host,
  port: config.database.port,
  database: config.database.name,
  user: config.database.user,
  password: config.database.password
});

// 调用第三方 API
const response = await axios.post(
  `${config.api.openai.baseUrl}/chat/completions`,
  { model: 'gpt-4', messages: [...] },
  { headers: { Authorization: `Bearer ${config.api.openai.key}` } }
);
```

## 最佳实践

### 1. 永远不要把敏感信息提交到 Git

❌ **错误做法：**
```javascript
// config.js
module.exports = {
  database: {
    password: 'mysecretpassword' // ❌ 密码泄露！
  }
};
```

✅ **正确做法：**
```javascript
// config.js
module.exports = {
  database: {
    password: process.env.DB_PASSWORD // ✅ 从环境变量读取
  }
};
```

---

### 2. 提供 .env.example 模板

让团队成员知道需要哪些环境变量，但**不要填入真实值**。

---

### 3. 配置验证要在启动时做

```javascript
// 应用启动时立即验证配置
const config = require('./config');
console.log('✅ Configuration loaded successfully');
```

如果配置缺失，应用应该**立即崩溃**，而不是在运行时才报错。

---

### 4. 用 lodash.merge 深度合并配置

```javascript
const _ = require('lodash');

const defaultConfig = { a: { b: 1, c: 2 } };
const envConfig = { a: { b: 99 } };

const finalConfig = _.merge({}, defaultConfig, envConfig);
// { a: { b: 99, c: 2 } } ✅ 深度合并
```

---

## 关键要点

1. **敏感信息用环境变量**：永远不要硬编码密码和 API 密钥
2. **多环境配置分离**：development、test、production 各自独立
3. **配置验证不可少**：启动时检查，避免运行时报错
4. **提供 .env.example**：让团队知道需要哪些配置
5. **.gitignore 要完善**：防止敏感文件泄露
