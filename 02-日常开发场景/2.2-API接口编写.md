# 2.2 API 接口编写

## 场景描述

用 Claude Code 快速编写**规范、可维护、生产级**的 API 接口。本章案例：在 2.1 原型基础上，升级成一个完整的**待办事项 API**（加入参数校验、错误处理、日志记录）。

---

## 核心目标

- **参数校验**：防止脏数据进入系统
- **错误处理**：统一的错误响应格式
- **日志记录**：方便调试和监控
- **代码规范**：分层清晰，易于维护

### 第三步：核心代码解读

#### 1. 参数校验中间件（`middlewares/validator.js`）

```javascript
const { validationResult } = require('express-validator');

const validate = (validations) => {
  return async (req, res, next) => {
    await Promise.all(validations.map(validation => validation.run(req)));

    const errors = validationResult(req);
    if (errors.isEmpty()) {
      return next();
    }

    return res.status(400).json({
      success: false,
      errors: errors.array().map(err => ({
        field: err.param,
        message: err.msg
      }))
    });
  };
};

module.exports = validate;
```

**使用方式**（在路由中）：

```javascript
const { body, param } = require('express-validator');
const validate = require('../middlewares/validator');

router.post('/', 
  [
    body('title').notEmpty().withMessage('标题不能为空'),
    body('title').isLength({ min: 1, max: 200 }).withMessage('标题长度 1-200 字符'),
    body('description').optional().isString().withMessage('描述必须是字符串')
  ],
  validate,  // ← 参数校验中间件
  todoController.create
);
```

**好处**：
- 校验逻辑集中管理，不散落在 controller 里
- 错误信息格式统一，前端好处理

---

#### 2. 错误处理中间件（`middlewares/errorHandler.js`）

```javascript
const logger = require('../utils/logger');

const errorHandler = (err, req, res, next) => {
  logger.error('Error occurred', {
    message: err.message,
    stack: err.stack,
    path: req.path,
    method: req.method
  });

  const statusCode = err.statusCode || 500;
  const message = err.message || '服务器内部错误';

  res.status(statusCode).json({
    success: false,
    error: {
      message,
      ...(process.env.NODE_ENV === 'development' && { stack: err.stack })
    }
  });
};

module.exports = errorHandler;
```

**使用方式**（在 `server.js` 中）：

```javascript
const errorHandler = require('./middlewares/errorHandler');

// 所有路由之后，注册错误处理中间件
app.use(errorHandler);
```

**好处**：
- 所有错误统一处理，不会漏掉
- 开发环境返回 stack trace，生产环境隐藏细节

#### 3. 日志记录（`utils/logger.js`）

```javascript
const winston = require('winston');
const path = require('path');

const logger = winston.createLogger({
  level: 'info',
  format: winston.format.combine(
    winston.format.timestamp({ format: 'YYYY-MM-DD HH:mm:ss' }),
    winston.format.errors({ stack: true }),
    winston.format.json()
  ),
  transports: [
    new winston.transports.File({ filename: path.join(__dirname, '../logs/error.log'), level: 'error' }),
    new winston.transports.File({ filename: path.join(__dirname, '../logs/combined.log') })
  ]
});

// 开发环境同时在控制台输出
if (process.env.NODE_ENV !== 'production') {
  logger.add(new winston.transports.Console({
    format: winston.format.simple()
  }));
}

module.exports = logger;
```

**使用方式**：

```javascript
const logger = require('../utils/logger');

logger.info('待办事项创建成功', { id: newTodo.id, title: newTodo.title });
logger.error('数据库连接失败', { error: err.message });
```

#### 4. Controller 层（`controllers/todoController.js`）

```javascript
const todoService = require('../services/todoService');
const logger = require('../utils/logger');

const create = async (req, res, next) => {
  try {
    const { title, description } = req.body;
    const newTodo = await todoService.create({ title, description });
    
    logger.info('待办事项创建成功', { id: newTodo.id });
    res.status(201).json({ success: true, data: newTodo });
  } catch (error) {
    next(error);  // ← 交给错误处理中间件
  }
};

const getAll = async (req, res, next) => {
  try {
    const todos = await todoService.getAll();
    res.json({ success: true, data: todos });
  } catch (error) {
    next(error);
  }
};

const getById = async (req, res, next) => {
  try {
    const todo = await todoService.getById(req.params.id);
    if (!todo) {
      return res.status(404).json({ success: false, error: '待办事项不存在' });
    }
    res.json({ success: true, data: todo });
  } catch (error) {
    next(error);
  }
};

const update = async (req, res, next) => {
  try {
    const { title, description, completed } = req.body;
    const updated = await todoService.update(req.params.id, { title, description, completed });
    
    if (!updated) {
      return res.status(404).json({ success: false, error: '待办事项不存在' });
    }
    
    logger.info('待办事项更新成功', { id: req.params.id });
    res.json({ success: true, data: updated });
  } catch (error) {
    next(error);
  }
};

const remove = async (req, res, next) => {
  try {
    const deleted = await todoService.remove(req.params.id);
    
    if (!deleted) {
      return res.status(404).json({ success: false, error: '待办事项不存在' });
    }
    
    logger.info('待办事项删除成功', { id: req.params.id });
    res.json({ success: true, message: '删除成功' });
  } catch (error) {
    next(error);
  }
};

module.exports = { create, getAll, getById, update, remove };
```

**关键点**：
- Controller 只处理请求和响应，业务逻辑交给 Service
- 用 `try-catch` 捕获异常，交给 `next(error)` 统一处理

---

#### 5. Service 层（`services/todoService.js`）

```javascript
const todoStore = require('../data/store');
const logger = require('../utils/logger');

const create = async ({ title, description }) => {
  const newTodo = todoStore.create({ title, description });
  return newTodo;
};

const getAll = async () => {
  return todoStore.getAll();
};

const getById = async (id) => {
  return todoStore.getById(id);
};

const update = async (id, updates) => {
  const updated = todoStore.update(id, updates);
  return updated;
};

const remove = async (id) => {
  const deleted = todoStore.remove(id);
  return deleted;
};

module.exports = { create, getAll, getById, update, remove };
```

**好处**：
- 业务逻辑独立，方便单元测试
- 后续换数据库只需修改 Store 层，不影响 Service 和 Controller

## 核心技巧

### 1. 让 Claude Code 按"分层架构"生成代码

❌ **不好**：所有代码写在一个文件里（controller、service、数据操作混在一起）
✅ **好**：明确告诉 Claude Code 你要分层架构

```
请用分层架构重构代码：
- Controller：处理 HTTP 请求和响应
- Service：业务逻辑
- Data：数据存储
```

---

### 2. 参数校验用现成库，别手写

❌ **不好**：
```javascript
if (!req.body.title || req.body.title.length > 200) {
  return res.status(400).json({ error: '标题不合法' });
}
```

✅ **好**：用 `express-validator` 或 `Joi`，声明式校验

```javascript
const { body } = require('express-validator');
body('title').notEmpty().isLength({ min: 1, max: 200 })
```

**让 Claude Code 帮你生成校验规则**，你只需说需求。

---

### 3. 错误处理要"统一"，别散落各处

❌ **不好**：每个路由里都写一遍错误处理
✅ **好**：用错误处理中间件统一捕获

**让 Claude Code 生成**：
```
帮我写一个错误处理中间件，要求：
1. 捕获所有异常
2. 记录日志（包含请求路径、错误信息、stack trace）
3. 返回统一的 JSON 格式
```

---

### 4. 日志记录用 winston，别用 console.log

❌ **不好**：`console.log('创建成功')`
✅ **好**：`logger.info('创建成功', { id: newTodo.id })`

**好处**：
- 日志可以输出到文件（按日期轮转）
- 生产环境可以关掉控制台输出
- 可以区分日志级别（info / warn / error）

## 常见问题

### Q1：Claude Code 生成的分层架构太复杂，有没有更简单的？

有！你可以说：

```
我不需要这么复杂的分层，只用 controller 和 route 两层就够了。
```

Claude Code 会简化架构，适合小项目。

---

### Q2：如何让 Claude Code 生成单元测试？

直接说：

```
请为 todoController 生成单元测试（用 Jest），覆盖：
1. 创建待办事项（成功/失败）
2. 获取待办事项（存在/不存在）
3. 更新待办事项
4. 删除待办事项
```

Claude Code 会生成 `todoController.test.js`，包含 mock service 的代码。

---

### Q3：参数校验规则写错了怎么办？

把错误信息发给 Claude Code：

```
运行的时候报错了：

Error: Invalid validation rule

这是我的校验代码：

[粘贴代码]

请帮我修复。
```

## 小结

- **分层架构**：Controller → Service → Data，职责清晰
- **参数校验**：用 express-validator 或 Joi，声明式校验
- **错误处理**：统一中间件捕获，返回规范格式
- **日志记录**：用 winston，方便调试和监控
- **API 文档**：用 Swagger 自动生成
