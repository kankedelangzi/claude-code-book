# 2.6 代码审查与质量保证

## 场景描述

代码写完了，但质量如何？
- 有没有 bug？
- 性能有没有问题？
- 是否符合团队规范？
- 测试覆盖够不够？

**Claude Code 可以帮你做自动化代码审查，提升代码质量。**

---

## 案例：自动化代码审查流程

我们要为项目搭建自动化代码审查流程，包括：
- 静态代码分析（ESLint、Prettier）
- 代码复杂度检查（圈复杂度）
- 安全漏洞扫描（npm audit、Snyk）
- 测试覆盖率检查
- 用 Claude Code 做 AI 代码审查

## 核心配置文件解析

### .eslintrc.js（ESLint 配置）

```javascript
module.exports = {
  env: {
    node: true,
    es2021: true,
    jest: true
  },
  extends: [
    'eslint:recommended',
    'plugin:security/recommended',
    'prettier' // 必须放在最后，避免冲突
  ],
  parserOptions: {
    ecmaVersion: 2021,
    sourceType: 'module'
  },
  rules: {
    // 自定义规则
    'no-console': ['warn', { allow: ['warn', 'error'] }],
    'no-unused-vars': ['error', { argsIgnorePattern: '^_' }],
    'complexity': ['error', { max: 10 }], // 圈复杂度 ≤ 10
    'security/detect-object-injection': 'error',
    'security/detect-non-literal-fs-filename': 'error'
  },
  plugins: ['security']
};
```

### .github/workflows/code-review.yml（CI/CD）

```yaml
name: Code Review

on: [push, pull_request]

jobs:
  review:
    runs-on: ubuntu-latest
    
    steps:
      - uses: actions/checkout@v3
      
      - name: Setup Node.js
        uses: actions/setup-node@v3
        with:
          node-version: '18'
      
      - name: Install dependencies
        run: npm ci
      
      - name: Run ESLint
        run: npm run lint
      
      - name: Run tests with coverage
        run: npm test -- --coverage
      
      - name: Check coverage threshold
        run: |
          if [ $(jq '.total.lines.pct' coverage/coverage-summary.json) -lt 80 ]; then
            echo "❌ Test coverage is below 80%"
            exit 1
          fi
      
      - name: AI Code Review (Claude Code)
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        run: |
          # 获取本次变更的文件
          files=$(git diff --name-only ${{ github.event.before }} ${{ github.sha }} | grep '\.js$' || true)
          
          if [ -n "$files" ]; then
            echo "$files" | while read file; do
              echo "🤖 AI Reviewing: $file"
              
              # 用 Claude Code 分析代码质量
              claude -p "请审查以下代码：
              - 检查是否有 bug
              - 检查性能问题
              - 检查安全漏洞
              - 给出改进建议
              
              文件: $file
              $(cat $file)
              " || true
            done
          fi
```

## 质量检查清单

### ✅ 代码风格

```bash
# 运行 ESLint 和 Prettier
npm run lint
npm run format:check
```

```
检查代码风格是否一致：
- 引号（单引号 vs 双引号）
- 分号（有 vs 无）

- 尾逗号（有 vs 无）
```

---

### ✅ 测试覆盖率

```bash
# 运行测试并生成覆盖率报告
npm test -- --coverage
```

**Claude Code 提示词：**

```
检查测试覆盖率：
1. 找出未测试的代码路径
2. 生成测试用例模板
3. 给出 Mock 数据建议
```

---

### ✅ 安全漏洞

```bash
# 扫描依赖漏洞
```

## 自动化工作流程

### 1. 开发阶段

```bash
# 写代码
vim src/services/payment.js

# 保存时自动格式化（VS Code + Prettier 插件）

# 提交前自动检查（Husky + lint-staged）
git add .
git commit -m "feat: add payment service"
# 自动触发：ESLint + Prettier + Jest
```

---

### 2. CI/CD 阶段

```bash
# 推送代码到 GitHub/Gitee
git push origin main

# 自动触发 GitHub Actions：
# 1. 运行 ESLint
# 2. 运行 Jest + 覆盖率检查
# 3. AI 代码审查（Claude Code）
# 4. 如果失败，阻止合并
```

---

### 3. Code Review 阶段

```bash
# 创建 Pull Request
# 审查者查看：
# - CI/CD 报告（ESLint、测试、覆盖率）
# - AI 审查报告（Claude Code 的建议）
# - 人工审查（重点看业务逻辑）
```

---

## 关键要点

1. **自动化检查**：ESLint + Prettier + Jest，提交前自动运行
2. **AI 辅助审查**：Claude Code 找出潜在 bug 和安全漏洞
3. **覆盖率要求**：测试覆盖率 ≥ 80%
4. **CI/CD 集成**：推送代码后自动运行所有检查
5. **人工审查**：AI 审查 + 人工审查双保险
