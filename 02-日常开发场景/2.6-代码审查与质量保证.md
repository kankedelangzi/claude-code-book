# 2.6 代码审查与质量保证

> 让Claude Code帮你做代码审查，提高代码质量，减少bug。

## 🎯 场景描述

你写完了一段代码，但不确定：
- 是否有潜在的bug？
- 性能是否有问题？
- 是否符合最佳实践？
- 是否有安全隐患？

**Claude Code可以帮你做全面的代码审查，就像有一个资深开发者在帮你review代码。**

## ✨ 经典代码审查场景

### 场景1：全面代码审查

**审查指令：**

```
请审查这个文件 [文件路径]，检查以下问题：
1. 潜在的bug和边界情况
2. 性能问题
3. 安全漏洞
4. 代码质量和可维护性
5. 是否符合最佳实践

给出具体的改进建议和代码示例。
```

**Claude Code会做什么：**
- 分析代码逻辑，找出潜在问题
- 检查性能瓶颈
- 识别常见安全漏洞（如SQL注入、XSS等）
- 评估代码可读性和可维护性
- 提供具体的修复建议

### 场景2：安全审查

**审查指令：**

```
检查这个文件 [文件路径] 的安全问题：
- SQL注入
- XSS攻击
- 身份验证和授权问题
- 数据验证和净化
- 敏感信息泄露

对每个问题给出修复方案。
```

**Claude Code会做什么：**
- 识别常见安全漏洞
- 提供具体的攻击场景
- 给出安全的代码示例
- 建议安全最佳实践

### 场景3：性能审查

**审查指令：**

```
分析这个代码 [文件路径] 的性能问题：
- 时间复杂度和空间复杂度
- 数据库查询优化
- 内存使用优化
- 并发性能问题

给出优化建议和重构方案。
```

**Claude Code会做什么：**
- 分析算法复杂度
- 识别性能瓶颈
- 提供优化方案
- 给出性能对比

## 🔥 实战Prompt模板

### 模板1：请求全面代码审查

```
请审查以下代码，给出详细报告：

[粘贴代码或指定文件路径]

审查重点：
1. 代码质量和可维护性
2. 潜在bug和边界情况
3. 性能问题
4. 安全漏洞
5. 最佳实践遵循情况

对每个问题给出：
- 问题描述
- 严重程度（高/中/低）
- 修复建议
- 代码示例
```

### 模板2：专注特定问题审查

```
审查这个文件的 [特定问题，如"错误处理"、"内存管理"、"并发安全"]：

[文件路径]

只关注这个问题，深入分析：
- 当前实现的问题
- 可能的后果
- 改进方案
- 重构示例
```

### 模板3：对比审查

```
我有两个版本的代码实现，请对比分析：

版本1：[代码或文件路径]
版本2：[代码或文件路径]

对比维度：
1. 代码质量
2. 性能
3. 可维护性
4. 安全性

给出推荐方案和理由。
```

## 🚀 质量保证工作流

```
1. 代码完成
   ├── 功能实现完成
   └── 基本测试通过

2. 自动审查
   ├── 语法和风格检查（ESLint/Prettier）
   └── 类型检查（TypeScript Flow）

3. Claude Code审查
   ├── 全面代码审查
   ├── 安全审查
   └── 性能审查

4. 问题修复
   ├── 按严重程度排序修复
   └── 重新审查确认

5. 人工复核
   └── 关键部分人工复核

6. 提交代码
   └── git commit -m "code review: [描述修复的问题]"
```

## ⚠️ 代码审查最佳实践

| 实践 | 说明 |
|------|------|
| **审查前自测** | 先跑测试，确保基本功能正常 |
| **分批审查** | 大文件分多次审查，每次聚焦一个方面 |
| **记录问题** | 把发现的问题记录下来，建立检查清单 |
| **持续学习** | 从审查结果中学习，避免重复错误 |
| **平衡完美** | 不要追求完美，解决关键问题即可 |

## 📝 小结

Claude Code代码审查的优势：

- **全面细致** — 不会遗漏常见问题
- **知识丰富** — 了解各种最佳实践和常见陷阱
- **客观公正** — 不受情绪影响，只关注代码质量
- **快速高效** — 几分钟完成人工需要几小时的审查

**代码审查不是找茬，而是提高代码质量、减少bug的重要手段。**
