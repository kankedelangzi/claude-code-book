# 2.6 代码审查与质量保证

## 场景描述

代码写完后，如何让 Claude Code 帮你**自动审查代码质量**、**发现潜在 bug**、**生成单元测试**？本章案例：对待办 API 项目进行全面的代码审查和质量提升。

---

## 核心目标

- **代码审查**：自动发现潜在问题（安全漏洞、性能瓶颈、不良实践）
- **单元测试**：生成高覆盖率的测试用例
- **代码格式化**：统一代码风格（ESLint + Prettier）
- **性能优化**：发现并修复性能瓶颈

---

## 完整工作流

### 第一步：让 Claude Code 审查代码（5分钟）

对 Claude Code 说：

```
请帮我审查当前项目的代码质量，重点检查：
1. 安全漏洞（如 SQL 注入、XSS、密钥泄露）
2. 错误处理是否完善
3. 是否有性能瓶颈（如数据库查询未索引）
4. 代码规范（命名、注释、重复代码）
5. 给出具体的修改建议

请逐文件分析，并生成代码审查报告。
```

**关键点**：明确说出你要审查的"重点方面"，Claude Code 会生成详细的审查报告。

---

### 第二步：审查报告示例

Claude Code 会生成类似这样的报告：

```markdown
# 代码审查报告

## 1. 安全漏洞

### 🔴 高危：JWT 密钥硬编码
**文件**：`middlewares/auth.js`
**问题**：JWT 密钥直接写在代码里，存在泄露风险
**建议**：改用环境变量 `process.env.JWT_SECRET`

### 🟡 中危：未限制请求频率
**文件**：`routes/todos.js`
**问题**：未添加 rate limiting，容易被恶意刷接口
**建议**：用 `express-rate-limit` 限制频率

---

## 2. 错误处理

### 🟡 不完善：未捕获异步错误
**文件**：`services/todoService.js`
**问题**：部分 async 函数未用 try-catch 包裹
**建议**：统一用 try-catch 或 `express-async-errors` 库

---

## 3. 性能优化

### 🟢 建议：数据库查询未索引
**文件**：`models/Todo.js`
**问题**：`findByUserId` 未建索引，数据量大时查询慢
**建议**：添加索引 `{ userId: 1 }`

---

## 4. 代码规范

### 🟢 建议：函数命名不清晰
**文件**：`dao/todoDao.js`
**问题**：函数名 `get` 太宽泛，建议改为 `findById`
**建议**：统一命名规范（动词+名词）

---

## 5. 改进优先级

1. **立即修复**：JWT 密钥硬编码（安全风险）
2. **高优先级**：添加 rate limiting（防止滥用）
3. **中优先级**：完善错误处理（提高稳定性）
4. **低优先级**：优化命名（提高可读性）
```

---

### 第三步：让 Claude Code 自动修复问题（10分钟）

根据审查报告，让 Claude Code 逐个修复：

#### 修复 1：JWT 密钥硬编码

```
请帮我修复 JWT 密钥硬编码问题：
1. 从 process.env.JWT_SECRET 读取密钥
2. 更新 .env.example 添加 JWT_SECRET 配置项
3. 更新 config/validation.js 添加 JWT_SECRET 校验
```

Claude Code 会自动修改相关文件。

---

#### 修复 2：添加 Rate Limiting

```
请帮我添加 API 访问频率限制：
1. 安装 express-rate-limit
2. 在 server.js 中全局配置（每 15 分钟最多 100 次请求）
3. 在敏感接口（如登录）添加更严格的限制（每 15 分钟最多 5 次）
```

Claude Code 会生成类似代码：

```javascript
// middlewares/rateLimiter.js
const rateLimit = require('express-rate-limit');

const globalLimiter = rateLimit({
  windowMs: 15 * 60 * 1000,  // 15 分钟
  max: 100,  // 最多 100 次请求
  message: {
    success: false,
    error: '请求过于频繁，请稍后再试'
  }
});

const authLimiter = rateLimit({
  windowMs: 15 * 60 * 1000,
  max: 5,  // 登录接口最多 5 次
  message: {
    success: false,
    error: '登录尝试次数过多，请 15 分钟后再试'
  }
});

module.exports = { globalLimiter, authLimiter };
```

---

#### 修复 3：完善错误处理

```
请帮我完善错误处理：
1. 安装 express-async-errors
2. 在异步路由中自动捕获错误（不用写 try-catch）
3. 更新错误处理中间件，区分不同错误类型（404、400、500）
```

### 第四步：生成单元测试（8分钟）

让 Claude Code 生成测试用例：

```
请为 todoController 生成单元测试（用 Jest + Supertest），覆盖：
1. 创建待办事项（成功/失败）
2. 获取待办事项列表（空列表/有数据）
3. 获取单个待办事项（存在/不存在）
4. 更新待办事项（成功/失败）
5. 删除待办事项（成功/失败）

要求：
- Mock todoDao（不依赖真实数据库）
- 测试覆盖率 > 80%
- 包含边界情况测试
```

Claude Code 会生成类似代码：

```javascript
// tests/todoController.test.js
const request = require('supertest');
const app = require('../server');
const todoDao = require('../dao/todoDao');

// Mock todoDao
jest.mock('../dao/todoDao');

describe('Todo Controller', () => {
  beforeEach(() => {
    jest.clearAllMocks();
  });

  // 测试创建待办事项
  describe('POST /api/todos', () => {
    it('应该成功创建待办事项', async () => {
      const mockTodo = {
        _id: '123',
        title: '测试待办',
        description: '测试描述',
        completed: false
      };
      
      todoDao.create.mockResolvedValue(mockTodo);
      
      const response = await request(app)
        .post('/api/todos')
        .send({ title: '测试待办', description: '测试描述' })
        .expect(201);
      
      expect(response.body.success).toBe(true);
      expect(response.body.data.title).toBe('测试待办');
    });

    it('应该返回 400 如果标题为空', async () => {
      const response = await request(app)
        .post('/api/todos')
        .send({ description: '测试描述' })
        .expect(400);
      
      expect(response.body.success).toBe(false);
    });
  });

  // 测试获取待办事项列表
  describe('GET /api/todos', () => {
    it('应该返回待办事项列表', async () => {
      const mockTodos = [
        { _id: '123', title: '待办1', completed: false },
        { _id: '456', title: '待办2', completed: true }
      ];
      
      todoDao.findAll.mockResolvedValue(mockTodos);
      
      const response = await request(app)
        .get('/api/todos')
        .expect(200);
      
      expect(response.body.data).toHaveLength(2);
    });
  });

  // ... 更多测试用例
});
```

### 第五步：配置 ESLint + Prettier（5分钟）

让 Claude Code 生成配置：

```
请帮我配置 ESLint + Prettier，要求：
1. 使用 Airbnb JavaScript 规范
2. 自动格式化代码（保存时自动格式化）
3. 生成 .eslintrc.js 和 .prettierrc
4. 添加 npm scripts：lint、format
```

Claude Code 会生成配置文件：

**.eslintrc.js**：

```javascript
module.exports = {
  env: {
    node: true,
    es2021: true,
    jest: true
  },
  extends: ['airbnb-base'],
  parserOptions: {
    ecmaVersion: 12,
    sourceType: 'module'
  },
  rules: {
    'no-console': ['warn', { allow: ['warn', 'error'] }],
    'no-unused-vars': ['error', { argsIgnorePattern: '^_' }]
  }
};
```

**.prettierrc**：

```json
{
  "singleQuote": true,
  "trailingComma": "es5",
  "printWidth": 100,
  "semi": true
}
```

**package.json** 添加 scripts：

```json
{
  "scripts": {
    "lint": "eslint . --ext .js",
    "lint:fix": "eslint . --ext .js --fix",
    "format": "prettier --write \"**/*.js\""
  }
}
```

## 核心技巧

### 1. 让 Claude Code 生成"完整的代码审查报告"

❌ **不好**：只说"帮我审查代码"
✅ **好**：明确说出审查重点

```
请帮我审查代码，重点检查：
1. 安全漏洞（SQL 注入、XSS、密钥泄露）
2. 性能问题（数据库查询、循环嵌套）
3. 错误处理（是否完善）
4. 代码规范（命名、注释、重复代码）
```

---

### 2. 优先修复高危问题

根据审查报告的优先级逐个修复：

1. **立即修复**：安全漏洞（SQL 注入、密钥泄露）
2. **高优先级**：性能瓶颈（数据库未索引、循环嵌套）
3. **中优先级**：错误处理不完善
4. **低优先级**：代码规范（命名、注释）

---

### 3. 用 Jest + Supertest 生成自动化测试

❌ **不好**：手动测试 API（用 curl 或 Postman）
✅ **好**：用 Jest 生成自动化测试

**让 Claude Code 生成**：

```
请为 todoController 生成单元测试，要求：
1. Mock 所有外部依赖（数据库、第三方 API）
2. 测试覆盖率 > 80%
3. 包含边界情况测试
```

---

### 4. 用 ESLint + Prettier 统一代码风格

❌ **不好**：手动格式化代码，风格不统一
✅ **好**：用 ESLint + Prettier 自动格式化

**好处**：
- 保存时自动格式化
- 团队统一代码风格
- 减少代码审查时的格式争议

## 常见问题

### Q1：Claude Code 生成的测试代码有 bug 怎么办？

把错误信息发给它：

```
运行测试的时候报错了：

TypeError: Cannot read property 'mockResolvedValue' of undefined

这是我的测试代码：

[粘贴代码]

请帮我修复。
```

---

### Q2：如何提高测试覆盖率？

让 Claude Code 帮你补充测试用例：

```
我的测试覆盖率只有 60%，请帮我补充测试用例，重点覆盖：
1. 边界情况（如空数组、null、undefined）
2. 错误处理（如数据库连接失败）
3. 并发场景（如多个用户同时创建待办事项）
```

---

### Q3：ESLint 报错太多，如何快速修复？

运行自动修复：

```bash
npm run lint:fix
```

如果还有报错，把错误信息发给 Claude Code：

```
ESLint 报错：

error  'todoDao' is not defined  no-undef

请帮我修复。
```
