# 3.3 架构调整场景

## 场景描述

项目从单体应用演进到微服务架构，或者需要引入消息队列、读写分离等高级架构。用 Claude Code 可以快速**生成架构调整方案**、**自动重构代码**。

本章案例：将单体待办 API **拆分为微服务**（用户服务 + 待办服务），并引入 **Redis 消息队列**。

---

## 核心目标

- **架构评估**：让 Claude Code 评估当前架构的瓶颈
- **生成方案**：自动生成微服务拆分方案
- **代码重构**：让 Claude Code 拆分代码（提取服务、配置通信）
- **验证结果**：用集成测试确保服务间通信正常

**Claude Code 会生成类似报告**：

```markdown
# 架构调整方案：单体 → 微服务

## 1. 服务拆分建议

### 用户服务（User Service）
- **职责**：用户注册、登录、权限管理
- **数据库**：独立用户数据库（users）
- **接口**：`POST /users`、`POST /login`、`GET /users/:id`

### 待办服务（Todo Service）
- **职责**：待办事项的 CRUD
- **数据库**：独立待办数据库（todos）
- **接口**：`POST /todos`、`GET /todos`、`PUT /todos/:id`、`DELETE /todos/:id`

### 通知服务（Notification Service）
- **职责**：发送邮件、推送通知
- **通信方式**：消息队列（Redis Pub/Sub）
- **触发时机**：待办事项即将到期时发送提醒

---

## 2. 服务间通信方式

| 场景 | 通信方式 | 理由 |
|---|---|---|
| 创建待办时验证用户 | HTTP 调用（User Service） | 同步调用，立即返回结果 |
| 待办到期提醒 | 消息队列（Redis Pub/Sub） | 异步处理，解耦 |

---

## 3. 数据库拆分方案

### 用户数据库（user_db）
```sql
CREATE TABLE users (
  id INT PRIMARY KEY AUTO_INCREMENT,
  name VARCHAR(100),
  email VARCHAR(100) UNIQUE
);
```

### 待办数据库（todo_db）
```sql
CREATE TABLE todos (
  id INT PRIMARY KEY AUTO_INCREMENT,
  title VARCHAR(200),
  user_id INT,  -- 指向用户服务
  FOREIGN KEY (user_id) REFERENCES users(id)  -- 注意：跨库无法建外键
);
```

**注意**：微服务架构中，每个服务有独立数据库，无法使用数据库外键，需要**应用层保证一致性**。

---

## 4. 分布式事务方案

### 场景：创建待办事项（需要验证用户是否存在）

**方案 1：SAGA 模式（推荐）**
1. Todo Service 发送 "创建待办" 消息到消息队列
2. User Service 消费消息，验证用户是否存在
3. 如果存在，Todo Service 创建待办；否则回滚

**方案 2：TCC 模式（复杂）**
1. Try：预创建待办（状态为 "pending"）
2. Confirm：用户验证通过，状态改为 "active"
3. Cancel：用户验证失败，删除待办

---

## 5. 实施步骤

1. **第一步**：拆分用户服务（User Service）
2. **第二步**：拆分待办服务（Todo Service）
3. **第三步**：引入消息队列（Redis Pub/Sub）
4. **第四步**：拆分数据库（user_db / todo_db）
5. **第五步**：添加服务发现（Consul / etcd）
```

**核心代码**（`todo-service/src/services/userServiceClient.js`）：

```javascript
const axios = require('axios');
const config = require('../config');

const userServiceClient = {
  // 验证用户是否存在
  checkUserExists: async (userId) => {
    try {
      const response = await axios.get(`${config.services.user}/users/${userId}`);
      return response.data;
    } catch (error) {
      if (error.response && error.response.status === 404) {
        throw new Error('用户不存在');
      }
      throw error;
    }
  }
};

module.exports = userServiceClient;
```

**核心代码**（`todo-service/src/services/notificationService.js`）：

```javascript
const redis = require('../config/redis');

const notificationService = {
  // 发送待办到期提醒
  sendDueReminder: async (todo) => {
    const message = {
      type: 'TODO_DUE',
      todoId: todo._id,
      userId: todo.userId,
      title: todo.title,
      dueDate: todo.dueDate
    };
    
    await redis.publish('notifications', JSON.stringify(message));
  }
};

module.exports = notificationService;
```

**核心代码**（`notification-service/src/index.js`）：

```javascript
const redis = require('./config/redis');
const emailService = require('./emailService');

const start = async () => {
  console.log('📧 通知服务启动，订阅 notifications 频道...');
  
  // 订阅 Redis 频道
  const subscriber = redis.duplicate();
  await subscriber.connect();
  
  await subscriber.subscribe('notifications', async (message) => {
    const notification = JSON.parse(message);
    
    console.log('收到通知：', notification);
    
    // 发送邮件提醒
    if (notification.type === 'TODO_DUE') {
      await emailService.sendDueReminder(notification);
    }
  });
};

start();
```

services:
  # MongoDB for User Service
  mongodb-user:
    image: mongo:4.4
    container_name: mongodb-user
    ports:
      - "27017:27017"
    volumes:
      - mongodb_user_data:/data/db
    networks:
      - microservices-network

  # MongoDB for Todo Service
  mongodb-todo:
    image: mongo:4.4
    container_name: mongodb-todo
    ports:
      - "27018:27017"
    volumes:
      - mongodb_todo_data:/data/db
    networks:
      - microservices-network

  # Redis for Message Queue
  redis:
    image: redis:6.2
    container_name: redis
    ports:
      - "6379:6379"
    networks:
      - microservices-network

  # User Service
  user-service:
    build: ./user-service
    container_name: user-service
    ports:
      - "3001:3001"
    environment:
      MONGODB_URI: mongodb://mongodb-user:27017/user_db
    depends_on:
      - mongodb-user
    networks:
      - microservices-network

  # Todo Service
  todo-service:

    container_name: todo-service
    ports:
      - "3002:3002"

      USER_SERVICE_URL: http://user-service:3001
      REDIS_URL: redis://redis:6379
    depends_on:
      - mongodb-todo
      - user-service
      - redis
    networks:
      - microservices-network

  # Notification Service
  notification-service:
    build: ./notification-service
    container_name: notification-service
    environment:
      REDIS_URL: redis://redis:6379
    depends_on:
      - redis
    networks:
      - microservices-network

networks:
  microservices-network:
    driver: bridge

volumes:
  mongodb_user_data:
  mongodb_todo_data:
