## 场景一：文件管理 —— filesystem

**问题**：每次要读写文件都要切换终端或 IDE，太麻烦。

### 安装

```json
// ~/.config/claude/mcp.json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/Users/dayu/projects"]
    }
  }
}
```

### 真实使用

```bash
# 场景：你要在项目里新建一个组件，但不确定目录结构
你：查看 ~/projects/my-app/src 目录下所有 .tsx 文件
Claude：找到以下组件文件：
  - Button.tsx
  - Modal.tsx
  - Dropdown.tsx

你：把 components 目录的 .tsx 文件复制到新项目 src/components/
Claude：[读取] [写入] 已复制 3 个文件到新项目

你：帮我搜索 components 目录里包含 "onClick" 的文件
Claude：匹配结果：
  - Button.tsx (12 处)
  - Modal.tsx (3 处)
```

### 效率对比

| 操作 | 手动操作 | 用 MCP |
|------|---------|--------|
| 批量文件操作 | 手动复制/移动 | 一句话搞定 |
| 搜索内容 | grep 命令 | 自然语言搜索 |
| 文件对比 | 打开两个窗口 | 直接对比结果 |

## 场景二：数据库操作 —— postgres

**问题**：查数据库要打开 TablePlus/PgAdmin，记 SQL 语法头疼。

### 安装

```json
{
  "mcpServers": {
    "postgres": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-postgres"],
      "env": {
        "DATABASE_URL": "postgresql://user:password@localhost:5432/myapp"
      }
    }
  }
}
```

### 真实使用

```bash
# 场景：运营问你要最近一周的活跃用户数据

你：查询 users 表中最近 7 天有登录记录的活跃用户数，按注册来源分组
Claude：[执行 SQL]
活跃用户统计（最近7天）：
┌────────────┬───────┐
│ 来源       │ 用户数 │
├────────────┼───────┤
│ ios        │ 1,234 │
│ android    │ 2,891 │
│ web        │  876 │
└────────────┴───────┘

# 场景：开发时想知道某个表的结构
你：描述 users 表的结构，包括所有字段和类型
Claude：
users 表结构：
  - id: integer (PK, 自增)
  - email: varchar(255) (唯一)
  - created_at: timestamp (默认 now())
  - status: varchar(50) (索引)
  ...

# 场景：数据修复
你：把 users 表中 status='pending' 且 created_at < '2024-01-01' 的记录状态改为 'archived'
Claude：[执行] 已更新 47 条记录
```

### 安全提示

⚠️ 数据库 MCP 权限很大，用完记得断开或限制 IP 白名单。

## 场景三：网页搜索 —— brave-search

**问题**：Claude Code 知识有截止日期，查最新资讯还得切浏览器。

### 安装

1. 去 [brave.com/search/api](https://brave.com/search/api/) 申请 API Key（免费额度够用）
2. 配置：

```json
{
  "mcpServers": {
    "brave-search": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-brave-search"],
      "env": {
        "BRAVE_API_KEY": "你的API密钥"
      }
    }
  }
}
```

### 真实使用

```bash
# 场景：写代码前查最新方案

你：搜索 Claude Code 最新版本有哪些新特性
Claude：[搜索 Web]
根据搜索结果，Claude Code 最新特性包括：
  ✓ MCP 工具支持增强
  ✓ 自动内存管理优化
  ✓ 更好的长文本处理
  ...

# 场景：查某个库的版本
你：搜索 React 19 正式版的发布时间和主要变化
Claude：
- 正式发布：2024年10月
- 主要变化：Server Components 稳定、新的 hooks...

# 场景：排查错误
你：搜索 "TypeError: Cannot read properties of undefined" react 19 这个错误怎么解决
Claude：
根据搜索结果，解决方案是...
```

### 替代方案

如果没有 Brave API Key，可以用免费的 `ddg-search`：

```json
{
  "mcpServers": {
    "ddg": {
      "command": "npx",
      "args": ["-y", "mcp-server-ddg"]
    }
  }
}
```

## 场景五：Slack/通知 —— slack

**问题**：CI 跑完了、部署完成了，你还在等通知。

### 安装

1. 在 Slack 创建 App，拿到 Bot Token
2. 配置：

```json
{
  "mcpServers": {
    "slack": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-slack"],
      "env": {
        "SLACK_BOT_TOKEN": "xoxb-xxx",
        "SLACK_TEAM_ID": "T0123456789"
      }
    }
  }
}
```

### 真实使用

```bash
# 场景：自动化通知

你：当我的代码推送到 main 分支时，发送消息到 #deployments 频道
Claude：已配置 Webhook 触发规则

你：手动测试一下，发送"部署测试成功"到 #deployments
Claude：[发送消息] ✓ 消息已发送

# 场景：CI 结果通知
你：当 GitHub Actions 失败时，发送到 #alerts 频道，包含失败原因
Claude：已配置 GitHub Webhook + Slack 集成
```

## MCP 组合技：一条命令完成全套操作

**场景**：运营报告自动化

```
你：用 MCP 查询数据库里最近 7 天的数据，生成 Markdown 报告保存到 ~/reports/weekly.md
Claude：
  [查询数据库] → 获取数据
  [生成报告] → 格式化内容
  [写入文件] → ~/reports/weekly.md ✓

你：然后把这份报告发送到 Slack 的 #reports 频道
Claude：[读取文件] → [发送 Slack] ✓ 已发送
```

**一条命令，过去要开三个工具做的事情，30 秒搞定。**
