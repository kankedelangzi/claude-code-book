# 前言

## 为什么写这本书

2025 年，AI 编程助手从"新奇玩具"变成了"生产力工具"。

Copilot 开了个头，Cursor 做了更好的 IDE 集成，但真正让我觉得"这玩意儿能干活"的，是 Claude Code。它不是那种"你敲一个字母我补全一个单词"的补全工具，而是一个能听懂你说什么、读得懂你的项目、自己就能动手改代码的助手。

第一次用 Claude Code，我跟它说"帮我把这个 REST API 迁移到 GraphQL"，它读了我的代码结构，改了十几个文件，还顺带把测试也更新了。我检查了一下，居然没什么大问题。那一刻我意识到——这东西跟以前不一样了。

但问题也来了：**大多数人不知道怎么用它。**

官方文档写得很好，但偏理论。社区里零散有一些案例，但不成体系。很多人的体验是：打开 Claude Code，敲一句话，得到一个还行的结果，然后就不知道怎么往下走了。

**这本书就是解决这个问题的。**

## 这本书适合谁

- 你是开发者，听说过 Claude Code，想快速上手
- 你已经在用 Claude Code，但觉得"明明可以更好"
- 你带团队，想提高整个团队的 AI 辅助开发效率
- 你不是专业程序员，但想用 Claude Code 帮你写代码解决问题

你不需要是 AI 专家。这本书不讲大模型原理，不讲 transformer 架构，不讲训练方法。我们只关心一件事：**怎么把 Claude Code 用好。**

## 这本书怎么读

这本书按场景组织，不是按功能组织。你不需要从头读到尾。

- **想快速体验** → 直接看第一章
- **遇到具体问题** → 翻到对应章节找案例
- **想系统提升** → 从头到尾过一遍

每个案例都是独立的，包含：
- **场景描述**：什么情况下用
- **操作对比**：传统做法 vs Claude Code 做法
- **效率提升**：实际节省多少时间
- **注意事项**：什么时候要小心

代码可以直接复制粘贴，案例可以直接照着做。

## 几个忠告

1. **Claude Code 是助手，不是替代**。它可以帮你写代码、改代码、查 Bug，但最终决定权在你手上。不要无脑接受它的输出，尤其是涉及安全、性能的关键代码。

2. **指令质量决定输出质量**。"帮我写个接口"和"用 Express + Prisma 写一个 POST /users 接口，参数是 name 和 email，返回 201 和用户对象，重复 email 返回 409"——后者的结果好十倍。

3. **上下文是王道**。Claude Code 能读取你的项目文件，但它不知道你的业务背景。用 CLAUDE.md 告诉它你的技术栈、代码规范、项目结构，输出质量会上一个台阶。

4. **先跑测试，再信代码**。Claude Code 生成的代码大多数时候是对的，但"大多数"不等于"总是"。养成跑测试的习惯，省得事后排错。

5. **小步快跑**。与其一次让它改 20 个文件，不如分 3-4 次每次改 5 个，每改一次验证一次。出错了好定位，回滚也方便。
