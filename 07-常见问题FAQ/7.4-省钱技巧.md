# 7.4 省钱技巧

> Claude Code 按用量计费。不多花冤枉钱，也是一种能力。

## 🎯 核心思路

省钱不是少用，而是**用得聪明**。

```
省钱 = 减少无效 token + 善用本地能力 + 合理规划对话
```

---

## 💡 最重要的原则（详细版）

### 原则 1：能在本地搞定的，别让它处理 🏠

Claude Code 每次对话都要发送上下文给 API。上下文越大，花费越高。

**浪费钱的示例 ❌**
```bash
# 场景 1：改一个变量名
你："帮我把 config.username 改成 config.accountName"
→ Claude Code 会读取整个文件（甚至整个项目）作为上下文
→ 花费：读取 1000+ tokens
→ 你自己用编辑器全局替换：0 元，10 秒

# 场景 2：格式化代码
你："帮我把这段代码格式化一下"
→ 它可以做，但你的编辑器有快捷键（Shift+Alt+F）
→ 花费：100+ tokens
→ 编辑器格式化：0 元，1 秒

# 场景 3：查一个简单的 API
你："Math.random() 怎么用？"
→ 你可以查 MDN（5 秒）
→ 花费：50+ tokens
→ 查 MDN：0 元，5 秒
```

**省钱的做法 ✅**
```bash
✅ 简单操作自己来：
   - 改变量名 → 编辑器全局替换
   - 格式化代码 → 编辑器快捷键
   - 查 API → 查文档
   - 改配置 → 直接编辑配置文件

✅ 复杂操作让 Claude Code 来：
   - 重构代码
   - 写测试用例
   - 调试复杂 Bug
   - 生成重复性代码
```

---

### 原则 2：每次对话只做一件事 🎯

**浪费钱的示例 ❌**
```bash
# 一次对话扔 5 个任务
你："帮我创建用户表、写 API、写前端页面、写测试、写文档"

→ Claude Code 会：
   1. 读取整个项目结构（1000+ tokens）
   2. 生成大量代码（2000+ tokens）
   3. 一次对话搞定所有事（看起来省事）

问题：
- 如果中间某一步错了，前面生成的代码可能都要重新生成
- 上下文越来越大，费用越来越高
- 你很难验证每一步是否正确
```

**省钱的做法 ✅**
```bash
✅ 拆成 5 次短对话：

对话 1：创建用户表
"创建 Prisma schema，定义 User 模型（id, name, email, passwordHash）"
→ 费用：200 tokens

[验证、提交、推送]

对话 2：写 API
"基于 User 模型，写 CRUD API（GET/POST/PUT/DELETE）"
→ 费用：300 tokens

[验证、提交、推送]

对话 3：写前端页面
"创建用户管理页面（列表+表单），用 React + TypeScript"
→ 费用：400 tokens

[验证、提交、推送]

对话 4：写测试
"给 User API 写单元测试，用 Jest"
→ 费用：300 tokens

[验证、提交、推送]

对话 5：写文档
"生成 API 文档，保存为 docs/api.md"
→ 费用：200 tokens

[验证、提交、推送]

总花费：1400 tokens
如果一次对话：可能花费 3000+ tokens（因为要反复修正）
```

**关键：每次对话结束后，上下文清零。新对话 = 新计费起点。**

### 原则 3：指令要简洁精准 📝

**浪费钱的示例 ❌**
```bash
# 啰嗦的指令
你："我想写一个用户登录功能，就是那种可以让用户输入邮箱和密码，然后点击登录按钮，如果登录成功就跳转到首页，如果失败就显示错误提示的那种，对了要用 React，用 TypeScript 更好，样式的话用 Tailwind 吧，还有..."

→ 输入：500+ tokens
→ 其实 50 个 token 就能说清楚
```

**省钱的做法 ✅**
```bash
✅ 简洁的指令：
"创建登录页面：React + TypeScript + Tailwind，邮箱+密码登录，成功跳转首页，失败显示错误"

→ 输入：50 tokens
→ 节省 90% 的输入费用
```

## 📝 具体省钱技巧（详细版）

### 技巧 1：用 /compact 压缩上下文 🗜️

**问题：**
对话越长，每次发送的内容越多，费用越高。

**解法：**
Claude Code 支持 `/compact` 命令，压缩对话历史：

```bash
# 当对话变长时（比如超过 10 轮）
/compact

# 或附带指令（保留关键信息）
/compact 保留关键的技术决策和代码结构
```

**效果：**
- 压缩前：对话历史 5000 tokens
- 压缩后：摘要 500 tokens
- 节省：90% 的输入费用

**建议：**
- 对话超过 10 轮，就 compact 一次
- 重要决策要保留（在 `/compact` 后面说明）
- 压缩后验证一下它是否理解了你的意图

### 技巧 2：精准指定文件，避免全项目搜索 🎯

**浪费钱的示例 ❌**
```bash
# 模糊的指令
你："帮我修复那个 bug"

→ Claude Code 会：
   1. 搜索整个项目（grep -r "bug 关键词"）
   2. 读取多个文件寻找相关代码
   3. 可能读了很多无关文件

→ 花费：1000+ tokens（读取了大量无关文件）
```

**省钱的做法 ✅**
```bash
# 精准的指令
你："修复 src/api/users.ts 第 45 行的 bug：undefined 错误"

→ Claude Code 会：
   1. 直接读取 src/api/users.ts
   2. 只看第 45 行附近代码
   3. 精准定位问题

→ 花费：200 tokens
→ 节省：80% 的费用
```

**关键：告诉它精确位置，它就不用到处搜索。**

### 技巧 3：善用 .claudeignore 排除不需要的文件 📁

**问题：**
项目里有些文件完全没必要让 Claude Code 知道，但它们会占用上下文。

**.claudeignore 示例：**

```
# .claudeignore

# 忽略大型生成文件（这些文件很大，但 Claude Code 不需要看）
dist/
build/
.next/
out/
*.min.js
*.min.css

# 忽略媒体文件（图片、视频、音频）
images/
videos/
audio/
*.jpg
*.png
*.mp3
*.mp4

# 忽略依赖目录（这些永远不会改）
node_modules/
vendor/
packages/

# 忽略日志和缓存
logs/
*.log
.cache/
.session/

# 忽略大型数据文件
*.csv
*.jsonl
*.parquet
data/large/

# 忽略测试覆盖率报告
coverage/
```

**效果：**
- 有 .claudeignore：上下文 5000 tokens
- 没有 .claudeignore：上下文 50000+ tokens（10 倍差距！）

**建议：**
- 项目根目录创建 `.claudeignore`
- 把不需要 Claude Code 看的文件都加进去
- 定期审查，看看有没有漏掉的

### 技巧 4：使用 instructions.md 减少重复指令 📋

**问题：**
每次都要说"用 TypeScript""代码加注释""用 Tailwind"？这些重复的话浪费 token。

**解法：**
写进 `~/.claude/instructions.md`：

```markdown
# ~/.claude/instructions.md

## 技术栈
- 使用 TypeScript（严格模式）
- 样式用 Tailwind CSS
- 注释用中文
- 优先 async/await，不用回调函数

## 代码规范
- 函数名用驼峰命名
- 常量用大写+下划线
- 组件用函数式，不用 Class
- 每个函数不超过 50 行

## 项目约定
- API 响应格式：{ success, data, error }
- 错误用 AppError 类封装
- 日志用 logger（不要用 console.log）
```

**效果：**
- 每次对话不用重复说这些要求
- 节省：每次 50-100 tokens
- 一个月（100 次对话）：节省 5000-10000 tokens

**省下的不仅是钱，还有你的耐心。**

### 技巧 5：先让它给方案，再让它写代码 🤔

**浪费钱的示例 ❌**
```bash
# 直接让它写代码
你："帮我重构这个模块"

→ Claude Code 会：
   1. 读取整个模块（1000+ tokens）
   2. 生成重构后的代码（2000+ tokens）
   3. 如果方向错了，这些代码都白写了

→ 可能花费：3000+ tokens
→ 实际有效：可能只有 30%（方向错了）
```

**省钱的做法 ✅**
```bash
# 先让它给方案
你："分析 src/modules/user 的重构方向，列出 3 种方案，说明优缺点，不写代码"

→ Claude Code 会：
   1. 读取代码（1000+ tokens）
   2. 分析并列出方案（500 tokens）

→ 花费：1500 tokens

[你选择方案 2]

# 再让它按方案实现
你："按方案 2 实现重构，保持 API 兼容"

→ Claude Code 会：
   1. 读取代码（可能从缓存，不花 tokens）
   2. 生成重构代码（2000 tokens）

→ 花费：2000 tokens

总花费：3500 tokens，但方向正确，没有返工
如果直接写代码可能花费 6000+ tokens（返工 2 次）
```

**关键：先确认方向，再花 token 写代码。方向错了，代码白写。**

### 技巧 6：小改动自己来，别麻烦 AI ✋

**判断标准：**

| 操作 | 预计时间 | 用 Claude Code？ | 原因 |
|------|---------|----------------|------|
| 改一个变量名 | 10 秒 | ❌ 不用 | 编辑器全局替换更快 |
| 加一行注释 | 5 秒 | ❌ 不用 | 手打最快 |
| 改一个 CSS 颜色 | 10 秒 | ❌ 不用 | 手改最准 |
| 格式化代码 | 1 秒 | ❌ 不用 | 编辑器快捷键 |
| 查一个 API 用法 | 30 秒 | ❌ 不用 | 查文档更快 |
| 创建一个组件 | 30 分钟 | ✅ 用 | 它 5 分钟，你 30 分钟 |
| 调试复杂 Bug | 1 小时 | ✅ 用 | 它 10 分钟，你 1 小时 |
| 写测试用例 | 1 小时 | ✅ 用 | 它 10 分钟，你 1 小时 |
| 重构代码 | 2 小时 | ✅ 用 | 它 20 分钟，你 2 小时 |

**3 分钟能搞定的，别花 token。**

### 技巧 7：合理使用不同模型（如果可选）🧠

**不同任务用不同级别的模型：**

```
简单格式化、文件操作、查找替换
    → 用较轻量的模型（如果可选）

复杂架构设计、疑难 Bug、性能优化
    → 用最强模型

日常开发（创建组件、写 API、改代码）
    → 默认模型就好
```

**如果 Claude Code 支持模型选择：**
```bash
# 简单任务用轻量模型
/model claude-instant
"帮我格式化这个文件"

# 复杂任务用最强模型
/model claude-3-opus
"帮我设计一个微服务架构"
```

### 技巧 8：利用缓存，避免重复读取 📦

**问题：**
每次对话，Claude Code 都要重新读取文件，花费 tokens。

**解法：**
```bash
# 在同一个对话里，尽量完成相关任务

对话 1：
"读取 src/api/users.ts，然后：
 1. 给 getAll 函数加参数验证
 2. 给 getById 函数加错误处理
 3. 给 create 函数加权限校验"

→ 文件只读一次，3 个任务都完成
→ 花费：300 tokens

如果分 3 次对话：
→ 文件读 3 次
→ 花费：900 tokens
```

**关键：相关任务在一次对话里完成，利用缓存。**

### 技巧 9：避免让 Claude Code 搜索全项目 🔍

**浪费钱的示例 ❌**
```bash
你："这个项目里哪里用到了 useState？"

→ Claude Code 会：
   1. 搜索整个项目（grep -r "useState"）
   2. 读取所有匹配的文件
   3. 汇总结果

→ 花费：可能 5000+ tokens（读取了大量文件）
```

**省钱的做法 ✅**
```bash
# 你自己搜索，然后问具体问题
你（在自己终端）：grep -r "useState" src/

[发现 5 个文件用了 useState]

你："src/components/UserList.tsx 第 10 行用了 useState，帮我改成 useReducer"

→ 花费：200 tokens
→ 节省：95% 的费用
```

**关键：搜索自己来，让 Claude Code 专注写代码。**

### 技巧 10：批量操作优于逐个操作 📊

**浪费钱的示例 ❌**
```bash
# 逐个文件改
对话 1："给 User.ts 加注释"
对话 2："给 Order.ts 加注释"
对话 3："给 Product.ts 加注释"

→ 3 次对话，每次都要读取文件
→ 花费：3 × 200 = 600 tokens
```

**省钱的做法 ✅**
```bash
# 一次批量改
"给以下文件加注释：
- src/models/User.ts
- src/models/Order.ts
- src/models/Product.ts"

→ 一次对话，读取 3 个文件
→ 花费：400 tokens
→ 节省：33% 的费用
```

## 📊 理解计费方式（详细版）

Claude Code 的费用主要来自两方面：

```
1. 输入 token（你发送给 API 的内容）
   - 包含：你的指令 + 代码文件 + 对话历史 + 系统提示
   - 特点：通常比输出贵（或者至少同样贵）
   
2. 输出 token（API 返回的内容）
   - 包含：生成的代码 + 解释文字
   - 特点：代码越长，输出 token 越多
```

**关键：输入 token 通常比输出贵，所以减少输入量 = 直接省钱。**

---

### 什么最吃 token？🍽️

| 操作 | 预计 token 消耗 | 是否必要 |
|------|----------------|----------|
| 读取大文件（> 500 行） | 1000+ tokens | 尽量避免 |
| 长对话历史（> 20 轮） | 5000+ tokens | 用 /compact |
| 多文件搜索（grep -r） | 2000+ tokens | 自己搜索 |
| 读取整个项目结构 | 500+ tokens | 精准指定文件 |
| 生成大量代码（> 200 行） | 1000+ tokens | 分批生成 |

---

### 什么不花 token？（或者花得很少）💰

| 操作 | Token 消耗 | 说明 |
|------|--------------|------|
| 终端命令执行 | 0 tokens | 执行本身不花 token（但输出会计入上下文） |
| 文件写入 | 0 tokens | 写文件不额外花 token |
| 简单的数学计算 | 10-20 tokens | 非常少 |
| 缓存命中 | 减少 50-90% | 同一次对话里重复读取同一文件 |

---

### 一个估算公式 🧮

```
单次对话成本 ≈ (系统提示 + 你的指令 + 文件内容 + 对话历史) × 输入单价
             + (生成内容) × 输出单价
```

**所以省钱的关键就是：**
1. **减少每次对话传入的文件大小** → 减少输入 token
2. **压缩对话历史** → 减少输入 token
3. **指令简洁精准** → 减少输入 token
4. **分批生成代码** → 减少输出 token（如果输出更贵）

## ⚡ 实用省钱清单

### 每天开始工作前：

- [ ] 检查 `.claudeignore` 是否覆盖了不需要的文件
- [ ] 确认 `instructions.md` 里有常用偏好（省得每次重复说）
- [ ] 看看有没有可以批量处理的任务（一次对话完成多个相关任务）

### 每次对话前：

- [ ] 这个任务我自己 3 分钟能搞定吗？能就自己做
- [ ] 文件路径我明确吗？明确就精准指定
- [ ] 我能不能先自己搜索，然后只问具体问题？

### 对话过程中：

- [ ] 对话超过 10 轮了吗？超过就 `/compact`
- [ ] 它在搜索我不需要的东西吗？及时叫停
- [ ] 我是不是在让它做简单的事（改变量名、格式化）？停下来自己改

### 对话结束后：

- [ ] 涉及关键决策的内容记录下来了吗？（下次就不用重新讨论）
- [ ] 生成的代码我测试了吗？没测试别结束对话
- [ ] 可以提交代码了吗？提交后再开始新对话

## 🎓 学到了什么

1. **省钱的核心是减少无效 token** — 精准指令 + 合理范围 + 及时压缩
2. **小改动自己做** — 别拿大炮打蚊子
3. **善用配置** — `.claudeignore` 和 `instructions.md` 是省钱利器
4. **先方案后代码** — 方向确认了再花 token
5. **批量优于逐个** — 相关任务一次对话完成，利用缓存
6. **自己搜索** — 让 Claude Code 专注写代码，别让它浪费 token 搜索

---

## ⚠️ 注意

- 省钱的前提是**效率不降低**，如果为了省钱让开发变慢，反而亏了
- Claude Code 的定价可能调整，关注官方公告
- 记住：**时间 > token 费用** — 别为了省几毛钱浪费半小时
- 如果任务紧急，别为了省钱而省钱，用最好的模型最快解决
- 定期回顾你的 token 使用情况，找出可以优化的地方
