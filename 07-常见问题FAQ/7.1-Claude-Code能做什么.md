# 7.1 Claude Code 能做什么？

> 别问"它行不行"，问"怎么让它干"。大多数时候，答案是：能。

## 🎯 一句话回答

Claude Code 是一个住在终端里的编程搭档——你说需求，它写代码、改代码、调 Bug、跑测试，还能帮你读文档和搜索方案。

## 💡 它擅长的领域

### 1. 写代码（从零到完整实现）

**场景：你想实现一个功能，但不知道从哪开始**

```
帮我在 Next.js 项目里创建一个用户登录页面，
用 TypeScript，包含表单验证和错误提示。
要求：
- 邮箱 + 密码登录
- 表单验证（邮箱格式、密码至少 8 位）
- 错误提示用红色文字显示在输入框下方
- 登录成功跳转到 /dashboard
- 登录失败显示错误提示
- 用 Tailwind CSS 样式
- 组件放在 src/components/LoginForm.tsx
```

**Claude Code 会做什么：**
1. 创建 `src/components/LoginForm.tsx`
2. 写完整的 React 组件（状态管理、表单处理、API 调用）
3. 添加 TypeScript 类型定义
4. 写 Tailwind 样式
5. 处理登录成功/失败的逻辑
6. 如果需要，还会帮你创建 API 路由 `src/pages/api/login.ts`

**传统做法 vs Claude Code：**
- 传统：查文档 → 写组件 → 调样式 → 对接 API → 测试（2-3 小时）
- Claude Code：描述需求 → 生成代码 → 跑起来看看 → 微调（10-15 分钟）

### 2. 改代码（理解上下文，精准修改）

**场景：你要重构或添加功能，但代码已经很复杂**

```

用 useState 和 useEffect 替换生命周期方法。

```

**Claude Code 会做什么：**
1. 读取整个文件，理解现有逻辑
2. 识别生命周期方法（`componentDidMount` 等）
3. 转换成对应的 Hooks（`useEffect` 等）
4. 保留所有业务逻辑
5. 更新类型定义

**更复杂的改代码场景：**

```
给所有 API 接口加上错误处理：
- 网络错误时显示"网络连接失败，请检查网络"
- 401 错误时跳转到登录页
- 500 错误时显示"服务器开小差了，请稍后再试"
- 其他错误显示服务器返回的错误信息
- 涉及文件：src/services/*.ts
```

它会在多个文件里统一加上错误处理逻辑。

### 4. 调 Bug（定位 + 修复一条龙）

**场景：报错了，但不知道哪里出问题**

```
这个接口返回 500，日志里有 "Cannot read property 'map' of undefined"
帮我定位问题
```

**Claude Code 会做什么：**
1. 分析错误信息，定位可能的代码位置
2. 读取相关文件
3. 找出为什么会出现 `undefined`
4. 给出修复方案（可能还要你确认）
5. 直接改代码

**更复杂的 Debug：**

```
用户报告：提交表单后页面白屏
控制台报错：
TypeError: Cannot read properties of null (reading 'userId')

调用栈：
  at UserProfile (UserProfile.jsx:15)
  at renderWithHooks (react-dom.development.js:14965)

帮我修复
```

它会：
1. 读取 `UserProfile.jsx`
2. 发现第 15 行访问了 `user.userId`
3. 但 `user` 可能是 `null`（还没加载完）
4. 给出修复：加一个空值判断 `if (!user) return <Loading />`

### 9. 数据库操作（SQL + ORM 都行）

**场景：你要写复杂的 SQL 查询**

```
帮我写一个统计查询：
- 表：orders（订单）、users（用户）、products（商品）
- 需求：统计每个用户的总消费金额、订单数、平均客单价
- 只统计 2024 年以来的数据
- 结果按总消费金额降序排列
- 输出：用户名、邮箱、总消费、订单数、平均客单价
```

**Claude Code 会生成优化的 SQL：**
```sql
SELECT 
    u.name,
    u.email,
    SUM(o.total_amount) AS total_spent,
    COUNT(o.id) AS order_count,
    AVG(o.total_amount) AS avg_order_value
FROM users u
JOIN orders o ON u.id = o.user_id
WHERE o.created_at >= '2024-01-01'
GROUP BY u.id, u.name, u.email
ORDER BY total_spent DESC;
```

**ORM 操作：**

```
用 Prisma 实现：
- 创建用户时同时创建用户配置文件（UserProfile）
- 使用事务保证原子性
- 如果失败要回滚
```

## ❌ 它做不好的事（诚实评估）

**诚实说，有些场景别指望它：**

### 1. 完全取代你的判断 🚫

它写的代码你要 review，不要无脑采纳。

**为什么：**
- AI 不知道你的具体业务场景
- 它可能用了过时的最佳实践
- 安全敏感代码必须人工审查

**正确做法：**
```
让 Claude Code 写代码 → 你 review → 你测试 → 你提交
```

---

### 2. 理解你没有说清的需求 🤔

指令模糊，结果就模糊。

**模糊的指令：**
```
❌ 帮我优化一下这个函数
```

**清晰的指令：**
```
✅ 帮我优化这个函数：
   - 目标：减少时间复杂度从 O(n²) 到 O(n)
   - 方法：用 Map 缓存中间结果
   - 保持函数签名不变
   - 添加性能测试
```

---

### 3. 处理超大型单体项目 📚

上下文窗口有限，几十万行的项目会吃力。

**为什么：**
- Claude Code 一次能处理的代码量有限（约 200K tokens）
- 超大型项目需要分模块处理

**解决方案：**
```
❌ 不要：让它一次性理解整个项目
✅ 应该：按模块逐步引导，每次聚焦一个模块
```

**示例：**
```
先帮我理解用户模块（src/modules/users）
看完后再帮我理解订单模块（src/modules/orders）
```

---

### 4. 实时协作 👥

它不是实时结对编程，是异步对话。

**不适合的场景：**
- 你需要和人实时讨论设计方案
- 你在 pair programming
- 你需要立即得到反馈（Claude Code 响应需要几秒到几十秒）

**适合的场景：**
- 你写代码，它帮你查文档、生成模板代码
- 你遇到 bug，它帮你分析
- 你要重构，它帮你一步步改

---

### 5. 闭眼提交到生产环境 🚨

重要代码必须自己测试。

**Claude Code 能做的：**
- 写代码
- 写测试
- 生成部署脚本

**你必须做的：**
- Review 代码
- 跑测试
- 在测试环境验证
- 监控生产环境

---

### 6. 理解业务逻辑和人情世故 🤷

它只看代码，不理解：
- 为什么你们公司要用这个奇怪的架构（可能有历史原因）
- 为什么这个 bug 不能立即修复（可能涉及到其他团队）
- 代码里的注释"临时方案"其实是永久方案

**你需要做的：**
- 给 Claude Code 提供足够的上下文
- 告诉它哪些是不能动的"核心代码"
- 让它避开那些"政治敏感"的区域 😄

---

### 7. 处理硬件和系统级问题 🔧

软件的事它能帮，但硬件问题不行。

**它能做的：**
- 写驱动程序的代码（如果你提供规格文档）
- 调试软件层面的问题
- 生成硬件模拟代码

**它做不了的：**
- 你的电脑蓝屏了 → 它没法帮你重启
- 网线断了 → 它没法帮你插网线
- GPU 坏了 → 它没法帮你换硬件

| 处理复杂的 Git 冲突 | 简单冲突可以，复杂的你要介入 | 先让它尝试，解决不了你再上 |
| 性能优化（系统级） | 它能优化代码，但系统架构优化要你自己 | 它优化函数，你优化架构 |
| 安全加固（生产级） | 它能修常见漏洞，但高级攻防要专家 | 它处理常见问题，你请安全专家审查 |

---

### ❌ 做不了的（别为难它）

| 任务 | 原因 | 谁来做 |
|------|------|--------|
| 替你做技术决策 | 它不知道你的业务场景、团队情况、技术债务 | 你 + 你的团队 |
| 保证代码 100% 正确 | 永远要 review，AI 也会犯错 | 你 + 测试 + Code Review |
| 理解项目的历史背景 | 它只看代码，不参加你们的站会 | 你（通过文档或 CLAUDE.md 告诉它） |
| 处理硬件问题 | 拔网线、换硬盘、重启服务器 | 你（或你们的运维） |
| 预测未来需求 | 它基于当前信息，不能未卜先知 | 你（基于你对业务的理解） |
| 处理人际关系 | 代码冲突背后的"政治"问题 | 你（这是在考验你的软实力） |

## 📝 怎么判断该不该用它？（决策树）

### 决策树

```
开始
 |
 +-- 这个任务我 10 分钟内能自己完成？
 |   |
 |   Yes → 不要用它，自己敲更快
 |   |
 |   No
 |   |
 +-- 这个任务需要 10 分钟 ~ 2 小时？
     |
     Yes → 用它，效率能翻 3-5 倍
     |
     No
     |
     +-- 这个任务我完全不会？
         |
         Yes → 用它，多轮对话，逐步推进
         |
         No → 混合模式：你设计架构，它写实现细节
```

### 具体场景判断

| 场景 | 建议 | 原因 |
|------|------|------|
| 改一个变量名 | 不用 | 3 秒钟的事，打开 Claude Code 都要 5 秒 |
| 写一个 React 组件 | 用 | 它 5 分钟，你半小时 |
| 设计一个微服务架构 | 你自己来 | AI 不知道你的业务约束 |
| 实现微服务的具体接口 | 用 | 它写 CRUD 很快 |
| 修复一个小 bug | 看情况 | 如果能一眼看出，就自己改；如果要调试，就用它 |
| 写项目文档 | 用 | 它写文档很快，而且格式标准 |
| Code Review | 混合 | 它帮你找问题，你做最终决定 |

## 🎓 学到了什么

1. **Claude Code 是编程搭档，不是魔法** — 给它清晰的指令才有好结果
2. **它最擅长的是"有明确目标的编码任务"** — 越具体，效果越好
3. **了解边界比知道能力更重要** — 知道它做不好什么，才能用好它

## ⚠️ 注意

- Claude Code 的能力在不断更新，保持关注官方文档
- 不同模型版本能力有差异，遇到问题先确认版本
- 它是你的工具，不是你的替代品
