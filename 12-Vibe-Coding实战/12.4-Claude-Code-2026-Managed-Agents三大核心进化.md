# 12.4 Claude Code 2026 Managed Agents 三大核心进化

> 2026 年 5 月，Anthropic 为 Claude Code 的 Managed Agents 带来了三项核心进化：**Dreaming（复盘学习）**、**Outcomes（结果评估）**和 **Multi-agent Orchestration（多智能体编排）**。这标志着 Claude Code 从"单兵作战"正式进化为"团队智能协作"。

---

## 核心概念：Managed Agents 架构

Claude Code 的架构分为四层：

| 层级 | 名称 | 功能 |
|------|------|------|
| **第一层** | 用户交互 | 终端 CLI、VSCode/JetBrains 插件、Remote Control 远程会话、`claude ultrareview` 命令 |
| **第二层** | 运行时与编排 | **Managed Agents**（本次更新的核心） |
| **第三层** | 能力模块 | Skills、MCP 服务器、Hooks、Plugins |
| **第四层** | 模型核心 | Claude Sonnet 4.6 / Opus 4.6 |

**第二层（运行时与编排）**是 2026 年变化最大的一层，新增了三个重磅功能：

1. **Multi-Agent Orchestration（多智能体编排）**
2. **Dreaming（复盘学习）**
3. **Outcomes（结果评估）**

## 案例 1：Multi-Agent Orchestration（多智能体编排）

### 问题场景

以前，如果你有一个复杂任务（例如"开发一个完整的用户管理系统"），Claude Code 只能**单线程**处理：

**传统做法**（单线程，慢）：

```
你: 开发一个完整的用户管理系统，包括注册、登录、权限管理

Claude: 好的，我先实现用户注册功能...
（等待 5 分钟）
Claude: 注册功能完成了，现在开始登录功能...
（等待 5 分钟）
Claude: 登录功能完成了，现在开始权限管理...
（等待 10 分钟）
...
```

**痛点**：
- 大任务需要**顺序执行**，耗时长
- Claude 只能**一次处理一个子任务**
- 无法并行利用多个 Agent 的计算能力

---

### Claude Code 做法（使用 Multi-Agent Orchestration）

2026 年 5 月，Claude Code 新增 **Multi-Agent Orchestration（多智能体编排）** 功能。

**核心原理**：
- **Lead Agent（领导智能体）**：负责理解任务、拆解子任务、分配给 Specialist Agent
- **Specialist Agent（专家智能体）**：负责执行具体的子任务，最多支持 **20 个并行**
- **Task List（任务列表）**：Lead Agent 拆解的子任务列表
- **Mailbox（邮箱）**：Agent 之间通信的媒介

#### 第一步：Lead Agent 拆解任务

当你输入一个复杂任务时，Lead Agent 会自动拆解成多个子任务：

**示例任务**：

```
你: 开发一个完整的用户管理系统，包括：
  1. 用户注册（前端表单 + 后端 API）
  2. 用户登录（JWT 认证）
  3. 权限管理（RBAC）
  4. 单元测试（覆盖率 > 80%）
```

**Lead Agent 拆解结果**：

```
任务拆解完成！共 4 个子任务：

子任务 1: 用户注册前端表单
  - 负责人: Specialist Agent 1
  - 依赖: 无
  - 状态: 等待执行

子任务 2: 用户注册后端 API
  - 负责人: Specialist Agent 2
  - 依赖: 子任务 1 完成
  - 状态: 等待执行

子任务 3: 用户登录（JWT 认证）
  - 负责人: Specialist Agent 3
  - 依赖: 子任务 2 完成
  - 状态: 等待执行

子任务 4: 权限管理（RBAC）
  - 负责人: Specialist Agent 4
  - 依赖: 子任务 3 完成
  - 状态: 等待执行

子任务 5: 单元测试
  - 负责人: Specialist Agent 5
  - 依赖: 子任务 1-4 全部完成
  - 状态: 等待执行
```

#### 第二步：并行执行子任务

Lead Agent 会根据**依赖关系**，并行分配给最多 20 个 Specialist Agent：

```
Lead Agent: 开始执行任务...

分配给 Specialist Agent 1: 用户注册前端表单
分配给 Specialist Agent 2: 用户注册后端 API
（等待子任务 1 和 2 完成）
分配给 Specialist Agent 3: 用户登录（JWT 认证）
（等待子任务 3 完成）
分配给 Specialist Agent 4: 权限管理（RBAC）
（等待子任务 4 完成）
分配给 Specialist Agent 5: 单元测试
```

**关键**：
- **无依赖的子任务**可以**并行执行**（例如子任务 1 和 2 可以同时进行）
- **有依赖的子任务**必须**顺序执行**（例如子任务 3 必须等待子任务 2 完成）

#### 第三步：Agent 之间通信

Specialist Agent 之间可以通过 **Mailbox（邮箱）** 互相通信：

**示例**：

```
Specialist Agent 1 (前端): 我已经完成了注册表单，API 端点是什么？
  → 发送到 Mailbox

Specialist Agent 2 (后端): API 端点是 /api/v1/auth/register，需要 POST 请求
  → 从 Mailbox 读取消息，回复

Specialist Agent 1 (前端): 收到！
  → 继续工作
```

### 基本用法

#### 1. 自动模式（默认）

直接输入复杂任务，Lead Agent 会自动拆解并分配给 Specialist Agent：

```
你: 开发一个完整的用户管理系统，包括注册、登录、权限管理
```

Claude Code 会自动：
1. Lead Agent 拆解任务
2. 分配给 Specialist Agent
3. 并行执行
4. 汇总结果

#### 2. 手动模式（高级）

如果你想要更多控制，可以手动指定哪些子任务并行、哪些顺序：

```
你: /orchestrate
  task: 用户注册前端表单
  task: 用户注册后端 API
  depends: 任务1
  task: 用户登录
  depends: 任务2
  parallel: 任务1, 任务2
```

#### 3. 查看任务状态

```
你: /orchestrate status
```

会显示：

```

claude "为所有模块写单元测试"

**Claude Code 做法**（并行，快）：

```

  1. 用户注册（前端表单 + 后端 API）

1. Lead Agent 拆解为 5 个子任务

### 注意事项

| 问题 | 解决方案 |
|------|----------|
| **文件冲突** | Lead Agent 会自动检测文件冲突，避免多个 Agent 同时修改同一个文件 |
| **Token 消耗** | Token 消耗随 Agent 数量线性增长，需权衡效率与成本 |
| **依赖关系** | Lead Agent 会自动分析依赖关系，确保任务按正确顺序执行 |
| **通信开销** | Agent 之间的 Mailbox通信会有一定开销，但远低于串行执行的等待时间 |
