# 12.3 Claude Code 2026-05 最新功能：Agent View 与 /goal

> 2026年5月12日，Anthropic 为 Claude Code 发布了两个重磅功能：Agent View（集中指挥舱）和 /goal（结果驱动的自动任务）。这标志着 Claude Code 从"单任务助手"正式进化为"多任务调度中心"。

---

## 案例 1：使用 Agent View 管理多任务（2026-05-12 新增）

### 问题场景

以前，如果你想让 Claude Code 同时处理多个任务，你需要：
- 打开多个终端标签页
- 或者用 tmux 开多个窗口
- 来回切换查看每个任务的进度
- 哪个任务需要你的反馈？哪个完成了？一片混乱

**传统做法**（混乱的多任务管理）：

```bash
# 终端标签 1：处理任务 A
claude "实现用户登录功能"

# 终端标签 2：处理任务 B
claude "编写 API 文档"

# 终端标签 3：处理任务 C
claude "修复测试失败"

# ... 来回切换，眼花缭乱
```

**痛点**：
- 不知道哪个任务在等待你的权限审批
- 不知道哪个任务已经完成
- 不知道哪个任务卡住了
- 切换上下文成本高

---

### Claude Code 做法（使用 Agent View）

2026 年 5 月 12 日，Claude Code 正式上线 **Agent View** 功能——一个内置的任务面板，允许开发者在同一个终端窗口里**调度、后台挂起和统一管理多个并行的 AI 编程代理**。

#### 第一步：启动后台任务

有两种方式启动后台任务：

**方式 A：直接用 `claude --bg` 启动新后台任务**

```bash
claude --bg "为所有 API 端点添加输入验证"
```

**方式 B：用 `/bg` 指令把当前会话推到后台**

```bash
# 在 Claude Code 会话中
/ bg "继续完成这个任务，我稍后查看"
```

#### 第二步：打开 Agent View 查看所有任务

按下 **左方向键** 或输入 `claude agents`，终端会切出全局列表，展示：

| 信息 | 说明 |
|------|------|
| **任务名称/描述** | 每个任务的简要描述 |
| **当前状态** | 等待中 / 进行中 / 已完成 / 需要反馈 |
| **最后一次回复** | 任务的最新进展 |
| **闲置时间** | 任务已经多久没有活动 |

**示例 Agent View 界面**：

```
┌─────────────────────────────────────────────────────────┐
│  Claude Code - Agent View                              │
├─────────────────────────────────────────────────────────┤
│  🟢 后台任务 1: "添加输入验证"                         │
│     状态: 进行中                                         │
│     最后回复: 正在修改 user.py...                       │
│     闲置: 5 秒                                           │
│                                                          │
│  🟡 后台任务 2: "编写 API 文档"                        │
│     状态: 等待权限批准                                   │
│     最后回复: 需要权限编辑 docs/api.md                   │
│     闲置: 2 分钟                                         │
│                                                          │
│  ✅ 后台任务 3: "修复测试失败"                         │
│     状态: 已完成                                         │
│     最后回复: 所有测试通过                               │
│     闲置: 10 分钟                                        │
└─────────────────────────────────────────────────────────┘
```

#### 第三步：原地回复等待中的任务

如果某个代理卡在等指令（比如需要你的权限批准，或者需要你提供更多信息），你可以**在不切入完整会话的情况下直接在面板里原地回复**。

**示例**：

```
任务 2 需要权限批准：是否允许编辑 docs/api.md？
> 输入 /allow 批准
> 输入 /deny 拒绝
> 输入具体指令继续任务
```

#### 第四步：管理任务

| 命令 | 功能 |
|------|------|
| `claude agents` | 打开 Agent View |
| `/bg` | 把当前会话推到后台 |
| `claude --bg [task]` | 直接启动新的后台任务 |
| 左方向键 | 打开/关闭 Agent View |
| `/allow` | 批准等待中的权限请求 |
| `/deny` | 拒绝等待中的权限请求 |

---

### 实战案例：并行开发功能 + 写文档 + 修 Bug

**场景**：你有一个星期要上线，需要同时：
1. 实现用户注册功能
2. 编写 API 文档
3. 修复一个紧急 Bug

**传统做法**（串行，慢）：

```bash
# 第 1 小时：实现注册功能
claude "实现用户注册功能"
# ... 等待完成 ...

# 第 2 小时：写文档
claude "编写 API 文档"
# ... 等待完成 ...

# 第 3 小时：修 Bug
claude "修复登录验证的 Bug"
# ... 等待完成 ...
```

**Claude Code 做法**（并行，快）：

```bash
# 终端 1：启动任务 1（后台）
claude --bg "实现用户注册功能"

# 终端 2：启动任务 2（后台）
claude --bg "编写 API 文档"

# 终端 3：启动任务 3（后台）
claude --bg "修复登录验证的 Bug"

# 打开 Agent View 查看所有任务进度
claude agents
```

**优势**：
- 三个任务**同时推进**，节省 2/3 的时间
- 随时查看进度，不需要来回切换
- 哪个任务需要你反馈，一目了然

## 案例 2：使用 /goal 实现结果驱动的任务（2026-05-12 新增）

### 问题场景

以前，你让 Claude Code 做一个大任务，它可能会：
- 做一轮就停下来等你确认
- 做到一半"忘记"了最终目标
- 需要你不断输入"继续"才能持续推进

**传统做法**（需要不断监督）：

```
你: 修复本项目所有代码风格问题
Claude: 已修复 5 个文件，是否继续？
你: 继续
Claude: 又修复了 3 个文件，是否继续？
你: 继续
Claude: ...
（你需要不断监督，不断输入"继续"）
```

**痛点**：
- 大任务需要多轮对话，你需要不断监督
- Claude 可能做到一半就停下来
- 你不知道任务什么时候真正完成

---

### Claude Code 做法（使用 /goal）

2026 年 5 月 12 日，Claude Code 新增 **/goal** 命令，彻底改变了你与 AI 的协作方式。

**核心原理**：
- 你设定一个**完成条件**（例如"修复本项目所有代码风格问题"）
- Claude 会**持续工作**（跨多轮对话），直到目标达成
- 界面会实时显示已耗时、对话轮数及 Token 消耗的浮动面板

#### 第一步：设定目标

在 Claude Code 中输入 `/goal` 命令，后面跟上**完成条件**：

```
/goal 修复本项目所有代码风格问题，运行 eslint 不再报错
```

或者更复杂的目标：

```
/goal 把所有 API 端点从 v1 迁移到 v2，确保所有测试通过
```

#### 第二步：Claude 自动执行，直到目标达成

输入 `/goal` 后，Claude 立刻开始干活。系统会：

1. **执行一轮任务**（例如运行 eslint，修复报错）
2. **自动检查目标是否达成**（运行 eslint，看是否还有报错）
3. **如果没达成** → 继续下一轮
4. **如果达成了** → 自动停止

**关键**：每一轮结束后，系统会用一个**小模型（默认 Haiku）评估条件是否满足**，给出一个简短的 reason（评估理由）。

#### 第三步：查看目标状态面板

运行过程中，界面上会显示一个 **/goal active** 的状态面板：

```
┌─────────────────────────────────────────────────────────┐
│  /goal active                                           │
├─────────────────────────────────────────────────────────┤
│  目标: 修复本项目所有代码风格问题                         │
│                                                          │
│  已运行时间: 00:05:23                                   │
│  轮次数: 3                                              │
│  Token 消耗: 12,345                                     │
│                                                          │
│  最新评估: 还有 3 个文件的 eslint 报错未修复             │
│  状态: 继续工作中...                                     │
└─────────────────────────────────────────────────────────┘
```

#### 第四步：查看评估结果

每一轮结束后，系统会用小模型评估，你可以在状态面板和对话记录里看到评估理由（reason）：

```
评估轮次 1:
  reason: "eslint 还有 15 个报错，目标未达成"
  结果: 继续下一轮

评估轮次 2:
  reason: "eslint 还有 8 个报错，目标未达成"
  结果: 继续下一轮

评估轮次 3:
  reason: "eslint 还有 3 个报错，目标未达成"
  结果: 继续下一轮

评估轮次 4:
  reason: "eslint 无报错，目标达成！"
  结果: 自动停止
```

---

### 基本用法

#### 1. 设定目标

```
/goal <完成条件>
```

**示例**：

```
/goal 修复本项目所有代码风格问题，运行 eslint 不再报错
/goal 把所有 API 端点从 v1 迁移到 v2，确保所有测试通过
/goal 实现用户注册功能，包括前端表单、后端 API、数据库迁移
/goal test/auth 下所有测试通过，lint 干净
```

#### 2. 查看当前目标状态

```
/goal
```

会显示：
- 目标描述
- 已运行时间
- 对话轮次
- Token 消耗
- 最新的评估理由

#### 3. 清除目标（停止任务）

```
/goal clear
```

或者：

```
/goal stop
/goal off
/goal reset
/goal cancel
```

#### 4. 跨会话恢复目标

```
/goal --resume
```

**场景**：你设定了一个目标，然后关闭了 Claude Code。第二天打开，可以用 `/goal --resume` 恢复昨天的目标，继续工作。

### 非交互模式（CI 管道中使用）

你可以在非交互模式下使用 `/goal`，直接接进 CI 管道里用：

```bash
claude -p "/goal CHANGELOG.md 里有本周每个合并 PR 的记录"
```

**适用场景**：
- CI 管道中自动生成 CHANGELOG
- 定时任务（例如每天凌晨自动修复代码风格问题）
- 自动化测试流程

### 官方推荐适用场景

根据 Anthropic 官方文档，以下场景非常适合用 `/goal`：

| 场景 | 示例目标 |
|------|----------|
| **迁移任务** | 把一个模块迁移到新 API，直到所有调用点编译通过、测试全过 |
| **功能实现** | 按照设计文档实现功能，直到所有验收标准满足 |
| **重构任务** | 把一个大文件拆成聚焦的小模块，直到每个文件都在大小限制内 |
| **清理任务** | 清理 issue 列表，直到队列为空 |
| **测试任务** | 让所有测试通过，lint 干净 |
| **文档任务** | 生成 CHANGELOG.md，包含本周所有合并 PR 的记录 |

**核心特点**：**有明确终态的、可验证的大任务**，就可以用 `/goal`。

### 实战案例：自动修复所有 ESLint 报错

**场景**：你的项目有 50 个 ESLint 报错，一个个修太慢了。

**传统做法**（手动修复）：

```bash
# 运行 eslint
npx eslint src/

# 看到 50 个报错...
# 手动修复...
# 再运行 eslint
npx eslint src/

# 看到 30 个报错...
# 手动修复...
# ...（重复很多次）
```

**Claude Code 做法**（使用 /goal）：

```
/goal 修复本项目所有 ESLint 报错，运行 npx eslint src/ 不再报错
```

Claude 会：
1. 运行 `npx eslint src/`，查看所有报错
2. 自动修复第一批报错
3. 再次运行 `npx eslint src/`，检查是否还有报错
4. 如果有，继续修复；如果没有，自动停止
5. 你可以在状态面板看到实时进度

**最终输出**：

```
✅ 目标达成！

已修复 50 个 ESLint 报错：
- 20 个: 缺少分号
- 15 个: 未使用的变量
- 10 个: 缩进错误
- 5 个: 引号风格不一致

运行 npx eslint src/ 确认无报错。
```

**场景**：你需要把项目的所有 API 端点从 v1 迁移到 v2。

**目标**：

```
/goal 把所有 API 端点从 /api/v1/ 迁移到 /api/v2/，确保：
1. 所有后端路由已更新
2. 所有前端 API 调用已更新

5. 直到所有测试通过，自动停止

**最终输出**：

```
✅ 目标达成！

运行 npm test 确认无失败。

## 案例 3：System Prompt Compaction（系统提示压缩）

### 问题场景

你有一个长时间运行的会话（比如重构一个大模块），突然发现 Claude 开始：
- "忘记"早期的指令
- 回复质量下降
- 响应变慢

这是因为**上下文窗口满了**，Claude 无法有效处理所有历史信息。

**传统做法**（重新开始）：

```
你: 你怎么忘记了我之前说的架构约束？
Claude: 抱歉，让我重新...
（上下文窗口已满，质量下降）
```

---

### Claude Code 做法（System Prompt Compaction）

2026 年 5 月，Claude Code 新增 **System Prompt Compaction**（系统提示压缩）功能，为长期会话做的"保鲜剂"。

**核心原理**：
- 当上下文窗口接近满载时，Claude Code 会自动"压缩"早期的对话历史
- 保留关键信息（你的指令、重要决策、代码结构）
- 丢弃不重要的细节（闲聊、重复内容）
- 让会话"继续"而不丢失关键上下文

#### 第一次：会话接近上下文限制时

你会看到提示：

```
⚠️  上下文窗口即将满载。
是否压缩历史对话以继续？

[ y ] 是，压缩并继续
[ n ] 否，开始新会话
```

**建议**：输入 `y`，让 Claude Code 自动压缩历史，继续工作。

#### 第二次及之后：自动压缩

如果你选择了压缩，后续当上下文再次接近满载时，Claude Code 会**自动压缩**，不再询问。

---

### 实战技巧：如何写出"可压缩"的指令

为了让 System Prompt Compaction 更有效，你需要确保**关键信息写在文件中**，而不是只说在对话里。

#### ❌ 不好的做法（只说在对话里）

```
你: 记得用 ES modules，别用 CommonJS
你: 我们的数据库用 PostgreSQL
你: API 风格要 RESTful
（这些信息只在对话历史里，压缩后可能丢失）
```

#### ✅ 好的做法（写在文件里）

```markdown
# CLAUDE.md

## 技术栈
- 使用 ES modules (import/export)，不用 CommonJS
- 数据库: PostgreSQL
- API 风格: RESTful

## 代码规范
- 缩进: 2 空格
- 引号: 单引号
- 分号: 必须
```

（这些信息在文件里，压缩后不会丢失）

---

### 什么时候应该手动开始新会话？

虽然 System Prompt Compaction 很好用，但以下场景建议**手动开始新会话**：

| 场景 | 原因 |
|------|------|
| 切换了任务类型 | 例如从"实现功能"切换到"调试 Bug" |
| 上下文已经被"污染" | 早期指令已经不适用了 |
| 需要"全新开始" | 例如尝试不同的架构方案 |

**操作**：

```bash
/compact
```

或者干脆：

```bash
/clear
```

## 总结：2026-05 最新功能清单

### ✅ Agent View（集中指挥舱）

**核心能力**：
- 在一个界面中监控和管理多个 AI 会话
- 使用 `claude --bg [task]` 直接派一个新代理去后台工作
- 使用 `/bg` 指令把当前会话推到后台
- 按左方向键或输入 `claude agents` 打开全局列表
- 展示每个任务的当前状态、最后一次回复和闲置时间
- 可以在不切入完整会话的情况下直接在面板里原地回复

**适用场景**：
- 并行开发多个功能
- 同时处理编程 + 文档 + 测试
- 需要统一监控多个 Agent 的进度

---

### ✅ /goal（结果驱动的自动任务）

**核心能力**：
- 设定一个完成条件，Claude 持续工作直到目标达成
- 每完成一轮，系统自动判断目标是否达成
- 没达成 → 继续下一轮；达成了 → 自动停止
- 使用小模型（默认 Haiku）评估条件是否满足
- 界面实时显示已耗时、对话轮数及 Token 消耗

**适用场景**：
- 有明确终态的、可验证的大任务
- 迁移任务（例如 API 版本迁移）
- 重构任务（例如拆分大文件）
- 清理任务（例如修复所有 eslint 报错）
- 测试任务（例如让所有测试通过）

---

### ✅ System Prompt Compaction（系统提示压缩）

**核心能力**：
- 当上下文窗口接近满载时，自动"压缩"早期的对话历史
- 保留关键信息，丢弃不重要的细节
- 让会话"继续"而不丢失关键上下文
- 第一次会询问是否压缩，之后自动压缩

**最佳实践**：
- 把关键信息写在 CLAUDE.md 或其他文件中
- 不要只说在对话里，压缩后可能丢失
- 切换任务类型时，建议手动开始新会话
