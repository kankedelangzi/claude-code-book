# 12.5 官方插件实战：用 Anthropic 官方插件扩展 Claude Code

> Claude Code 2.1.152+ 引入了官方插件系统，Anthropic 在 GitHub 仓库中内置了十几个高质量官方插件。本章基于 **Claude Code v2.1.153 CHANGELOG** 和 **官方 plugins 目录**的真实资料，带你逐个实战这些插件。

---

## 什么是 Claude Code 插件

插件（Plugin）是 Claude Code 的扩展机制，可以在不修改核心代码的情况下，为 Claude Code 添加：

- **自定义 Slash 命令**（如 `/code-review`、`/feature-dev`）
- **专用 Agent**（如代码审查 Agent、架构设计 Agent）
- **Hook 事件处理**（在会话启动、工具调用前后自动执行逻辑）
- **MCP 服务器配置**（连接外部工具）

官方插件全部开源，位于：[github.com/anthropics/claude-code/tree/main/plugins](https://github.com/anthropics/claude-code/tree/main/plugins)

## 插件安装方法

### 方法一：使用 `/plugin` 命令（推荐）

```bash
# 在 Claude Code 会话中直接安装
/plugin marketplace add https://github.com/anthropics/claude-code

# 浏览可用插件
/plugin marketplace list

# 安装指定插件（如 code-review）
/plugin install code-review
```

### 方法二：手动配置 `.claude/settings.json`

```json
{
  "plugins": [
    {
      "name": "code-review",
      "source": "github:anthropics/claude-code/plugins/code-review"
    }
  ]
}
```

### 方法三：`/reload-skills` 刷新（v2.1.152+）

安装插件后，无需重启会话，直接运行：

```bash
/reload-skills
```

> **新功能（v2.1.152）**：`/reload-skills` 命令可以重新扫描 skill 目录，让新安装的插件立即生效。

## 案例 1：`code-review` — 多 Agent 并行 PR 代码审查

### 问题场景

传统代码审查的痛点：

- **人工审查慢**：一个中等 PR 需要 30-60 分钟
- **容易漏掉问题**：疲劳导致漏看边界条件、安全漏洞
- **主观性强**：不同 reviewer 关注点不同，质量不稳定

### 解决方案：用 `code-review` 插件自动审查

#### 安装

```bash
/plugin install code-review
```

#### 使用

```bash
# 审查当前分支相对于 main 的所有变更
/code-review

# v2.1.152+：审查后自动修复发现的问题
/code-review --fix
```

#### 工作原理

`code-review` 插件启动 **5 个并行 Sonnet Agent**，每个负责不同维度：

| Agent | 审查维度 | 输出 |
|-------|----------|------|
| Agent 1 | CLAUDE.md 规范合规性 | 是否遵循项目代码规范 |
| Agent 2 | Bug 检测 | 逻辑错误、边界条件、空指针等 |
| Agent 3 | 历史上下文 | 结合 Git 历史判断改动意图是否合理 |
| Agent 4 | PR 历史 | 参考同类 PR 的审查意见 |
| Agent 5 | 代码注释质量 | 注释是否准确、完整 |

每个 Agent 给出**置信度评分**（0-100），最终汇总时过滤掉低置信度的误报。

#### 实际输出示例

```
🔍 正在启动代码审查...（5 个 Agent 并行分析中）

✅ Agent 1（规范合规）：置信度 92
   - 建议：新增函数缺少 JSDoc 注释（第 47 行）

✅ Agent 2（Bug 检测）：置信度 88
   - 问题：handleLogin() 未处理 Email 为空的情况（第 82 行）
   - 建议：添加 if (!email) return res.status(400).json(...)

⚠️ Agent 3（历史上下文）：置信度 45（已过滤）
   - 低置信度建议已忽略

📊 审查完成！发现 2 个高置信度问题，1 个建议优化。
```

#### v2.1.152 新功能：`/code-review --fix` 自动修复

```bash
# 审查完成后自动将建议应用到工作区
/code-review --fix
```

Claude Code 会：
1. 重新读取审查结果
2. 对高置信度的"复用、简化、效率"类建议，直接修改代码
3. 展示 diff 供你确认

> **Tips**：`/simplify` 命令现在也调用 `/code-review --fix`，一键简化代码。

## 案例 2：`feature-dev` — 7 阶段结构化功能开发

### 问题场景

让 Claude Code "开发一个用户管理模块"时，如果没有结构化引导，可能会出现：

- **需求理解偏差**：没搞清楚边界条件就开始写
- **架构不合理**：文件组织混乱，后期难以维护
- **遗漏边界情况**：只实现了 happy path，错误处理缺失

### 解决方案：`feature-dev` 插件的 7 阶段工作流

#### 安装与使用

```bash
/plugin install feature-dev

# 启动引导式功能开发
/feature-dev
```

#### 7 个阶段详解

| 阶段 | 名称 | 内容 |
|------|------|------|
| 1 | 需求澄清 | Claude 主动问你 3-5 个关键问题，确认需求边界 |
| 2 | 代码库分析 | `code-explorer` Agent 扫描相关文件，理解现有架构 |
| 3 | 架构设计 | `code-architect` Agent 输出实现方案（文件结构、接口设计） |
| 4 | 方案确认 | 展示架构方案，等你确认后再动手 |
| 5 | 编写代码 | 按方案逐项实现，每完成一个文件展示 diff |
| 6 | 质量审查 | `code-reviewer` Agent 自动审查实现代码 |
| 7 | 测试验证 | 生成测试用例，运行并修复失败 |

#### 实际对话示例

```bash
你: /feature-dev

Claude: 好的，我们按 7 个阶段来开发。先确认需求：
  1. 用户管理模块需要支持哪些操作？（CRUD？批量导入？）
  2. 认证方式？（JWT？Session？）
  3. 权限分级？（管理员/普通用户？）
  
你: 1. CRUD + 批量导入；2. JWT；3. 管理员/普通用户两级的方案

Claude: 明白了。正在分析代码库...
  [code-explorer Agent] 发现：项目使用 Express + Prisma，
  用户表已存在（models/User.js），认证中间件在 middlewares/auth.js

Claude: 架构方案：
  - 新增 routes/userRoutes.js（CRUD 接口）
  - 扩展 middlewares/auth.js（增加角色校验）
  - 新增 services/userService.js（业务逻辑）
  - 新增 __tests__/userService.test.js（测试用例）
  
  确认后我开始写代码？（y/n）

你: y

Claude: [开始编写代码...]
  ✅ routes/userRoutes.js 完成（diff 展示）
  ✅ services/userService.js 完成
  ✅ 扩展 middlewares/auth.js 完成
  
  [code-reviewer Agent] 审查完成：发现 1 个建议（第 34 行建议加 rate limiting）
  
  是否修复？（y/n）
```

## 案例 3：`security-guidance` — 编辑时自动检测安全漏洞

### 问题场景

写代码时无意中引入了安全漏洞：

- 用 `eval()` 解析用户输入 → 代码注入
- 直接拼接 SQL 查询 → SQL 注入
- 没有转义就渲染用户内容 → XSS

### 解决方案：`security-guidance` Hook 插件

#### 安装

```bash
/plugin install security-guidance
```

#### 工作原理

该插件注册了一个 **`PreToolUse` Hook**，在 Claude Code 每次**即将编辑文件之前**自动运行，检测 9 种危险模式：

| 危险模式 | 说明 |
|----------|------|
| `eval()` / `Function()` | 代码注入 |
| 未转义的 HTML 渲染 | XSS 跨站脚本 |
| `pickle.loads()` | Python 反序列化攻击 |
| `os.system()` / `subprocess()` 未转义参数 | 命令注入 |
| SQL 字符串拼接 | SQL 注入 |
| 硬编码密钥/密码 | 凭证泄露 |
| 不安全的反序列化 | 对象注入 |
| 路径拼接未校验 | 路径遍历 |
| 未校验的重定向 | Open Redirect |

#### 实际效果

```bash
你: 帮我写一个根据用户输入执行动态表达式的函数

Claude: 好的，我来写一个...
  [正在编辑 utils/evalHelper.js...]
  
  ⚠️  Security Warning（security-guidance 插件）
  Hook 检测到危险模式：eval() 使用
  文件：utils/evalHelper.js，第 5 行
  建议：使用 AST 解析器（如 acorn）替代 eval()
  
  是否继续？（y/n/skip）
```

#### 自定义规则

在项目根目录创建 `.claude/security-rules.json`：

```json
{
  "rules": [
    {
      "pattern": "eval\\(",
      "message": "禁止使用 eval()，请用 JSON.parse 或 acorn 替代",
      "severity": "error"
    }
  ]
}
```

## 案例 4：`hookify` — 自动生成 Hook 规则防止不良行为

### 问题场景

你发现 Claude Code 经常犯某些错误：

- 每次都忘记添加错误处理
- 生成的代码不遵循你的命名规范
- 喜欢用 `any` 类型（TypeScript）

手动写 Hook 规则很麻烦，需要理解 Hook 系统的 JSON 格式。

### 解决方案：`hookify` 插件自动分析并生成规则

#### 安装与使用

```bash
/plugin install hookify

# 分析当前会话，自动生成 Hook 规则
/hookify

# 查看已生成的规则
/hookify:list

# 配置规则生效范围（session/project/global）
/hookify:configure
```

#### 工作原理

1. `conversation-analyzer` Agent **分析当前会话**的对话历史
2. 识别出 Claude 反复犯的错误模式
3. 自动生成对应的 **Hook 规则**（`settings.json` 中的 `hooks` 配置）
4. 下次会话启动时，这些规则自动生效

#### 实际示例

```bash
你: /hookify

Claude: [conversation-analyzer Agent 分析中...]
  发现 3 个可改进的行为模式：
  
  1. Claude 在 5 次代码生成中，3 次使用了 `any` 类型
     → 建议添加 Hook 规则：禁止 `any`，强制使用具体类型
  
  2. Claude 生成的 TypeScript 文件缺少 JSDoc 注释（8 次）
     → 建议添加 Hook 规则：新文件必须包含文件头注释
  
  3. Claude 在 API 路由中没有添加 rate limiting（3 次）
     → 建议添加 Hook 规则：包含 'router.' 的文件必须调用 rateLimit()
  
  是否应用这些规则？（y/n）
```

## 案例 5：`ralph-wiggum` — 自主迭代循环

### 问题场景

有些任务需要**反复迭代**才能达到满意效果：

- 写一篇文档，第一版不够好，需要反复修改
- 生成一个 UI 组件，样式需要多次调整
- 优化一段代码性能，需要多次 profiling

每次都要手动说"再改改"，很烦。

### 解决方案：`ralph-wiggum` 插件自主迭代

#### 安装与使用

```bash
/plugin install ralph-wiggum

# 启动自主迭代循环（默认最多 5 次）
/ralph-loop "优化这段代码的性能，直到 benchmark 提升不超过 5%"

# 中断循环
/cancel-ralph
```

#### 工作原理

1. Claude 完成第一次尝试
2. **`Stop` Hook** 拦截"会话结束"信号
3. 自动评估当前结果是否满足退出条件
4. 如果不满足，自动继续下一轮迭代
5. 达到退出条件或最大次数后停止

#### 实际示例

```bash
你: /ralph-loop "为这个排序函数实现最快的算法，直到性能提升小于 3%"

Claude: 第 1 次迭代：实现快速排序
  基准测试：平均 120ms（10000 个元素）
  
  [Stop Hook 拦截：性能提升空间仍大于 3%，继续迭代]
  
Claude: 第 2 次迭代：改为堆排序 + 手写分区函数
  基准测试：平均 85ms
  
  [Stop Hook 拦截：性能提升 29% > 3%，继续迭代]
  
Claude: 第 3 次迭代：引入 Introsort（混合排序）
  基准测试：平均 62ms
  
  [Stop Hook 评估：性能提升 27% > 3%，继续迭代]
  
Claude: 第 5 次迭代：已尝试 5 种算法，当前实现为 Introsort
  性能提升小于 3%，停止迭代。
  
  最终代码已写入 sort.js。
```

## 案例 6：`pr-review-toolkit` — 专项 PR 审查

### 问题场景

`code-review` 插件做通用审查，但有时你只关心**某一个维度**，比如：

- "这个 PR 的错误处理是否完整？"
- "类型设计是否合理？"
- "代码能否进一步简化？"

### 解决方案：`pr-review-toolkit` 插件的专项审查

#### 安装与使用

```bash
/plugin install pr-review-toolkit

# 审查 PR 的注释质量
/pr-review-toolkit:review-pr comments

# 审查测试覆盖率
/pr-review-toolkit:review-pr tests

# 审查错误处理
/pr-review-toolkit:review-pr errors

# 审查类型设计
/pr-review-toolkit:review-pr types

# 审查代码简化机会
/pr-review-toolkit:review-pr simplify

# 全部维度
/pr-review-toolkit:review-pr all
```

#### 专项 Agent 详解

| 命令 | Agent | 审查内容 |
|------|-------|----------|
| `comments` | `comment-analyzer` | 注释是否准确、完整、有用 |
| `tests` | `pr-test-analyzer` | 测试覆盖率、边界情况、mock 合理性 |
| `errors` | `silent-failure-hunter` | 静默失败、未捕获异常、错误处理完整性 |
| `types` | `type-design-analyzer` | 类型设计合理性（TS/Python 泛型等） |
| `code` | `code-reviewer` | 通用代码质量 |
| `simplify` | `code-simplifier` | 是否有冗余逻辑、可简化表达式 |

## v2.1.152/v2.1.153 插件相关新功能汇总

### 1. `disallowed-tools` 前置拦截（v2.1.152）

Skills 和 Slash Commands 现在可以在 frontmatter 中声明 `disallowed-tools`，在该 Skill/命令生效期间**禁用指定工具**：

```yaml
---
name: read-only-review
description: 只做代码审查，不修改任何文件
disallowed-tools: [Edit, Write, Bash]
---
```

### 2. `MessageDisplay` Hook（v2.1.152）

新增 `MessageDisplay` Hook 事件，可以在消息**显示给用户之前**进行转换或隐藏：

```json
{
  "hooks": {
    "MessageDisplay": {
      "command": "python3 .claude/hooks/filter.py"
    }
  }
}
```

用途：
- 过滤敏感信息（如 API Key）后再显示
- 将技术术语替换为更友好的表达
- 在团队环境中统一输出风格

### 3. `pluginSuggestionMarketplaces` 管理员管控（v2.1.152）

企业管理员可以通过 managed settings 配置 `pluginSuggestionMarketplaces`，**只允许指定的插件市场**出现在上下文感知提示中：

```json
{
  "pluginSuggestionMarketplaces": ["github:your-org/claude-plugins"]
}
```

### 4. 背景 Agent 权限持久化（v2.1.153）

macOS 上，背景 Agent 现在在"隐私与安全"中显示为 **"Claude Code"**，并且**升级后权限授权不会丢失**（以前每次升级都要重新授权）。
