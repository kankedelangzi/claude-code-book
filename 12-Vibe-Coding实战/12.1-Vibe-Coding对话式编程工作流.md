# 12.1 Vibe Coding 对话式编程工作流

> **案例背景**：2026 年，Vibe Coding（对话式编程）已成为 AI 辅助编程的主流范式。根据最新行业报告，91% 的工程团队已在日常开发中使用 Vibe Coding。本章通过完整实战案例，展示如何用 Claude Code 实践 Vibe Coding——从需求描述到可运行应用，全程由对话流驱动，你负责「要什么」，AI 负责「怎么写」。

---

## 什么是 Vibe Coding？

**Vibe Coding** 是一种全新的编程范式：你用自然语言描述意图，AI 生成代码，你审查结果、给出反馈、推进方向。整个编码过程是一条**连续的对话流**，而不是一堆孤立的问答。

### 核心理念

```
传统编程：你想 → 你写代码 → 你调试 → 你测试 → 你部署
Vibe Coding：你想 → 你描述 → AI 写代码 → 你审查 → 你反馈 → AI 改进 → 重复
```

Andrej Karpathy（特斯拉前 AI 总监）在 2025 年发推说：

> "我现在写代码时完全不关注语法，只关注想解决什么问题，全靠 AI 生成代码。"

这就是 Vibe Coding 的精髓：**你负责定义「终点」和设立规则，AI 负责修路。**

## Vibe Coding 四大核心原则

### 原则 1：描述意图，而非实现

❌ **错误示例**（关注实现细节，AI 反而容易混乱）：
```
"用 Express 框架创建一个路由 /api/users，
使用 PostgreSQL 数据库连接池，
编写 SQL 查询 SELECT * FROM users WHERE id = $1，
然后用 JSON 格式返回，状态码 200..."
```

✅ **正确示例**（关注意图，让 AI 决定实现）：
```
"创建一个用户查询 API，根据 ID 返回用户信息，JSON 格式"
```

**为什么？** Claude Code 比你更懂实现细节，你只需要说清楚「要什么」，它自动选择最佳实现方式。过度指定实现细节反而限制 AI 的发挥。

### 原则 2：对话流，而非孤立问答

❌ **错误模式**（每次都重新开始，丢失上下文）：
```
你："帮我写一个登录功能"
AI：（生成代码）
你：（复制代码，关闭对话）
（第二天）
你："帮我写一个注册功能"
AI：（不记得昨天的上下文，重新开始）
```

✅ **正确模式**（连续对话流，AI 记住所有上下文）：
```
你："帮我写一个登录功能"
AI：（生成代码，记住你的技术栈和代码风格）
你："好的，现在加一个「记住我」的复选框"
AI：（理解上下文，在同一个文件里修改）
你："再添加一个「忘记密码」的链接，样式和登录页保持一致"
AI：（继续迭代，自动保持风格一致）
你："现在写注册功能，复用登录页的样式和验证逻辑"
AI：（记住之前的样式和验证逻辑，直接复用）
```

**关键**：保持对话连贯，不要频繁开启新会话。Claude Code 的上下文窗口越大，记住的内容越多。

### 原则 3：审查优先，信任但验证

Vibe Coding 不是「全自动编程」，而是「AI 起草，你审查」。

**审查清单**：
- ✅ 逻辑是否正确？（AI 有时会「想当然」地写错业务逻辑）
- ✅ 边界情况是否处理？（空输入、超长字符串、并发竞争等）
- ✅ 错误信息是否友好？（用户能不能看懂报错？）
- ✅ 性能是否有问题？（N+1 查询、无限循环、内存泄漏）
- ✅ 安全隐患是否存在？（SQL 注入、XSS、密钥硬编码）

**技巧**：让 Claude Code 自己审查自己的代码：
```
"帮我审查一下刚才生成的代码，找出可能的安全隐患和性能问题"
```

### 原则 4：迭代改进，小步快跑

不要试图一次性描述完所有需求，而是分阶段推进：

**阶段一（MVP）**：
```
"先做基础 CRUD，能创建和查看任务，不用考虑权限和并发"
```

**阶段二（功能增强）**：
```
"加入拖拽功能，用 HTML5 Drag & Drop API，不需要额外依赖"
```

**阶段三（UI 美化）**：
```
"美化 UI，用 CSS Grid 布局，配色参考 Linear 的设计风格"
```

**阶段四（生产加固）**：
```
"加上错误处理、输入校验、JWT 认证，准备部署到生产环境"
```

## 实战案例二：用 Vibe Coding 写一个算卦平台

本案例基于真实项目（2026 年 5 月 CSDN 博客记录），展示如何用 Claude Code 从零到一构建一个完整的 Web 应用。

### 项目需求

构建一个在线算卦平台：
- 用户输入生辰八字（年、月、日、时）
- 系统自动计算卦象
- 生成卦象解读报告
- 分享功能（生成图片）

### 第一步：启动项目

**你的输入**：
```
创建一个算卦平台，使用 React + TypeScript + Tailwind CSS，
整体风格要神秘、古典，配色用紫色和金色。
```

**Claude Code 的输出**：
```bash
✅ 已创建项目骨架（Vite + React + TypeScript）

✅ 已配置 Tailwind 主题（紫色 + 金色配色）
✅ 开发服务器已启动：http://localhost:5173
```

### 第二步：用 Plan Mode 规划核心功能

复杂功能不要直接让 AI 写代码，容易跑偏。先用 `/plan` 规划。

**你的输入**：
```
/plan 添加用户输入生辰八字的功能，包括：
1. 年、月、日、时的输入框（支持农历选择）
2. 输入验证（必须是有效的生辰八字格式）

```

**Claude Code 的规划输出**：
```markdown
📋 执行计划：

1. 创建 src/components/BaziInput.tsx（生辰八字输入组件）
   - 四个下拉选择器（年/月/日/时）
   - 农历/公历切换
   - Zod 表单校验

2. 创建 src/utils/bazi.ts（八字计算工具函数）
   - 天干地支计算
   - 五行属性映射
   - 卦象生成算法

3. 创建 src/components/ResultDisplay.tsx（结果展示组件）
   - 卦象图 SVG 渲染
   - 解读文字 Markdown 渲染
   - 分享按钮（生成图片）

4. 修改 src/App.tsx（主页面路由）

是否确认执行此计划？(Y/n)
```

**你输入 `Y`，Claude Code 开始执行。**

### 第三步：迭代改进

**第一轮迭代**（样式调整）：
```
把主页面的背景改成渐变紫色，要有星空的感觉，

```

**第二轮迭代**（功能增强）：

**第三轮迭代**（分享功能）：

## Vibe Coding 的进阶技巧

### 技巧 1：用 Plan Mode 处理复杂任务

当你要实现的任务涉及多个文件、复杂逻辑时，**永远先 `/plan`**，确认计划后再执行。

```
/plan 帮我实现用户认证功能：
- JWT 认证
- 登录 / 注册 / 刷新 Token
- 密码 BCrypt 加密
- 中间件保护需要认证的路由
```

Claude Code 会先输出执行计划，你确认后再动手。这能避免 AI 「跑偏」或「过度修改」。

### 技巧 2：用 Sub-Agent 并行处理任务

Claude Code 支持 Sub-Agent（子智能体），可以让多个 Agent 并行处理不同任务。

```
用 Sub-Agent 并行处理以下任务：
- Agent 1：负责样式美化和响应式适配
- Agent 2：负责性能优化（代码分割、懒加载）
- Agent 3：负责添加单元测试
```

**主智能体**保持核心逻辑不变，**子智能体**并行处理各自任务，最后合并结果。效率提升 3-5 倍。

### 技巧 3：用 CLAUDE.md 设定项目规则

在项目根目录创建 `CLAUDE.md`，写入项目级别的指令和约束，Claude Code 每次会话都会自动读取。

```markdown
# CLAUDE.md — 项目规则

## 技术栈
- 前端：React 18 + TypeScript + Tailwind CSS
- 后端：Node.js + Express + SQLite
- 测试：Vitest + React Testing Library

## 代码规范
- 使用函数式组件，不要用 class 组件
- 所有 API 调用必须用 try-catch 包裹
- 错误信息必须是中文，面向最终用户
- 组件命名用 PascalCase，工具函数用 camelCase

## 禁止行为
- 不要使用 any 类型
- 不要直接操作 DOM（用 refs）
- 不要硬编码密钥（用环境变量）
```

**效果**：每次对话，Claude Code 都会遵守这些规则，代码质量更稳定。

### 技巧 4：让 AI 帮你审查代码

不要只让 AI 「写代码」，也要让 AI 「审查代码」。

```
帮我审查 src/utils/bazi.ts 这个文件：
1. 有没有边界情况没处理？
2. 有没有性能问题？
3. 有没有安全隐患？
4. 代码可读性如何？
```

AI 的审查往往比人工更仔细，因为它会逐行分析。

### 技巧 5：用 `/goal` 设定会话目标（2026 年 5 月新功能）

Claude Code 2.1.85+ 支持 `/goal` 命令，可以设定本次会话的目标，AI 会自动跟踪进度。

```
/goal 完成用户管理模块的 CRUD 功能，包括：
1. 创建用户 API
2. 查询用户列表 API
3. 更新用户信息 API
4. 删除用户 API
5. 为每个 API 写单元测试

目标完成前不要停止。
```

AI 会持续工作，直到所有子目标完成，并给出完成报告。

## Vibe Coding 的适用场景与局限

### ✅ 最适合的场景

| 场景 | 原因 |
|------|------|
| **快速原型开发** | 需要快速验证想法，代码质量可以后续优化 |
| **CRUD 接口编写** | 模式固定，AI 非常擅长 |
| **前端组件开发** | UI 渲染逻辑清晰，AI 生成质量高 |
| **单元测试编写** | 基于已有代码生成测试，AI 覆盖率很高 |
| **脚本和工具开发** | 需求明确，代码量少，适合快速生成 |
| **文档和注释编写** | AI 擅长根据代码生成文档 |

### ⚠️ 需要谨慎的场景

| 场景 | 风险 | 建议 |
|------|------|------|
| **高频交易系统** | 性能要求极高，AI 生成的代码可能不够优化 | 人工审查关键路径 |
| **安全敏感功能** | AI 可能引入安全漏洞 | 必须用安全工具扫描 |
| **遗留代码重构** | AI 可能不理解历史上下文 | 先让 AI 分析代码，人工确认后再改 |
| **复杂算法实现** | AI 可能在边界情况出错 | 写大量单元测试验证 |

### ❌ 不适合的场景

- **对性能要求极致的底层系统**（如数据库引擎、游戏引擎）
- **安全核心模块**（如加密算法实现、密钥管理）
- **需要深度领域知识的专业系统**（如医疗设备控制、航空控制系统）

## Vibe Coding 常见问题

### Q1：Claude Code 生成的代码可以直接用于生产环境吗？

**A**：取决于代码类型。CRUD 接口、前端组件、单元测试这类代码，生成质量通常很高，经过基本审查就可以用。但涉及安全、性能、并发的关键代码，必须人工深度审查后再上线。

### Q2：如果 Claude Code 生成的代码有 bug 怎么办？

**A**：把错误信息或异常行为直接告诉 Claude Code，它会分析并修复。大部分情况下，AI 能自己发现并修复 bug，不需要你手动调试。

```
我刚才运行的代码报错了，错误信息如下：
[粘贴错误信息]
帮我分析原因并修复
```

### Q3：Vibe Coding 会让程序员失业吗？

**A**：不会。Vibe Coding 改变的是「怎么写代码」，而不是「写什么代码」。程序员的核心价值从「手写代码」转向「问题分解、架构设计、代码审查、用户体验」——这些能力反而更重要了。

### Q4：如何让 Claude Code 生成更符合我期望的代码？

**A**：三个技巧：
1. **写好 CLAUDE.md**：设定项目规则，让 AI 每次都按你的规范来
2. **给参考示例**：「参考这个文件的风格写新代码」（AI 会读取参考文件）
3. **迭代反馈**：不要期待一次性完美，先让它生成，再逐步调整

## 总结：Vibe Coding 改变的是什么？

Vibe Coding 并不是让 AI 「取代」程序员，而是让程序员从「代码打字员」升级为「软件架构师 + 产品设计师 + 代码审查员」。

**你花时间的地方变了**：
- ❌ 不再：查文档、调语法、改 bug、写样板代码
- ✅ 改为：理解问题、设计方案、审查代码、优化体验

**你的生产力变了**：
- 以前：一天写一个功能
- 现在：一天写一个模块

**你的职业成长路径变了**：
- 以前：深挖语言特性和框架 API
- 现在：深挖问题域和业务逻辑，技术实现交给 AI

> **核心心法**：Vibe Coding 的精髓是「意图驱动开发」——你负责定义终点，AI 负责修路。你越清楚自己要什么，AI 生成的结果越精准。
