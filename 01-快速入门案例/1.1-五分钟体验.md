# 1.1 五分钟体验 Claude Code

> 本章带你快速感受 Claude Code 的威力，用一个真实案例让你立刻上手。

## 🎯 场景描述

假设你收到一个任务：**给公司内部系统写一个用户管理 API**。

传统做法：
1. 设计数据结构
2. 写 SQL 建表
3. 写 API 接口
4. 写测试用例
5. 写文档

**预计耗时：2-3 小时**

## ✨ Claude Code 做法

你只需要在项目目录打开 Claude Code，输入：

```
帮我创建一个用户管理模块：
- 用户表包含 id, name, email, created_at
- 提供 CRUD API（增删改查）
- 用 Node.js + Express
- 带基础测试用例
```

**Claude Code 会自动：**
1. 创建 `models/User.js`
2. 创建 `routes/users.js`
3. 创建 `tests/user.test.js`
4. 写好完整代码

**预计耗时：5-10 分钟**

## 💡 关键技巧

### 技巧 1：需求要具体

❌ 模糊的需求：
```
帮我写个用户管理
```

✅ 清晰的需求：
```
帮我创建一个用户管理模块：
- 用户表包含 id, name, email, created_at
- 提供 CRUD API（增删改查）
- 用 Node.js + Express
- 带基础测试用例
```

**原因**：Claude Code 需要明确的上下文才能生成你想要的代码。模糊的需求 = 模糊的结果。

### 技巧 2：一步一步来

不要一次性丢一个巨大的需求，分步推进：

```
# 第一步：搭骨架
帮我初始化 Express 项目，只要基础结构

# 第二步：加功能
现在添加用户管理 API，包含 CRUD

# 第三步：补测试
给用户 API 写测试用例

# 第四步：加验证
给 API 加参数校验，用 express-validator
```

**好处**：
- 每一步都能检查结果
- 发现问题可以及时调整
- 避免一次性生成大量错误代码

### 技巧 3：让它解释代码

```
解释一下这个 User 模型的代码逻辑
```

Claude Code 会逐段解释，帮你理解生成的代码，而不是只当一个代码搬运工。

### 技巧 4：让它改，不要自己改

❌ 自己打开文件改：
```
（你打开 models/User.js，手动加了一个字段）
```

✅ 让 Claude Code 改：
```
给 User 模型加一个 role 字段，可选值是 'admin' | 'user'，默认 'user'
```

**原因**：
- Claude Code 会同步更新所有相关文件（模型、路由、测试）
- 你手动改容易漏掉关联文件
- 让它改，它还会帮你加 role 字段的测试用例

## 🐛 常见踩坑与解决方案

### 坑 1：生成的代码跑不起来

**症状**：运行报错 `Cannot find module 'xxx'`

**原因**：Claude Code 创建了新文件但没帮你安装依赖。

**解决**：
```
帮我安装缺少的依赖并运行测试
```

Claude Code 会执行 `npm install` 并重新测试。

### 坑 2：代码风格跟项目不一致

**症状**：生成的代码用了 const，但你项目全用 let；或者缩进风格不同。

**解决**：
```
检查一下项目里其他文件的代码风格，把生成的代码调整成一致的
```

更好的做法是在项目根目录放一个 `.claude/CLAUDE.md` 文件，写上代码风格偏好：

```markdown
# 项目规范
- 使用 const，不用 var
- 缩进 2 空格
- 使用单引号
- 分号可省略
```

这样 Claude Code 每次都会自动遵守。

### 坑 3：生成了不需要的文件

**症状**：Claude Code 创建了一个你不需要的文件。

**解决**：
```
删除 middleware/auth.js，这个项目不需要鉴权中间件
```

或者更早干预——在需求里说清楚边界：
```
帮我创建用户管理模块，只需要路由和模型，不要中间件
```

### 坑 4：上下文丢失

**症状**：对话太长后，Claude Code 开始"忘记"之前的内容。

**解决**：

1. 使用 `/compact` 命令压缩上下文：
```
/compact
```

2. 或者用 `/clear` 清空重新开始，配合 `@file` 引入关键文件：
```
@models/User.js @routes/users.js 现在给用户 API 加上分页功能
```

## 🔄 遇到问题怎么办

| 问题 | 解决方法 |
|------|---------|
| 代码报错 | 直接把报错信息贴给它 |
| 风格不对 | 告诉它你要什么风格，或用 CLAUDE.md |
| 需求变了 | 直接说新需求，它会调整已有代码 |
| 生成了多余代码 | 说清楚不需要什么 |
| 上下文太长 | 用 `/compact` 或 `/clear` 重置 |
| 想撤销修改 | `git diff` 看改动，`git checkout .` 回滚 |

## ⚠️ 注意事项

### 1. 生成的代码要 review

Claude Code 生成的代码**不是完美的**，你需要检查：

- 数据库配置是否正确
- 安全验证是否完善
- 错误处理是否合理
- 边界条件是否覆盖

### 2. 安全相关要自己审计

认证、授权、加密等安全相关的代码，**务必自己审计**：

```
检查一下这个 JWT 认证实现有没有安全问题
```

Claude Code 能帮你做初步检查，但安全代码不能偷懒——它不懂你的业务安全需求。

### 3. 依赖版本要检查

Claude Code 可能会指定过旧的依赖版本：

```json
{
  "dependencies": {
    "express": "^4.17.1"  // 可能不是最新版
  }
}
```

```
帮我检查 package.json 里的依赖版本，更新到最新的稳定版
```

### 4. 项目结构可以调整

如果不喜欢 Claude Code 生成的项目结构，直接说：

```
我不喜欢这个结构，按 MVC 模式重新组织
```

Claude Code 会帮你重构文件布局，同时保证功能不变。

## 📝 小结

这就是 Claude Code 的核心价值：

> **把繁琐的重复劳动交给 AI，你专注在业务逻辑和创意设计。**

记住四个要点：
1. **需求要具体**——给它清晰的上下文
2. **分步推进**——不要一次性丢大需求
3. **代码要 review**——它生成的不是完美的
4. **遇到问题直接说**——报错贴给它，风格告诉它，不需要的删掉它
